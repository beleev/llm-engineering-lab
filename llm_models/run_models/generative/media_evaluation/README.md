# 媒体生成: 一致性、水印与来源

## 直觉

demo 生成 8 帧移动矩形: 每帧位移都是 1.0, 运动连贯, 但身份漂移片段后 4 帧的矩形强度从 0.8 换成 0.3, 最大跳变 0.5。嵌入 ±0.02 的扩频水印后相关 0.02; 把其中一帧的 16 个像素清零, 水印相关还有 0.01885, HMAC 签名却立刻失败。单帧漂亮不代表视频连贯; 检测到水印, 也不代表画面内容真实。

## 核心原理

生成任务要分开查提示遵循、局部编辑保持、身份一致、运动连续与镜头控制。demo 里每帧位移都是 1.0 而身份强度跳了 0.5, 说明运动一致和身份一致是两回事; 相机移动和物体移动会混淆, 要在固定背景/相机轨迹的对照里测运动。

demo 实际生成 8 帧移动矩形并统计外观漂移, 嵌入 ±0.02 的弱扰动水印再对照参考帧算相关 (0.02), 用 HMAC 记录内容摘要并检查篡改。简化水印依赖干净的参考帧, 不能外推成鲁棒检测, 真实盲检还要测误报和变换攻击。

图像编辑可以用掩码、条件控制或反演, 评估时看目标区域的变化和非目标区域的保持。音画同步要对齐事件时间或嘴形, 不是两条流长度相等; 音频 token → codec → 波形的路径见音频实验。

水印表示某种可检测的信号, 签名来源链证明某个身份对这条记录负责, 深伪检测是可能跨域失效的分类器。三者都不能独立证明事实为真; 来源缺失也不等于造假。

## 运行

```bash
python -m llm_models.run_models.generative.media_evaluation.demo
```

需要 Python ≥ 3.10，依赖使用仓库的 numpy / torch；不需要模型 API。网页在现有章节中提供同一实验的执行记录回放。

## 怎样验证

固定同一段 8 帧序列、同一个水印图案和同一把演示密钥, 分别改身份属性 (后 4 帧强度 0.8 → 0.3) 和字节内容 (清零一帧里的 16 个像素), 看时序指标和签名验证各自怎么反应; 公开的教学密钥保护不了真实来源, 完整的内容凭证还要身份、密钥管理和编辑链。

## 与真实系统的差距

合成短片与公开演示密钥，不是安全水印、C2PA 实现或通用深伪检测器；签名验证的是完整性与密钥持有者，不证明内容真实。

## 常见误区与自测

来源签名有效, 能推出画面描述的事件真实发生吗?

不能。签名核验的是内容摘要和签署者的关系以及完整性: demo 里一致片段和身份漂移片段的签名都通过, 只有改了字节的片段失败。画面里的事件有没有发生, 要靠现实证据核查。
