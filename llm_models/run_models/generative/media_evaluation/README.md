# 媒体生成: 一致性、水印与来源

## 直觉

这组实验生成一段 8 帧的小视频 (每帧 16×24 像素, 一个 4×4 的矩形每帧右移 1 像素), 分别检验三件事:
- 画面前后是否连贯。
- 能不能测到水印。
- 内容有没有被改过。
每帧位移都是 1.0, 运动连贯, 但身份漂移片段后 4 帧的矩形强度从 0.8 换成 0.3, 最大跳变 0.5; 强度在这里代表物体的外观, 外观突然变了, 看起来就像换了一个东西。
嵌入 ±0.02 的扩频水印 (给每个像素随机加或减 0.02 的微弱图案) 后相关 0.02; 把其中一帧的 16 个像素清零, 水印相关还有 0.01885, HMAC 签名 (用密钥对内容摘要算出的校验码) 却立刻失败。
单帧漂亮不代表视频连贯; 检测到水印, 也不代表画面内容真实。

## 核心原理

生成任务要分开查提示遵循、局部编辑保持、身份一致、运动连续与镜头控制。这五项是不同的问题:
- 提示遵循: 看画面有没有照提示词画。
- 局部编辑保持: 看只改一处时别处有没有被带着改。
- 身份一致: 看同一个人或物体在各帧里是不是同一个样子。
- 运动连续: 看位置变化是否平滑。
- 镜头控制: 看相机的运动是否符合要求。
demo 里每帧位移都是 1.0 而身份强度跳了 0.5, 说明运动一致和身份一致是两回事:
- 位移是相邻两帧矩形中心的列坐标相减, 只看位置。
- 身份强度是每帧最亮像素的值, 只看外观。
一个指标好不代表另一个也好。
相机移动和物体移动会混淆, 要在固定背景/相机轨迹的对照里测运动: 画面里物体往右挪, 可能是物体在动, 也可能是相机往左摇, 只看像素分不出来。

demo 实际生成 8 帧移动矩形并统计外观漂移, 嵌入 ±0.02 的弱扰动水印再对照参考帧算相关 (0.02), 用 HMAC 记录内容摘要并检查篡改。
水印检测的做法是:
1. 拿到带水印的视频后, 减去没加水印的原始帧 (参考帧)。
2. 剩下的差值和已知的 ±1 图案逐像素相乘再取平均。
有水印时得到 0.02, 没有水印时是 0。篡改的那一帧有 16 个像素被清零, 但相关是对全部 8×16×24 = 3072 个像素取平均, 改动只占约 0.5%; 相关从 0.02 降到 0.01885 (降多少取决于被清零的那些像素原来的值), 水印照样测得到, 却看不出内容被改过。
HMAC 这边分三步:
1. 先对全部像素字节算 sha256 摘要 (内容变一个字节, 摘要就完全不同)。
2. 再用密钥对摘要算签名。
3. 验证时重算一遍比对, 篡改后对不上, 验证失败。
简化水印依赖干净的参考帧, 不能外推成鲁棒检测, 真实盲检还要测误报和变换攻击: 盲检手里没有原始帧, 视频还可能被压缩、裁剪、调色, 这些变换都会削弱图案。

图像编辑可以用掩码、条件控制或反演, 评估时看目标区域的变化和非目标区域的保持。
三种做法:
- 掩码是标出允许改动的区域。
- 条件控制是用边缘图、姿态这类额外输入约束生成结果。
- 反演是先把原图倒推回生成模型的起点, 再从那里改。
不管用哪种, 评估都要看两边: 该改的地方改对了没有, 不该改的地方是否原样保留。
音画同步要对齐事件时间或嘴形, 不是两条流长度相等: 声音和画面都是 10 秒, 不代表拍手的声音落在拍手的那一帧上。音频 token 怎样经 codec 解码成波形, 见音频实验。本例没有实现编辑和音画同步, 这一条列的是验收时要补的检查项。

水印表示某种可检测的信号, 签名来源链证明某个身份对这条记录负责, 深伪检测是可能跨域失效的分类器。
三者回答三个不同的问题:
- 水印回答里面有没有某种预先放进去的图案。
- 签名来源链回答谁对这份内容负责、签完之后内容有没有被改过。
- 深伪检测是一个判断像不像伪造的分类器, 遇到训练时没见过的生成方式或画面类型 (跨域) 可能判错。
三者都不能独立证明事实为真; 来源缺失也不等于造假: 一段真实拍摄的视频也可能没有签名, 一段带合法签名的视频拍的也可能是摆拍。demo 里身份漂移片段的签名照样通过, 因为签名只认字节有没有变, 不管画面内容对不对。

## 怎样验证

固定同一段 8 帧序列、同一个水印图案和同一把演示密钥, 每次只改一处:
- 身份漂移是把后 4 帧的强度从 0.8 改成 0.3。
- 篡改是把一帧里的 16 个像素清零。
比较四个读数各自怎么反应:
- 最大身份强度跳变和每帧位移看时序。
- 水印相关看水印。
- 来源签名通过看完整性。
判定标准是漂移应被身份跳变抓到, 篡改应被签名抓到。公开的教学密钥保护不了真实来源, 完整的内容凭证还要身份、密钥管理和编辑链 (每次合法编辑都生成新摘要并记下上一个版本)。

## 与真实系统的差距

合成短片与公开演示密钥，不是安全水印、C2PA 实现或通用深伪检测器；签名验证的是完整性与密钥持有者，不证明内容真实。

## 常见误区与自测

来源签名有效, 能推出画面描述的事件真实发生吗?

<details><summary>展开解析</summary>

不能。签名核验的是内容摘要和签署者的关系以及完整性: demo 里一致片段和身份漂移片段的签名都通过, 只有改了字节的片段失败。
签名和验证分三步:
1. 签名时先对视频的全部字节算 sha256 摘要。
2. 再用密钥对摘要算 HMAC。
3. 验证时重算一遍, 对得上就通过。
所以签名通过只说明两件事:
- 这份内容签完以后没被改过。
- 签它的人握有这把密钥。
身份漂移片段的画面有问题, 签名照样通过, 因为签的就是这份有问题的内容。画面里的事件有没有发生, 签名不管, 要靠现实证据核查。
