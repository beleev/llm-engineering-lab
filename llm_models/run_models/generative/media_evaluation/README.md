# 媒体生成: 一致性、水印与来源

## 直觉

本组实验合成一段 8 帧微型视频 (每帧分辨率 16×24 像素, 内含一个每帧向右平移 1 像素的 4×4 矩形), 分别验证三类正交属性:
- 跨帧运动与主体外观是否一致。
- 能否从像素中检出嵌入的数字水印。
- 媒体字节在签署后是否发生局部篡改。
在时序一致性测试中, 相邻帧位移恒为 1.0, 轨迹保持匀速连贯; 但身份漂移片段将后 4 帧的矩形亮度强度从 0.8 突变为 0.3, 最大帧间强度跳变达 0.5, 模拟生成视频中主体外观的中途漂移。
在溯源与完整性测试中, 逐像素嵌入幅值 ±0.02 的扩频水印后, 对照参考帧测得相关值为 0.02; 将其中一帧的 16 个像素清零篡改后, 水印相关值仍保持 0.01885, 而基于内容摘要的 HMAC 签名校验立即宣告失败。
由此可见, 单帧画质正常不代表跨帧时序连贯, 检出水印信号也不代表媒体内容未经篡改或客观真实。

## 核心原理

可控视觉生成评测必须将提示词遵循、局部编辑保持、主体身份一致、运动连续性与镜头控制拆分为独立维度逐项核查:
- 提示词遵循: 生成内容是否忠实反映文本指令约束。
- 局部编辑保持: 修改目标区域时非目标背景是否保持不变。
- 身份一致: 同一人物或物体在跨帧序列中是否维持稳定的外观特征。
- 运动连续: 主体空间轨迹在相邻帧间是否平滑过渡。
- 镜头控制: 虚拟相机的推拉摇移是否符合指定轨迹。
本实验中相邻帧位移恒为 1.0, 而主体强度却发生 0.5 的跳变, 直接证明运动连续与身份一致彼此独立:
- 帧间位移由相邻帧前景质心的列坐标差计算, 仅度量空间位置变化。
- 身份强度取每帧像素最大亮度值, 仅度量主体外观幅值。
此外, 像素平面的表观位移同时混杂前景运动与相机运动 (例如物体右移与相机左摇在像素上表现相似), 评估物理运动准确性时必须设置固定背景或受控相机轨迹对照。

本实验合成 8 帧平移矩形序列统计外观漂移, 嵌入 ±0.02 弱扰动扩频水印并相对参考帧测得相关值 0.02, 同时使用 HMAC 绑定内容摘要以检测字节级篡改。
非盲扩频水印检测包含两步:
1. 将待检视频逐像素减去未嵌入水印的干净参考帧, 提取残差阵列。
2. 将残差与已知的 ±1 伪随机图案逐像素相乘并求全量均值。
未篡改带水印视频的相关值为 0.02, 无水印视频为 0。当单帧内 16 个像素被清零时, 由于相关性在全部 8×16×24 共 3072 个像素上取平均, 被修改像素仅占约 0.5%, 相关值仅从 0.02 微降至 0.01885 (具体降幅取决于被清零像素的原始幅值), 因此水印检测依然通过, 无法暴露局部内容篡改。
HMAC 完整性核验则分三步执行:
1. 对全部像素字节计算 sha256 哈希摘要, 任意单字节变动均会使摘要彻底改变。
2. 结合对称密钥对摘要计算 HMAC 标签。
3. 核验端重新计算并比对标签, 16 像素清零后摘要失配, 立即判定篡改。
实验边界: 本实验的简化水印依赖干净参考帧做差分, 不能外推为真实场景下的鲁棒盲水印; 实用盲检无原始参考帧可用, 还必须评估误报率以及重编码压缩、裁剪、调色等变换攻击下的存活率。

局部图像编辑需同时评估目标区域的修改准确度与非目标区域的背景保持度, 多模态视频生成则需按事件时间戳或口型帧级对齐核查音画同步。
常见的三类可控图像编辑路径如下:
- 掩码约束: 显式指定允许重绘的像素区域并冻结其余背景。
- 结构条件控制: 引入边缘图、深度图或人体姿态骨架等空间条件引导生成。
- 潜空间反演: 先将原图逆向映射回生成模型的初始隐状态, 再沿编辑方向修改后重采样。
无论采用何种路径, 验收均须双向度量编辑区的指令遵循与非编辑区的像素保持。
音画同步评估不能简化为核对音频流与视频流的总时长相等 (例如音视频同为 10 秒并不保证击掌声恰好落在手掌相碰的视频帧上), 必须测量视听事件时间戳偏差或口型对齐误差; 离散音频 token 经 codec 解码还原波形的链路参见音频模块实验。实验边界: 本实验未实现图像局部编辑与音画同步, 此处列出的是完整媒体生成系统验收需补充的检查项。

数字水印、加密签名来源链与深伪检测分类器分别服务于信号检出、责任溯源与伪造判别三类不同目标, 三者均不能单独证明画面所描述的现实事件为真:
- 数字水印: 仅验证媒体中是否含有特定生成器预先嵌入的统计信号。
- 签名来源链: 验证特定签署主体对该字节序列背书, 且签署后字节未经篡改。
- 深伪检测: 基于统计特征判别真伪的判别式分类器, 面对未见过的生成器架构或压缩域分布 (跨域样本) 时易发生漏检或误报。
工程与合规判定中需避免两类逻辑误推: 缺少来源签名不等于内容造假 (普通采集设备拍摄的真实影像未必附带签名), 签名核验通过也不等于事实为真 (摆拍影像或生成缺陷画面同样可被合法签署)。本实验中存在外观突变的身份漂移片段依然能够通过签名校验, 正是因为加密签名只核验字节完整性而不审查画面语义。

## 怎样验证

固定同一段 8 帧基础序列、同一组扩频水印图案与同一把演示密钥, 采用单变量扰动构造对照:
- 身份漂移组: 将后 4 帧的主体亮度强度从 0.8 改为 0.3。
- 局部篡改组: 将单帧内的 16 个像素置零。
联合观测四项指标对不同异常的响应分离度:
- 最大身份强度跳变与帧间位移: 度量跨帧外观与运动一致性。
- 水印相关值: 度量预设扩频信号的留存程度。
- 来源签名核验结果: 度量全量字节完整性。
验收标准要求外观漂移被最大身份强度跳变准确捕获, 字节修改被 HMAC 签名准确拦截。实验边界: 仓库内硬编码的公开演示密钥不具备真实防伪效力, 生产级内容凭证体系还需配套证书身份认证、硬件密钥管理及可追溯编辑链 (每次合规编辑生成新摘要并链接前序版本记录)。

## 与真实系统的差距

合成短片与公开演示密钥，不是安全水印、C2PA 实现或通用深伪检测器；签名验证的是完整性与密钥持有者，不证明内容真实。

## 常见误区与自测

媒体的加密来源签名核验有效, 能否据此推出画面描述的事件在现实中真实发生?

<details><summary>展开解析</summary>

不能。加密签名核验的只是字节摘要完整性与签署密钥归属关系: 本实验中时序一致片段与存在生成缺陷的身份漂移片段均能通过验签, 唯有签署后修改像素字节的篡改片段验签失败。
签名生成与核验由三步构成:
1. 签署端对视频全量像素字节计算 sha256 摘要。
2. 使用私钥或对称密钥对摘要生成 HMAC 签名标签。
3. 核验端重新计算字节摘要并比对标签是否一致。
因此验签通过仅能证明两项事实:
- 媒体文件自签署时刻起未发生任何字节变动。
- 签署操作由持有对应密钥的主体完成。
若待签署画面本身即含生成伪影 (如本例的身份漂移片段) 或人为摆拍, 签名同样会原样背书该字节序列; 画面所涉现实事件是否真实发生, 仍需依赖外部独立证据交叉核查。

</details>
