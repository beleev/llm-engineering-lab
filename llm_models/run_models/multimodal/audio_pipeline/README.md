# 语音信号：波形、Mel 与 codec

## 直觉

语音系统要处理连续的声音和时间，而不仅是转写后的文字。压缩、延迟和噪声会改变可用信息。

## 核心原理

从合成波形做分帧、窗函数、STFT、Mel 滤波与 log 压缩，实际计算帧时间戳。采样率约束可表达频率，重采样需防混叠；帧中心时间与可用输出时间不能混淆。

本例 PCM 量化再解码回波形，报告重建 SNR。神经 codec 则用编码器、量化器和解码器学习表示，离散音频 token 可由模型生成后解码；PCM 示例不是神经 codec 复现。

ASR 评估 WER/CER；说话人识别问“是谁”，diarization 问“谁在何时说话”，还要考虑重叠语音。按口音、语言、噪声和录音设备切片，不能只测干净单人语音。

TTS/音频生成要检查可懂度、韵律、说话人相似与人工自然度；流式系统分别计首包、实时率、端点检测与打断延迟。文本 token 生成不等于波形已经可播放。

## 运行

```bash
python -m llm_models.run_models.multimodal.audio_pipeline.demo
```

需要 Python ≥ 3.10，依赖使用仓库的 numpy / torch；不需要模型 API。网页在现有章节中提供同一实验的执行记录回放。

## 怎样验证

比较相同信号的噪声和量化失真。此例不训练 ASR/TTS；已有语音交互状态机用于打断与快慢响应，两者共同覆盖信号链和交互链。

## 与真实系统的差距

真实数值信号处理，但输入是合成音调，不是语音。没有声纹识别、ASR/TTS 或神经 codec 能力；音频输出必须和说话人授权一起管理。

## 常见误区与自测

生成了音频 token，就能认为用户已经听到声音吗？
