# 语音信号: 波形、Mel 与 codec

## 直觉

同一段 0.5 秒、4000 个采样点的合成音, 分成 47 帧 × 24 个 Mel 通道, 帧步长 10 ms, 末帧起点 460 ms。量化到 ±127 级再解码, 还原 SNR 45.853 dB; 只剩 7 级掉到 19.875 dB; 加 σ=0.15 的噪声掉到 9.213 dB。语音系统处理的是连续的声音和时间, 压缩、噪声和延迟各自改变可用信息。

## 核心原理

demo 从合成波形做分帧、Hann 窗、STFT、24 个三角 Mel 滤波和 log 压缩, 并实际算出每帧的起点时间戳 (hop 80 点 = 10 ms, 末帧 460 ms)。采样率限制能表达的频率, 重采样要防混叠; 帧的时间戳和可用输出的时间不能混为一谈。

demo 把样本量化到 ±127 级再解码回波形, 报告重建 SNR 45.853 dB; 量化到 7 级只剩 19.875 dB。神经 codec 用编码器、量化器和解码器学表示, 离散音频 token 可以由模型生成后再解码; 这里的 PCM 不是神经 codec 复现。

ASR 评 WER/CER; 说话人识别问 "是谁", diarization 问 "谁在何时说话", 还要处理重叠语音。按口音、语言、噪声和录音设备切片, 不能只测干净的单人语音。

TTS/音频生成要查可懂度、韵律、说话人相似度与人工自然度; 流式系统分别计首包、实时率、端点检测与打断延迟。生成了文本 token 不等于波形已经能播放。

## 运行

```bash
python -m llm_models.run_models.multimodal.audio_pipeline.demo
```

需要 Python ≥ 3.10，依赖使用仓库的 numpy / torch；不需要模型 API。网页在现有章节中提供同一实验的执行记录回放。

## 怎样验证

固定同一段合成信号和同一条分帧 → Mel 链路, 只换噪声 (σ=0.15) 或量化级数 (127 → 7), 比较还原 SNR, 帧数、通道数和时间戳应保持不变; 此例不训练 ASR/TTS, 已有的语音交互状态机负责打断与快慢响应, 两者合起来才覆盖信号链和交互链。

## 与真实系统的差距

真实数值信号处理，但输入是合成音调，不是语音。没有声纹识别、ASR/TTS 或神经 codec 能力；音频输出必须和说话人授权一起管理。

## 常见误区与自测

生成了音频 token, 就能认为用户已经听到声音吗?

<details><summary>展开解析</summary>

不能。音频 token 还要经过 codec 解码和缓冲播放才变成声音, demo 里 7 级量化的 token 解码后 SNR 只有 19.875 dB。模型出 token 的时间、首包时间和用户可听见的时间要分别记录。
