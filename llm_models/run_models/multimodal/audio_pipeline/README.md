# 语音信号: 波形、Mel 与 codec

## 直觉

这组实验用一段合成音 (440 Hz 和 880 Hz 两个正弦音叠加, 不是人声) 真实地走一遍语音前端的信号处理, 看压缩和噪声各自让声音损失多少。同一段 0.5 秒、4000 个采样点的合成音 (采样率 8000 Hz, 每秒取 8000 个点), 分成 47 帧 × 24 个 Mel 通道, 帧步长 10 ms, 末帧起点 460 ms; 帧是一小段连续的采样点, Mel 通道是按人耳对音高的感知划分的频段。量化到 ±127 级再解码, 还原 SNR 45.853 dB; 只剩 7 级掉到 19.875 dB; 加 σ=0.15 的噪声掉到 9.213 dB。SNR (信噪比) 是原信号能量和误差能量之比, 用分贝表示, 越高越接近原声, 每低 10 dB 误差能量相对多 10 倍。语音系统处理的是连续的声音和时间, 压缩、噪声和延迟各自改变可用信息。

## 核心原理

demo 从合成波形做分帧、Hann 窗、STFT、24 个三角 Mel 滤波和 log 压缩, 并实际算出每帧的起点时间戳 (hop 80 点 = 10 ms, 末帧 460 ms)。一步步看: 分帧是每隔 80 个采样点 (hop, 帧步长, 8000 Hz 下是 10 ms) 取一段 256 个点; Hann 窗把每段两头压低, 减少切断处的突变; STFT (short-time Fourier transform, 短时傅里叶变换) 算出每段里各个频率有多少能量; 24 个三角 Mel 滤波器把这些频率按人耳感知的刻度合并成 24 个通道; 最后取 log 压缩数值范围。4000 个点按 256 点一段、每次挪 80 点, 能切出 47 段, 最后一段从第 3680 个点开始, 对应 460 ms。采样率限制能表达的频率, 重采样要防混叠: 8000 Hz 采样最多表示 4000 Hz 的声音, demo 的 Mel 滤波器也只铺到 4000 Hz; 降低采样率前不先滤掉高频, 高频会冒充成低频, 这叫混叠。帧的时间戳和可用输出的时间不能混为一谈: 460 ms 是这一帧声音在录音里的位置, 不是系统处理完它、用户能拿到结果的时刻。

demo 把样本量化到 ±127 级再解码回波形, 报告重建 SNR 45.853 dB; 量化到 7 级只剩 19.875 dB。量化是把每个采样点 (原本在 -1 到 1 之间的小数) 乘 127 后四舍五入成整数, 这些整数就可以当作离散的 token; 解码是再除以 127 变回小数。取整会带来最多半格的误差, 级数越少, 一格越粗, 误差越大: 7 级时一格是 1/7, 比 127 级粗 18 倍多, SNR 也就低了约 26 dB。神经 codec 用编码器、量化器和解码器学表示, 离散音频 token 可以由模型生成后再解码: 它不是直接对每个采样点取整, 而是先用编码器把一小段声音压成向量, 再由量化器变成离散编号, 最后由解码器还原成波形, 这三部分都是训练出来的。这里的 PCM (直接存采样点数值的编码) 不是神经 codec 复现, 只是能解码的最小基线。

ASR 评 WER/CER; 说话人识别问 "是谁", diarization 问 "谁在何时说话", 还要处理重叠语音。ASR (automatic speech recognition) 是语音转文字, 用 WER (词错误率) 或 CER (字错误率) 评: 把识别结果和标准文本对齐, 数替换、漏掉、多出来的词或字占多少。说话人识别只判断一段声音是谁的; diarization (说话人分离) 要把一段多人录音切开, 标出每段是谁说的, 两个人同时说话 (重叠语音) 时最难。按口音、语言、噪声和录音设备切片, 不能只测干净的单人语音: 平均分数好看, 可能只是因为测试集大多是干净录音, 换成带口音、嘈杂或廉价麦克风的录音才会暴露问题。本例的输入是合成音调, 不涉及这些任务。

TTS/音频生成要查可懂度、韵律、说话人相似度与人工自然度; 流式系统分别计首包、实时率、端点检测与打断延迟。TTS (text to speech) 是文字转语音, 它的输出要看几件不同的事: 听不听得清 (可懂度), 停顿和语调对不对 (韵律), 像不像目标说话人 (说话人相似度), 人听起来自不自然 (人工自然度)。流式系统是边生成边播放的系统, 时间要拆开记: 首包是第一段声音送到用户的时间, 实时率是生成一秒声音要花几秒, 端点检测是判断用户说完了没有, 打断延迟是用户插话后系统多久停下。生成了文本 token 不等于波形已经能播放: 文本还要变成音频 token 或波形, 再解码、缓冲, 才能从扬声器出来。

## 怎样验证

固定同一段合成信号和同一条分帧加 Mel 的处理链路, 每次只换一个条件: 加 σ=0.15 的高斯噪声 (这一组仍按 127 级量化), 或把量化级数从 127 降到 7, 比较还原 SNR。判定标准是: SNR 只应随噪声和量化变化, 帧数、通道数和时间戳应保持不变, 因为它们只取决于信号长度和分帧参数。此例不训练 ASR/TTS, 已有的语音交互状态机负责打断与快慢响应, 两者合起来才覆盖信号链和交互链。

## 与真实系统的差距

真实数值信号处理，但输入是合成音调，不是语音。没有声纹识别、ASR/TTS 或神经 codec 能力；音频输出必须和说话人授权一起管理。

## 常见误区与自测

生成了音频 token, 就能认为用户已经听到声音吗?

<details><summary>展开解析</summary>

不能。音频 token 还要经过 codec 解码和缓冲播放才变成声音, demo 里 7 级量化的 token 解码后 SNR 只有 19.875 dB。一步步看: 模型生成的是一串离散编号, 扬声器要的是连续波形; 编号先要由 codec 的解码器还原成波形, demo 里这一步就是除以量化级数, 解码出来的声音和原声差多少取决于量化有多粗; 波形再进播放缓冲, 攒够一段才开始播。所以从模型吐出第一个 token, 到第一段声音送出 (首包), 再到用户真正听见, 中间隔着好几段时间。模型出 token 的时间、首包时间和用户可听见的时间要分别记录。
