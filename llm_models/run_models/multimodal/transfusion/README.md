# Transfusion — 统一多模态: 一个 transformer 既看图说话, 也按文本画图

[llm_models 目录](../../../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/models/unified-multimodal)

## 直觉

- Qwen2-VL 这类前缀路线只解决 "看": 图像变成一串连续向量拼在文本前面, 模型只输出文本。要生成图像, 还得另接一个扩散模型。
- Transfusion (Zhou et al., Meta, 2024) 让同一个 transformer 两件事都做: 文本位置照常做 next-token 预测, 图像位置做扩散去噪。两种位置排在同一条序列里, 共用同一套层, 只有输入层和输出头按位置类型分开。
- 两种目标对 "能看见谁" 的要求不同: 文本要因果, 只能看前面; 一张图的所有 patch 在同一个噪声水平上一起去噪, 需要互相看见。Transfusion 的掩码把两者合在一起: 整条序列因果, 同一张图内部双向。
- 对比 Chameleon: Chameleon 把图像量化成离散 token, 图像和文本都做 next-token 预测, 结构最统一, 但量化有损, 一张 512×512 的图要逐个生成 1024 个 token。Transfusion 让图像保持连续向量, 不经过量化。

## 核心原理

### 核心公式

```
序列:   [BOS, 文本..., BOI, p_1 .. p_N, EOI, 文本...]          p_i 是加噪后的图像 patch
掩码:   M[i, j] = (j ≤ i)  OR  (i 和 j 属于同一张图)
加噪:   x_t = (1 − t)·x_0 + t·ε                               本库用 flow matching
目标:   L = L_LM + λ·L_img
        L_LM  = 文本位置的 next-token CE
        L_img = 图像位置的 MSE(v_θ(x_t, t), ε − x_0)            论文是 MSE(ε_θ, ε), λ = 5
```

L_img 里的 v = ε − x_0 是从数据指向噪声的速度。模型在图像位置预测它, 生成时从纯噪声出发沿 −v 方向积分回 t = 0。

### 掩码: 三条性质

- **图像段内互相可见**: 去噪时每个 patch 都要参考整张图, 否则左上角的 patch 只能凭自己的噪声猜, 生成退化成逐 patch 的光栅顺序。
- **图像后的文本看得到整张图**: 这就是看图说话。
- **图像前的文本看不到图**: 按文本画图时, 提示词的表示不随图像变化, 生成可以先写字、遇到 BOI 再去噪。图像去噪完成后它的 K/V 不再变化, 后面的文本可以像普通自回归一样复用缓存。

### 论文的训练与推理设置

- 图像先过一个 86M 参数的 VAE, 256×256 的图压成 32×32×8 的 latent, 按 2×2 latent patch 经线性层或 U-Net 下/上采样块进出 transformer, U-Net 块效果更好, 7B 模型用它。
- 扩散目标是 DDPM 的噪声预测, cosine 噪声日程, 训练用 1000 个时间步, 推理默认 250 步。t 的嵌入加到每个 patch 上。
- 图文对 80% 文本在前、20% 图像在前; 图像在前的样本把噪声限制在 t ≤ 500, 论文报告这一项明显提高了看图说话 (CIDEr) 的分数。
- 推理时模型照常采样文本, 采到 BOI 就切到扩散模式, 接一段纯噪声 patch 去噪, 完成后接 EOI 回到文本模式。
- 7B 模型在约 2T token 上训练 (1T 文本 token、约 1T 图像 patch)。在 7B 的对照实验里, 达到与 Chameleon 相同 FID 所需的 FLOPs 约为后者的 0.029。

### 统一路线的几种做法

| 路线 | 图像怎样表示 | 图像怎样生成 | 理解与生成是否共用视觉表示 |
|---|---|---|---|
| Chameleon (Meta, 2024) | VQ 离散 token, 8192 码本并进词表 | 和文本一样 next-token | 共用 |
| Transfusion (Meta, 2024) | 连续 patch (VAE latent) | 同一模型里扩散去噪 | 共用 |
| Show-o (2024) | MAGVIT-v2 离散 token | MaskGIT 式掩码预测, 文本因果、图像全注意力 | 共用 |
| Janus (DeepSeek, 2024) | 理解用 SigLIP 特征, 生成用 VQ token | 自回归预测 VQ id | 分开: 两个视觉编码器, 一个 transformer |
| Show-o2 (2025) | 3D 因果 VAE latent | flow head 做 flow matching, language head 出文本 | 共用 latent, 空间与时空两路融合 |
| BAGEL (ByteDance Seed, 2025) | 理解用 SigLIP2 ViT, 生成用冻结的 FLUX VAE | rectified flow | 分开: 理解专家和生成专家每层共享自注意力 (7B 激活 / 14B 总参) |

Qwen3.5 (阿里, 2026-02) 的 "原生多模态" 指另一件事: 视觉从预训练一开始就进入主干, 而不是先训好语言模型再接视觉。它输入文本、图像和视频, 只输出文本, 属于理解侧的早融合, 不在同一个模型里生成图像。

## 运行

论文: Zhou et al. 2024, "Transfusion: Predict the Next Token and Diffuse Images with One Multi-Modal Model" (arXiv 2408.11039)。模型代码: `llm_models/models/multimodal/transfusion.py`。

```bash
python -m llm_models.run_models.multimodal.transfusion.infer_transfusion   # ~2s CPU, 不训练, 只验证掩码与数据流
python -m llm_models.run_models.multimodal.transfusion.train_transfusion   # ~70s CPU, 训练 3000 步后评估
```

## 运行后应该看到什么

玩具数据: 8×8 的 RGB 小图, 3 种颜色 (red / green / blue) × 3 种形状 (circle 圆环 / square 实心方块 / cross 十字), 位置抖动 ±1 像素, 亮度在 [0.6, 1] 之间随机, 再加 N(0, 0.05²) 像素噪声。2×2 切 patch 得到 16 个图像位置, 每个 patch 12 维。文本是 "颜色 形状" 两个词, 词表 9 个 (含 BOS / BOI / EOI)。两种样本各占一半:

- 文本在前: `[BOS, 颜色, 形状, BOI, 16 个 patch, EOI]`, t ~ U(0, 1)。
- 图像在前: `[BOS, BOI, 16 个 patch, EOI, 颜色, 形状]`, t ~ U(0, 0.5), 对应论文的噪声上限。

- 可见对多出的 120 = 16·15/2, 正好是一张图内部 "看后面 patch" 的格子数。
- 初始文本 CE 比 ln V 高约 0.25: weight tying 让预测位置的隐状态接近它自己的 embedding, 初始最偏爱输出 "自己" (logit ≈ 1.3, CE ≈ ln(V − 1 + e^1.3) ≈ 2.46), 与 llada 的 train 脚本同一原因。
- 初始图像 MSE ≈ 2: 速度头输出 ≈ 0, MSE ≈ E[(ε − x_0)²] = Var(ε) + E[x_0²], 背景像素 x_0 ≈ −1。

断言: 三条掩码性质; 涉及文本的位置与普通因果掩码逐格相同; 换整张图时图像前文本的 logits 一位不变、图像后文本会变; 改最后一个 patch 时第一个 patch 的输出会变, 换成纯因果掩码后不变; 图像在前时换标题不影响图像位置; 初始文本 CE ≈ ln V, 初始图像 MSE ≈ 2; 生成接口输出 [B, 3, 8, 8]。

- **图前文本 CE 停在 ln 3**: 文本在前的样本里, 颜色词和形状词各有 3 种等概率取值, 图又在它们后面看不到, 所以这部分 CE 降不到 ln 3 以下。实测 1.100, 这是掩码在训练里真正起作用的旁证。日志里的 "文本 CE" 是两类样本的平均, 所以停在约 0.55 (ln 3 的一半)。
- **看图说话全对, 按文本画图颜色全对、形状只对六成**: 颜色由一个通道的整体亮度决定, 很容易; 形状要求 16 个 patch 协调出同一个位置和轮廓。按要求的形状拆开, 方块 0.933, 圆环 0.433, 十字 0.500: 圆环和十字常被画成一团, 判定器把这种团块判成方块。上面的样例里 red circle 是散开的点, blue cross 也不完整。
- **判定器先在真图上验收**: 颜色和形状都是 1.000, 所以命中率反映的是生成质量, 不是判定器的误差。
- 换更大的模型 (d_model 96、4 层、2000 步) 时形状命中率实测 0.678, 增益有限; 欧拉步数从 20 加到 50 不改变结果。生成质量的瓶颈在模型和训练量, 不在采样步数。

断言: 判定器在真图上 > 0.98; 初始文本 CE ≈ ln V; 看图说话 CE 降到初始的一半以下, 图像 MSE 降到初始的 0.7 以下; 图前文本 CE 不低于 ln 3 − 0.05; 看图说话和按文本画图的颜色、形状、两个都对三项都比随机高 0.2 以上。

## 与真实系统的差距

- **规模**: 3 层、d_model=64、4 头, 词表 9 个, 序列长 21。图像是 8×8 像素, 没有 VAE, 直接对像素切 2×2 patch 并用线性层进出。
- **扩散目标**: 这里用 flow matching 回归速度 v = ε − x_0, t ~ U(0, 1); 论文用 DDPM 的 ε 预测和 cosine 日程。两者都是 "图像位置回归一个 MSE 目标", 掩码和损失的组合方式不变。
- **数据**: 9 种 (颜色, 形状) 组合, 每种 9 个位置, 留出集与训练集来自同一分布 (新抽的亮度、位置和噪声), 测的是通路能学会, 不是组合泛化。
- **比例**: 两种布局各占一半; 论文是文本在前 80%、图像在前 20%。图像在前的噪声上限 t ≤ 0.5 照论文设置。
- **生成**: 由调用方放好 BOI, 不用 CFG, 每一步去噪都对整段序列做前向, 没有 KV cache。论文推理时用 CFG, 由模型自己采到 BOI 再切换模式。
- **位置编码**: 整条序列的 1D RoPE, 一条序列里的图共用一个 t。论文的块结构与 Llama 相同 (含 RoPE), 图像 patch 位置的具体编码这里没有核实。
- **本库约定**: 文本 embedding 乘 √D、lm_head 与 embedding 共享权重、N(0, 0.02²) 初始化, 见 `llm_models/models/__init__.py`。

## 常见误区

1. **"统一模型 = 把图像量化成 token 再做 next-token"**: 这是 Chameleon 的做法。Transfusion 的图像保持连续向量, 用扩散损失训练, 序列里同时存在两种目标。
2. **"图像段内双向会让文本偷看未来"**: 双向只发生在同一张图的 patch 之间。infer 脚本里换整张图, 图像前文本的 logits 变化恰好是 0; 训练后图前文本的 CE 停在 ln 3。
3. **"图像生成可以一步出来"**: 生成时每个去噪步都要整段前向, 这里 20 步。理解只要一次前向, 生成的代价比理解高一个数量级。
4. **"看图说话准就说明会画"**: 实测看图说话 1.000, 按文本画图的形状只有 0.622。理解只要把图压成两个词, 生成要协调 16 个 patch 的位置和轮廓, 两者难度不对称。
5. **"Qwen3.5 的原生多模态就是 Transfusion 这种统一"**: Qwen3.5 是理解侧的早融合, 只输出文本; Transfusion 在同一模型里生成图像。

## 自测题

1. 文本在前的样本里, 颜色词位置的 CE 为什么训练后停在 ln 3 附近?
   **答**: 颜色在 3 种里均匀随机, 而图排在文本后面, 因果掩码让文本看不到它, 所以最好的预测就是均匀分布, CE = ln 3。实测 1.100。
2. 一张图有 N 个 patch, 段内双向比纯因果多出多少个可见格子?
   **答**: N(N−1)/2。N = 16 时多出 120, 可见对从 231 变成 351, infer 脚本里有打印。
3. 为什么图像在前的样本要限制噪声上限?
   **答**: 这类样本的作用是让后面的标题读图。噪声太大时图里几乎没有信息, 标题只能瞎猜, 这部分训练信号就浪费了。论文把它限制在 t ≤ 500 (共 1000 步), 报告看图说话的分数明显提高。
