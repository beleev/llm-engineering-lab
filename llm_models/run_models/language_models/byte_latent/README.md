# Byte Latent Transformer — 不用 tokenizer, 按下一字节熵切 patch

[llm_models 目录](../../../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/models/byte-latent)

## 直觉

- BPE 词表在训练前就定死了。词表没照顾到的语言, 同一句话要多花几倍 token (见 llm_train m26); 每个 token 不论难易, 都要过一遍整个大模型。
- 直接读 UTF-8 字节就没有词表偏差, 但序列比 BPE 长约 4 倍, 每个字节都过一遍大模型太贵。
- BLT 的办法是把字节切成长短不一的 patch, 大模型 (全局 latent transformer) 每个 patch 只走一步。切在哪里由一个小字节模型决定: 它算出下一个字节的熵, 熵高 (难猜) 的位置开新 patch, 熵低 (好猜) 的字节并进前一个 patch。
- 结果是全局模型的步数按信息量分配: 词的后半截、多字节汉字的续字节几乎不占全局计算。demo 里英文词 8 字节、中文词 10 字节 (都含空格), 平均都正好一个 patch。
- 两头各有一个小模型: 局部编码器把一个 patch 的字节汇成一个向量, 局部解码器把全局模型的输出还原成逐字节的预测。

## 核心原理

### 数据流

1. 熵模型 (小的字节级 LM) 算每个位置的下一字节熵 $H(x_t) = H(p(x_t \mid x_{<t}))$, $H(x_t) > \theta$ 处开新 patch, 位置 0 恒为边界。
2. 局部编码器: byte embedding 加 hash n-gram embedding, 过一个滑窗因果块, 再做交叉注意力池化。每个 patch 的 query 用本 patch 字节的 max-pool 初始化, 只对本 patch 的字节做注意力, 得到 patch 向量。
3. 全局 latent transformer 在 patch 序列上跑因果块。输入右移一个 patch, 开头补一个可学的 BOS patch, 所以第 $j$ 个输出 $g_j$ 只汇总 patch $0..j-1$。
4. 局部解码器: 位置 $t$ 预测 $x_{t+1}$ 时, 读 $x_{t+1}$ 所在 patch 的 $g$, 加到字节隐状态上, 再过一个滑窗因果块, 输出 256 个字节的 logits。

### 核心公式

```
边界:          b_t = 1[H(x_t) > θ],  b_0 = 1;    patch_id_t = Σ_{s ≤ t} b_s − 1
hash n-gram:   e_t = E_byte[x_t] + Σ_n E_n[hash(x_{t-n+1..t}) mod 桶数]
全局步数:      patch 数 / 字节数 = 1 / 平均 patch 长度
bits-per-byte: BPB = Σ_t CE_t / (ln 2 · 字节数)
```

- 切分是因果的: $b_t$ 只看 $H(x_t)$, 而 $H(x_t)$ 只由 $x_{<t}$ 算出, 生成时边走边切, 不需要先看到整段文本。
- 输出也是因果的: 位置 $t$ 读的 $g$ 只汇总 $x_{t+1}$ 所在 patch 之前的 patch, 这些 patch 的字节都在 $t$ 及以前; 如果读的是 $x_t$ 自己所在 patch 的表示, 同一 patch 里还没出现的字节就会泄露进来。
- BPB 按字节数归一化。BPE 的一个 token 覆盖好几个字节, 每 token 的 loss 和每字节的 loss 不能直接比; 换成整段文本要多少比特, 就和分词方式无关了。

### 相关路线

- MegaByte (固定长度 patch): 每 $K$ 个字节一刀, 和内容无关。本库用 `fixed_patch_ids` 做对照。
- H-Net (Hwang, Wang, Gu 2025, arXiv 2507.07955): 切分也让模型自己学。路由模块对相邻位置的表示算 $p_t = \tfrac{1}{2}(1 - \cos(q_t, k_{t-1}))$, $p_t \ge 0.5$ 处切; 配一个 ratio loss 把平均压缩比推向目标值 (1 阶段取 6, 实际约 4.8 字节一个 chunk)。论文报告在计算和数据对齐时, 1 阶段字节级 H-Net 胜过 BPE Transformer, 在中文、代码、DNA 上优势更大。本库没有实现 H-Net。

## 运行

论文: Pagnoni et al. 2024, "Byte Latent Transformer: Patches Scale Better Than Tokens" (arXiv 2412.09871)。模型代码: `llm_models/models/language_models/byte_latent.py`。

```bash
python -m llm_models.run_models.language_models.byte_latent.infer_byte_latent   # 约 7 s CPU, 内部先训 400 步熵模型
python -m llm_models.run_models.language_models.byte_latent.train_byte_latent   # 约 85 s CPU (单线程)
```

## 运行后应该看到什么

数据是合成的字节文本。18 个词用空格连接: 12 个英文词各 7 字节, 6 个中文词各 3 个汉字 (9 个 UTF-8 字节)。下一个词从当前词固定的 3 个后继里均匀抽。

这里刻意植入了一个结构: 每个词的 3 个后继共用同一个词尾, 只在词首上不同, 所以 "上一个词是谁" 只写在它的词首里。局部模型的滑窗是 2 个字节, 加上 3-gram, 视野约 5 个字节, 只够看到上一个词的词尾和空格, 这条信息必须经全局模型传过来。这个结构是为了在玩具规模下看出 "边界放在哪里" 的影响, 真实文本没有这么干净。

`infer_byte_latent` (seed 0 实测):

```
样本: 'redwolf redbear oldbear 大模型 redlynx 老模型 大模型 biglynx'
阈值 θ = 1.2: H > θ 处开新 patch, | 是边界
|redwolf |redbear |oldbear |E5A4A7E6A8A1E59E8B |redlynx |E88081E6A8A1E59E8B |E5A4A7E6A8A1E59E8B |bi

阈值 → 平均字节/patch:
  θ=0.0: 1.00 | θ=0.5: 6.78 | θ=1.0: 7.61 | θ=1.5: 10.79 | θ=2.0: 64.00 | θ=2.5: 64.00 | θ=3.0: 64.00

全局步数 2121 / 字节数 16384 = 0.129  (平均 7.72 字节/patch)
  英文词: 每词 7 字节, 加空格 8 字节 | 平均每词 1.00 个 patch (991 个词)
  中文词: 每词 9 字节, 加空格 10 字节 | 平均每词 1.00 个 patch (553 个词)

改动位置 31 之后的字节: 位置 ≤ 31 的切分不变 True | 之后切分变了的样本比例 1.00 | 位置 ≤ 30 的 logits 最大差 3.6e-07

初始 CE 5.554  vs  ln 256 = 5.545
```

- 词首字节的熵在 1.3 到 2.0 nats 之间, 词内字节不超过 0.25 (样本开头几个字节没有前文, 不算)。熵模型只有 1 层、32 维, 没完全学会用上一个词的词首, 所以词首熵高于理论值 $\ln 3 = 1.10$。
- 汉字的 3 个 UTF-8 字节里, 只有第一个字节熵高; 后两个字节由第一个字节和上下文决定, 熵接近 0, 所以一个中文词也只占一个 patch。
- $\theta = 2.0$ 以上时所有词首的熵都不够高, 只剩位置 0 一个边界, 整段只有 1 个 patch。

断言: patch 数随阈值单调不增; 全局步数 / 字节数等于 1 / 平均 patch 长度且小于 0.2; 英文词和中文词平均每词 0.8 到 1.5 个 patch; 改动位置 31 之后的字节不改变位置 31 及以前的切分, 也不改变位置 30 及以前的 logits; 初始 CE 与 $\ln 256$ 相差小于 0.3。

`train_byte_latent` (seed 0 实测, 600 步, 每步 32 条新数据, 留出集 256 条):

```
阈值 θ = 1.30: 熵切分平均 8.03 字节/patch | 固定切分 8.00 字节/patch
初始 5.552 nats/字节  vs  ln 256 = 5.545

留出集 bits-per-byte (256 条 × 64 字节):
  熵切分          | 8.03 字节/patch | 全局步数/字节 0.125 | BPB 0.220
  固定 8 字节切分 | 8.00 字节/patch | 全局步数/字节 0.125 | BPB 0.229
  每字节一个 patch | 1.00 字节/patch | 全局步数/字节 1.000 | BPB 0.219
```

- 阈值是在 0.05 的网格上选的, 让熵切分的平均 patch 长度对齐固定 8 字节切分, 两边全局模型的步数相同。模型、数据、步数、种子都相同, 只换切分。
- 熵切分比固定切分低 0.009 BPB, 和全局步数多 8 倍的 "每字节一个 patch" 只差 0.001。固定切分常常从上一个词中间下刀, 预测新词时上一个词的词首可能还没进入全局模型。
- 换训练种子 (1, 2) 时: 熵切分 0.221 / 0.221, 固定切分 0.228 / 0.230, 方向相同。差距只有 0.01 BPB 量级, 是 3 个种子上的方向, 不是统计检验。
- 这个差距来自上面植入的结构。在词尾不共用的数据上, 局部模型可以靠词尾和更早的全局信息推断出上一个词, 两种切分几乎没有差别。

断言: 两种切分的平均 patch 长度相差小于 0.3 字节; 初始 CE 与 $\ln 256$ 相差小于 0.3; 三种切分训练后的 BPB 都低于初始值的一半。脚本不断言熵切分一定更好。

## 与真实系统的差距

- **规模**: d_model=64、4 头, 全局 2 层, 局部编码器和解码器各 1 层; 序列 64 字节。论文做到 8B 参数, 训练 FLOPs 对齐时与 Llama 3 持平 (7 项任务平均 61.1 对 60.0, 约 4.5 字节一个 patch), patch 取 8 字节时推理 FLOPs 省近一半。这些数字本库没有复现。
- **熵模型**: 这里是 1 层、32 维的小 LLaMA, 和主模型分开训练。论文的熵模型约 100M 参数、14 层, 用 512 字节的滑窗。
- **切分规则**: 只实现了全局阈值 $H(x_t) > \theta$。论文另有近似单调约束 $H(x_t) - H(x_{t-1}) > \theta_r$, 也对比过空格切分和 BPE。
- **hash n-gram**: 只取 n = 3, 一张 512 行的表。论文取 n = 3..8, 用 50 万个 hash。
- **编码器和解码器**: 编码器只在最后做一次交叉注意力池化, 论文每层后都接一次。解码器里每个字节只读一个 patch 向量, 单 key 的交叉注意力退化成线性投影, 这里直接写成投影后相加。全局和局部同宽, 论文的全局模型更宽。
- **局部视野很窄**: 滑窗只有 2 个字节, 这是为了让远处的信息必须经全局模型传递, 玩具规模下才看得出切分的影响。
- **没有生成**: 只有 teacher forcing 下的 BPB。生成时需要边生成字节边算熵、到边界时让全局模型走一步, 本库没有写这段循环。
- **本库约定**: lm_head 与 byte embedding 共享权重, embedding 乘 √D, N(0, 0.02²) 初始化。

## 常见误区

1. **"BLT 就是按空格切词"** —— 边界由下一字节熵决定, 不看字节本身是不是空格。demo 的数据里词首正好熵高, 所以切出来像按词切; 遇到词内有歧义的位置 (比如两个后继共享开头几个字母), 熵切分也会在词中间下刀。
2. **"熵切分要先看完整段文本"** —— 熵只由前文算出, 切分是因果的。demo 把位置 31 之后的字节全部换掉, 位置 31 及以前的切分一个都没变。
3. **"patch 越长越省, 效果不受影响"** —— patch 长了全局步数少了, 但每个 patch 要装下更多信息; $\theta = 2.0$ 时整段只剩 1 个 patch, 全局模型就没用了。论文的结论是固定推理开销下可以同时放大 patch 和模型, 不是 patch 越长越好。
4. **"解码 patch $j$ 的字节时读 patch $j$ 的全局输出"** —— 那样 patch 里还没出现的字节会泄露进来。要读只汇总更早 patch 的那个输出 (本实现把全局输入右移一个 patch)。
5. **"每 token loss 低就是模型更好"** —— 字节模型和 BPE 模型的 token 长度不同, 要比 bits-per-byte。

## 自测题

1. 为什么 BLT 的熵切分在生成时可以边走边切?
   **答**: 边界 $b_t = 1[H(x_t) > \theta]$ 只看 $H(x_t)$, 而 $H(x_t)$ 是熵模型只看 $x_{<t}$ 时对下一个字节的不确定程度。生成到位置 $t$ 时前文已经齐了, 当场就能决定要不要开新 patch。demo 里改动位置 31 之后的字节, 位置 31 及以前的切分不变, 位置 30 及以前的 logits 最大差 3.6e-07。
2. 平均 patch 长度 8 字节时, 全局模型的步数是字节数的几分之几? 熵切分和固定 8 字节切分全局步数相同, 为什么 demo 里熵切分的 BPB 更低?
   **答**: 1/8 (实测 0.125)。数据里 "上一个词是谁" 只写在词首, 局部模型看不到, 只能靠全局模型传。熵切分的边界落在词首, 预测新词时上一个词完整地在前面的 patch 里; 固定切分常从词中间下刀, 上一个词的词首可能还没进入全局模型。实测熵切分 0.220, 固定切分 0.229。
3. 一个只有英文合并规则的 BPE 词表处理中文时会怎样? BLT 在 demo 里怎样处理中文词?
   **答**: 词表里没有中文合并规则时, 一个汉字最多被切成 3 个字节 token, 同样的意思中文要多花几倍 token (llm_train m26 的多语言实验)。BLT 按熵切分, 汉字的续字节好猜, 并进同一个 patch: demo 里中文词 10 字节 (含空格) 平均 1.00 个 patch, 和 8 字节的英文词一样。
