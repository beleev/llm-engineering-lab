# BD3-LM — 块扩散语言模型: 块间自回归, 块内掩码扩散

[llm_models 目录](../../../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/models/block-diffusion)

## 直觉

- LLaDA 的注意力是全双向的, 任何一个 `[MASK]` 被填上都会改变所有位置的 K/V, 所以它没有 KV cache, 每个去噪步都要把整段序列重算一遍, 生成长度也必须在开始前给定。
- 块扩散 (block diffusion) 把序列切成长度为 `block_size` 的块: 块与块之间按从左到右的顺序生成, 一个块内部仍然用 LLaDA 的掩码扩散并行去噪。
- 对应的注意力是 **块因果** 的: 一个位置能看到本块和之前所有块, 看不到之后的块。前面的块一旦定稿就不再受后面影响, 它们的 K/V 可以缓存; 生成可以一块接一块地往后续。
- 两个极端: `block_size = 1` 时块因果掩码就是因果掩码, 模型退化成自回归; `block_size = 序列长` 时掩码全可见, 前向与 LLaDA 逐位相同。

## 核心原理

### 核心公式

```
分解:     p(x) = Π_b p(x^b | x^{<b}),   每个条件分布是一个掩码扩散模型
加噪:     每个块各抽一个遮蔽率 t_b, 块内每个 token 独立以概率 t_b 变成 [MASK]
训练 loss: Σ_b (1/t_b) · Σ_{i ∈ 块 b 且被遮} −log p(x_i | 加噪的块 b, 干净的 x^{<b}) / L
裁剪日程:  训练时 t_b ~ U[β, ω] 而不是 U(0, 1); 本库取 [0.45, 0.95], 评估仍用全范围
```

`1/t` 权重和 "除以总 token 数" 与 LLaDA 相同, 代码直接把每个块当成一条短序列交给 `LLaDALoss`。裁剪日程针对的是方差: `t` 很小的块被遮的 token 很少, 乘上 `1/t` 之后单次估计忽大忽小, 把 `t` 限制在 `[β, ω]` 里就去掉了这一段。论文的 `β, ω` 是训练中按 loss 估计的方差网格搜索出来的, 块越小, 最优区间越靠近全遮; 本库固定取一组。

### 训练掩码: 一次前向算完所有块

如果逐块训练, 每个块都要单独跑一次前向, 前文还要重复计算。BD3-LM 把加噪序列 `x_t` 和干净序列 `x` 拼成长 `2L` 的输入, 两半共用位置 `0..L-1`, 再用一张分成四块的掩码:

```
           加噪 key   干净 key
加噪 query [ M_BD      M_OBC ]    M_BD : 块对角, 加噪块只看本块的加噪 token
干净 query [  0        M_BC  ]    M_OBC: 加噪块看之前各块的干净 token, 看不到本块的答案
                                  M_BC : 干净序列块因果, 算出的就是采样时缓存里的前文
```

干净那一半的隐状态与 "把干净块逐块送进 KV cache" 算出的完全一样, 加噪块看到的也正是采样时的 "cache 里的前文加当前草稿块"。所以训练和采样做的是同一件事 (脚本里有断言)。

### 采样: 草稿块不进 cache

每个块内部沿用 LLaDA 的低置信度重遮和线性日程。去噪过程中草稿块的 K/V 每一步都在变, 所以每步只把 cache 的浅拷贝传给前向; 块定稿以后再把它干净地过一遍, 这次的 K/V 才追加进真正的 cache。

## 运行

论文: Arriola et al., ICLR 2025, "Block Diffusion: Interpolating Between Autoregressive and Diffusion Language Models" (arXiv 2503.09573)。模型代码: `llm_models/models/language_models/block_diffusion.py`。

```bash
python -m llm_models.run_models.language_models.block_diffusion.infer_block_diffusion   # 约 7 s, 内部先训练 300 步
python -m llm_models.run_models.language_models.block_diffusion.train_block_diffusion   # 约 22 s, 含一个 LLaDA 对照
```

## 运行后应该看到什么

任务与 LLaDA 相同, 是 "置换链": 固定一个 16-环置换 π, 序列满足 `x[i+1] = π(x[i])`, 长度 16, 块大小 4。每步抽新数据和新遮蔽, 评估都在 held-out 序列上。下面是单线程 CPU、seed 0 的实测输出。

`infer_block_diffusion` 先打印 `L = 8`、块大小 4 时的训练掩码, 再做结构检查:

```
block_size = L 时与 LLaDA 前向的最大差 0.0e+00
训练前向 vs 逐块带 cache 前向, 加噪块 logits 最大差 4.9e-06
带 cache: 送进前向 80 个 token, 串行 20 次 | 不带 cache: 160 个 token, 串行 16 次 | 输出相同 True

真值 : 15  0  4  3  7  1 12 10  9  6 11  8 13  5  2 14
生成 : 15  0  4  3  7  1 12 10  9  6 11  8 13  5  2 14
给首 token 续写 15 个, 每块 4 步: 准确率 1.000 | chance 0.062
先生成 2 块 = 生成 4 块的前 2 块: 成立
```

断言: `block_size = 1` 的掩码等于因果掩码、`block_size = L` 时与 LLaDA 前向逐位相同、训练掩码与逐块带 cache 的前向一致、带 cache 与整段重算的生成相同且送进前向的 token 更少、先生成 2 块的结果等于生成 4 块时的前 2 块。

`train_block_diffusion`:

```
初始 loss 3.013  vs  ln V = 2.833
held-out loss (评估都用全范围 t) | 全范围训练 0.182 | 裁剪训练 0.183 | 下界 ln P / L = 0.173
同一批 64 条, 换 64 次遮蔽, loss 估计的 均值 ± 标准差:
  未训练 | 全范围 2.954 ± 0.171 | 裁剪 2.971 ± 0.069
  训练后 | 全范围 0.176 ± 0.041 | 裁剪 0.268 ± 0.050

给首 token 续写 15 个 (held-out 1024 条, chance = 1/16 = 0.062):
  LLaDA, 15 步           | 准确率 1.000 | 串行前向 15 次, 共 240 个 token
  BD3-LM 全范围, 每块 4 步 | 准确率 1.000 | 串行前向 20 次, 共 80 个 token
  BD3-LM 裁剪, 每块 4 步 | 准确率 1.000 | 串行前向 20 次, 共 80 个 token
  生成 32 个 (全范围训练) | 位置 1-15 准确率 1.000 | 位置 16-31 准确率 0.393
  生成 32 个 (裁剪训练) | 位置 1-15 准确率 1.000 | 位置 16-31 准确率 0.432
```

- 初始 loss 比 ln V 高约 0.18, 原因与 LLaDA 相同: weight tying 下 `[MASK]` 位置初始最偏爱输出 `[MASK]` 自己。
- 裁剪日程在未训练时把 loss 估计的标准差从 0.171 降到 0.069。训练好以后 `t` 小的块几乎都能猜对, `1/t` 放大的是接近 0 的 CE, 两种日程的标准差差不多 (0.041 和 0.050); 裁剪日程的均值更高, 是因为它只在难的那段 `t` 上取平均, 两个均值不是同一个量。两种日程训出来的 held-out loss 相同 (0.182 和 0.183)。
- 续写准确率三者都是 1.000。块扩散送进前向的 token 是 LLaDA 的 1/3, 但串行前向次数并没有更少 (20 次对 15 次, 其中 4 次是把定稿块写进 cache)。
- 生成到 32 个位置时, 训练见过的位置 1-15 仍然全对, 没见过的位置 16-31 只有 0.39 到 0.43。块因果结构允许一直往后接, 模型能不能在没训练过的位置和距离上写对是另一回事。

断言: 初始 loss ≈ ln V、两种日程训练后 loss 都低于初始的一半且不低于理论下界、未训练时裁剪日程的标准差小于全范围的一半、续写准确率 > 0.8、块扩散送进前向的 token 少于 LLaDA。

## 与真实系统的差距

- **规模**: 2 层、d_model=64、4 头, 词表 17 (16 个符号加 `[MASK]`), 训练序列长 16, 块大小 4。
- **任务是合成的**: 置换链整条序列只由首 token 决定, 能验证掩码、cache 和 loss, 说明不了自然语言上的困惑度。论文在 LM1B 和 OpenWebText 上报告块越小困惑度越接近自回归。
- **日程是固定的**: 论文在训练中按 loss 估计的方差搜索 `[β, ω]`, 不同块大小取不同区间; 这里固定取 `[0.45, 0.95]`。
- **没有停止符**: 论文的可变长生成是逐块采样直到出现 EOS (或样本质量下降)。这里的数据没有 EOS, 只演示了 "后面的块不改前面的块" 和 "生成超过训练长度" 两件事, 后者实测在没训练过的位置上明显变差。
- **骨干和 kernel**: 论文用自己的骨干和注意力实现; 这里直接继承 LLaDA 的 LLaMA 零件, 用一张显式的 bool 掩码。
- **推理加速另有一章**: 块内并行解码的步数调度、近似缓存等推理侧技巧不在这里, 见推理阶段的相关章节。
- **本库约定**: weight tying、embedding 乘 √D、N(0, 0.02²) 初始化, 不代表原模型的做法。

## 常见误区

1. **"块扩散就是 LLaDA 加了 KV cache"**: cache 能用的前提是注意力变成块因果, 这改变了模型本身, 训练时也必须用同一张块因果的掩码。拿训练好的 LLaDA 直接套 cache, 前文的 K/V 与训练时不一致。
2. **"块内也能用 cache"**: 去噪过程中当前块的 token 每一步都在变, 只有定稿的块才能写进 cache。代码里草稿块每步只用 cache 的拷贝。
3. **"块扩散比 LLaDA 少前向"**: 少的是每次前向的 token 数 (80 对 240), 不是串行前向次数 (20 对 15)。延迟取决于后者和每次前向的耗时。
4. **"裁剪日程的 loss 和全范围的 loss 可以直接比"**: 裁剪日程只在一段 `t` 上取平均, 均值更高 (0.268 对 0.176), 评估要换回全范围。
5. **"block_size 越大越好, 并行度越高"**: 块越大, 一步里同时定下的 token 越多, 彼此看不见; `block_size = L` 就回到了 LLaDA, 没有 cache 可用。

## 自测题

1. `block_size = 1` 和 `block_size = L` 时, 块因果掩码分别变成什么?
   **答**: `block_size = 1` 时每个块只有一个位置, 位置 i 能看到 0..i, 就是下三角因果掩码, 模型退化成自回归; `block_size = L` 时只有一个块, 所有位置互相可见, 前向与 LLaDA 逐位相同 (脚本里断言最大差 0)。
2. 训练时为什么要把加噪序列和干净序列拼成 `2L` 再用四块掩码, 而不是只喂加噪序列?
   **答**: 块 b 的条件是干净的前文 `x^{<b}`, 只喂加噪序列时前文也是加噪的, 与采样时 cache 里的定稿前文不一致。拼上干净序列后, 加噪块通过 `M_OBC` 看之前各块的干净 token, 一次前向就算完所有块, 结果与逐块带 cache 的前向一致 (最大差 4.9e-06)。
3. 生成 4 块、每块 4 步时, 带 cache 的版本串行前向 20 次、共 80 个 token; 整段重算的版本串行 16 次、共 160 个 token。多出来的 4 次串行前向是什么?
   **答**: 每个块定稿以后, 要把这个干净的块再前向一次, 把它的 K/V 追加进 cache, 4 个块就多 4 次; 换来的是之后每步只需送当前块的 4 个 token。
