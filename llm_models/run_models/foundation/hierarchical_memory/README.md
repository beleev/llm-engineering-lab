# 递归记忆与分层读取: 压缩丢了什么

## 直觉

8 个块、24 个细节查询: 保留全部 token 命中 24/24, 每次查询读 64 个单元; 把每块压成一个均值只读 8 个单元, 命中 0/24, 第 1 块是第 0 块的倒序, 均值相同、答案全不同。先按块 ID 路由再读块内位置, 24/24 命中、查询读 16 个单元, 但持久存储涨到 72。摘要能把前后两段连起来, 不一定能还原细节; 结构连通和信息保存要分别证明。

## 核心原理

demo 对 8 个块做精确位置问答 (每块问第 0、3、7 位, 共 24 条): full 读取全部 64 个单元, 24/24; recurrent 每块只留一个均值, 读 8 个单元, 0/24; hierarchical 先用块 ID 路由, 再读块内位置, 读 16 个单元, 24/24。

把第 1 块设成第 0 块的倒序: 均值一样 (碰撞块均值相同 = true), 细节答案却不同, 这是压缩不可逆的反例。固定大小的状态保存不了任意长的离散输入; 留什么丢什么, 取决于任务和学习目标。

分层路径把本例的查询读取从 64 降到 16, 却仍要存原始块, 再加 8 个索引, 持久存储 72。真实分层注意力的路由误差、摘要容量、KV 保留和跨块多跳都影响收益, 不能只看理论感受野。

## 怎样验证

固定同一个 8×8 数组和 24 个位置查询, 只换 full / recurrent / hierarchical 三种读取方式, 同时报告精确命中、查询读取单元和持久存储单元; 块 ID 已知, 所以这里不测语义检索, 有效上下文的对照实验见 agent-context-engineering。

## 与真实系统的差距

可控数组读写对照，不是 Transformer-XL 或训练过的分层注意力。读取单元是本例算法账本，不是端到端 FLOPs 或 GPU 延迟。

## 常见误区与自测

两个序列有相同摘要, 可以认为所有问题的答案相同吗?

<details><summary>展开解析</summary>

不可以。压缩映射会把不同输入映到同一个状态: demo 里第 1 块是第 0 块的倒序, 均值相同, 24 个细节查询在均值记忆上 0 命中。要主动构造摘要碰撞, 检查任务需要的细节有没有保存下来。

</details>
