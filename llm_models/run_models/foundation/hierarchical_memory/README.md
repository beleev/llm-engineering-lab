# 递归记忆与分层读取: 压缩丢了什么

## 直觉

这组实验用一个 8×8 的整数数组模拟一段长输入: 8 个块, 每块 8 个 token, 每个 token 是 0 到 99 之间的一个数。对每块问第 0、3、7 位是几, 一共 24 个细节查询, 比较三种记忆方式:
- 保留全部 token 命中 24/24, 每次查询读 64 个单元。
- 把每块压成一个均值只读 8 个单元, 命中 0/24, 第 1 块是第 0 块的倒序, 均值相同、答案全不同。
- 先按块 ID 路由 (先找到问的是哪一块) 再读块内位置, 24/24 命中、查询读 16 个单元, 但持久存储 (一直要占着的单元数) 涨到 72。
摘要能把前后两段连起来, 不一定能还原细节; 结构连通和信息保存要分别证明。

## 核心原理

demo 对 8 个块做精确位置问答 (每块问第 0、3、7 位, 共 24 条):
- full 读取全部 64 个单元, 24/24。
- recurrent 每块只留一个均值, 读 8 个单元, 0/24。
- hierarchical 先用块 ID 路由, 再读块内位置, 读 16 个单元, 24/24。
三种方式对应三类长上下文做法:
- full 像标准注意力, 所有 token 都留着, 每次查询都看一遍。
- recurrent 像递归记忆, 读完一块就把它压成一个固定大小的状态, 原文丢掉, 本例的状态就是这块 8 个数的平均值。
- hierarchical 像分层读取, 先在粗的一层选出相关的块, 再到细的一层读块里的内容。
均值一般不会正好等于被问的那一位上的数, 本例 24 个查询一个也没对上。读取单元和存储单元是 demo 写定的账本, 不是测出来的 FLOPs 或延迟。

把第 1 块设成第 0 块的倒序: 均值一样 (碰撞块均值相同 = true), 细节答案却不同, 这是压缩不可逆的反例。倒序只是把 8 个数的顺序反过来, 总和不变, 所以均值不变; 但第 0 位和第 7 位互换了, 第 3 位换成了原来的第 4 位, 问这三个位置得到的答案都变了。两块压缩后的状态一模一样, 不管后面用什么方法读这个状态, 都只能给两块同一组答案, 至少有一块要答错: 从状态推不回原文, 压缩不可逆。固定大小的状态保存不了任意长的离散输入; 留什么丢什么, 取决于任务和学习目标: 均值保留了总量, 丢掉了顺序, 对问这块整体多大的任务够用, 对问第 3 位是几的任务就不够。

分层路径把本例的查询读取从 64 降到 16, 却仍要存原始块, 再加 8 个索引, 持久存储 72。查询读 16 个单元, 可以理解为先读 8 个块索引确定是哪一块, 再读这一块的 8 个单元; 但为了能读到细节, 64 个原始单元一个也不能丢, 加上 8 个块索引一共存 72 个, 比保留全部还多。分层读取省的是每次查询要看的量, 不是存储。
本例的块 ID 是直接给出的, 路由不会选错; 真实分层注意力的路由误差、摘要容量、KV 保留和跨块多跳都影响收益, 不能只看理论感受野:
- 路由选错块就等于没存。
- 摘要层能装下的信息有限。
- 每块的 KV cache 留多少要权衡。
- 答案需要把两三块的信息串起来 (跨块多跳) 时只选一块也不够。
理论感受野是模型结构上能看到多远, 不等于它用得上那么远的信息。

## 怎样验证

固定同一个 8×8 数组和 24 个位置查询, 只换 full / recurrent / hierarchical 三种读取方式, 同时报告精确命中、查询读取单元和持久存储单元。
三个数要一起看:
- 命中数说明细节有没有保住。
- 读取单元说明每次查询花多少。
- 存储单元说明一直要占多少地方。
只看其中一个会得出偏的结论。块 ID 已知, 所以这里不测语义检索 (根据问题内容自己判断该去哪一块找), 有效上下文的对照实验见 agent-context-engineering。

## 与真实系统的差距

可控数组读写对照，不是 Transformer-XL 或训练过的分层注意力。读取单元是本例算法账本，不是端到端 FLOPs 或 GPU 延迟。

## 常见误区与自测

两个序列有相同摘要, 可以认为所有问题的答案相同吗?

<details><summary>展开解析</summary>

不可以。压缩映射会把不同输入映到同一个状态: demo 里第 1 块是第 0 块的倒序, 均值相同, 24 个细节查询在均值记忆上 0 命中。把一块 8 个数压成一个均值, 是把 8 个数变成 1 个数, 很多不同的块都会压出同一个均值; 第 0 块和它的倒序就是这样一对, 总和一样, 顺序却全反了。问第 3 位是几时, 均值记忆手里只有那一个平均数, 对两块只能给出同一个回答, 不可能两块都对。摘要相同只说明摘要保留的那部分信息 (这里是总量) 相同, 摘要丢掉的部分 (这里是顺序和具体数值) 可能不同。要主动构造摘要碰撞, 检查任务需要的细节有没有保存下来。
