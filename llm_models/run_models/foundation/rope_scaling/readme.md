# RoPE 长度外推: NTK / YaRN

## 直觉
RoPE 的第 i 对维度像一根转速为 θ_i 的表针, 位置 m 处指向角度 m·θ_i。高频针在训练长度 L 内转了几百圈, 所有角度都见过;
低频针连一圈都没转完, 模型只见过一小段弧。把位置推到 4L, 低频针就指向了**从未见过的方向** —— 这是外推崩坏的根源。
修法都是 "让针转慢一点": PI 所有针一律慢 s 倍 (高频也被压扁, 相邻 token 难区分); NTK 改 base, 高频几乎不动、最低频恰好慢 s 倍;
YaRN 按 "训练时转了几圈" 分段处理, 再补一个注意力温度。

## 核心公式
- plain: `θ_i = base^{-2i/d}`
- NTK: `base' = base · s^{d/(d-2)}` → `θ_0' = θ_0`, `θ_last' = θ_last / s`
- YaRN: `r_i = L·θ_i / 2π`, `γ_i = clip((r_i − 1)/(32 − 1), 0, 1)`, `θ_i' = (1−γ_i)·θ_i/s + γ_i·θ_i`; logits 乘 `(0.1·ln s + 1)²`

## 运行命令
```bash
python -m llm_models.run_models.foundation.rope_scaling.infer_rope_scaling
```
代码: `llm_models/layers/core/position_encoding.py::scaled_inv_freq`; 模型侧 `LLaMA(..., rope_scaling="yarn", rope_factor=4, rope_original_max_len=2048)`。

## 运行后应该看到什么 (实测, d_head=64, L=2048, s=4; 确定性, < 1 s)
位置 4L 处的角度 ÷ 训练见过的最大角度:

| 维 i | 圈数 r_i | plain | PI | NTK | YaRN |
|---|---|---|---|---|---|
| 0 | 325.95 | 4.00 | 1.00 | 4.00 | 4.00 |
| 16 | 3.26 | 4.00 | 1.00 | 1.96 | 1.22 |
| 24 | 0.33 | 4.00 | 1.00 | 1.37 | 1.00 |
| 31 | 0.04 | 4.00 | 1.00 | 1.00 | 1.00 |

- 低频维 (r<1) 11 个: plain 越界 4×; YaRN/PI 全拉回 1.00×; NTK 只有最低频恰好 1.00×, 其余至多 1.56×。
- 高频维 (r>32) 9 个: YaRN 原封不动; PI 把相邻 token 角度差 1.00 → 0.25 rad。
- mscale = 0.1·ln 4 + 1 = 1.1386 (logits × 1.2965)。三种方式都保持 ⟨q_m, k_n⟩ 只依赖 m−n。

## 常见误区
- 本 demo **没有训练模型、没有测 ppl**, 只验证了角度/频率层面的性质; "YaRN 的 ppl 优于 NTK" 是论文结论, 这里没有复现。
- "r_i ≥ 1 的维比值 4.00 也是越界": 不是, 转满过整圈的维所有角度都见过, 比值没有意义。
- "NTK 缩放 s 倍就能用满 s·L": 中间频率仍轻微越界, 实际可用长度打折 (所以有 dynamic-NTK)。
- "mscale 是随便的经验数": 序列变长后 softmax 分母项变多、分布变平, 乘 >1 的系数把注意力重新变尖。

## 自测题
1. d=64, s=4 时 NTK 的新 base? —— `10000 · 4^{64/62} ≈ 41,829`。
2. YaRN 为什么不碰高频维? —— 它们编码局部顺序, 且所有角度在训练时都见过; 压缩只会损失相邻 token 的分辨率。
3. s=32 时 YaRN 的 logits 乘多少? —— `(0.1·ln 32 + 1)² ≈ 1.813`。
