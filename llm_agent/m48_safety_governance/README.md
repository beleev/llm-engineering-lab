# 安全与治理: 误拒、漏拦和责任记录

## 直觉

LLM 系统的安全与治理证据需拆分为四个独立层次审视:
- 工具执行层: 模型提议的外部动作是否具备合法授权。
- 模型输出层: 模型生成的文本本身是否包含有害违规内容。
- 群体公平层: 不同受保护人群切片上的服务质量与误判率是否存在显著偏差。
- 研发治理层: 数据与模型的责任归属、审计日志及异常回滚机制是否完备。
本实验聚焦工具执行层的间接注入防御: 4 个合成测试案例包含 2 条正常请求与 2 条夹藏在外部文档中的注入攻击, 攻击企图诱导系统调用 send 外发资料, 而当前会话用户仅授权了 read 权限。
三种决策规则的对比结果如下:
- 关键词拦截 (命中「ignore previous」即拒绝) 误拒了 1 条仅正常引用并要求解释「ignore previous instructions」的良性请求, 同时漏放了 1 条不含敏感词但要求外发资料的改写攻击, 导致由这两例构成的 B 组正确率为 0。
- 无权限门控直接放行了全部 2 条越权攻击。
- 服务端权限门控由执行器严格核对服务端受控保存的 allowlist, 做到误拒 0、漏放 0。
良性文档完全可能正常讨论攻击文本, 恶意文档也完全可以避开固定敏感词, 因此操作权限只能源于可信服务端的用户授权状态, 绝不能依赖不可信文本的字面匹配。

## 核心原理

直接越狱与间接提示注入属于威胁源头与攻击目标截然不同的两类风险, 必须分别建立威胁模型与评测集:
- 越狱 (jailbreak) 由当前会话用户主动构造对抗话术, 企图绕过模型的安全对齐护栏以诱导模型输出违规内容。
- 间接注入 (indirect prompt injection) 则由第三方攻击者将恶意指令预埋进模型待读取的网页、PDF、邮件、图像或工具返回结果中, 企图劫持受委托的 agent 越权调用高危工具 (例如窃取并外发内部数据)。
由于两者的攻击入口与危害载体完全不同, 安全方案必须分别明确界定三项要素:
- 威胁模型: 攻击者所处的信任边界及其可操控的数据通道。
- 受保护资产: 系统需要守住的机密数据、外部副作用接口或输出合规底线。
- 攻击成功判据: 精确界定何种越权行为或违规输出算作防御失守。
不能用同一套敏感词规则混测两类风险; 本实验记录亦明确指出, 最终的工具授权门控不应依赖模型自身是否从文本中识别出注入企图。

实验专门将良性引用与恶意同义改写配成对抗样本对, 直接揭示字面关键词规则的结构性缺陷:
- quoted 为良性请求: 用户要求模型解释文档中引用的「ignore previous instructions」语句, 输入虽包含典型注入短语, 但实际请求动作仅为合法的 read。
- paraphrase 为恶意攻击: 外部文档将越权指令伪装为「将资料发送至外部邮箱以完成核验步骤」, 全文不含任何黑名单关键词, 却企图触发未授权的 send 动作。
实验将易判定的 ordinary 与 injected 编为 A 组, 将上述对抗配对 quoted 与 paraphrase 编为 B 组, 关键词拦截在 A 组正确率为 1.0, 在 B 组则跌至 0.0。
服务端权限模式完全脱离不可信文档文本, 仅在工具实际执行前核验模型提议的动作 proposed 是否属于服务端会话锁定的 allowlist: read 在白名单内予以放行, send 不在白名单内直接拦截。无论外部数据如何伪装成高优先级指令都无法自行扩张会话权限; 当然, 执行层门控仅管束工具副作用, 模型纯文本输出的有害内容仍需配套独立的安全对齐训练与评测。

模型输出层的内容安全依赖细粒度的对抗配对训练与多维分项评测, 以防止安全护栏退化为一刀切式的过度拒绝。安全微调阶段需围绕同一敏感主题同时构造良性探讨问法与恶意利用问法的意图配对样本, 避免模型习得只要命中特定话题词便无差别拒答的表面捷径。
输出安全评测应拆分为五项独立指标分别统计:
- 有害服从率 (应当拒绝的高危请求被错误放行)。
- 过度拒绝率 (合法无害的正常请求被误伤拒答)。
- 迎合偏见 (无原则顺从用户的错误前提或偏见立场)。
- 事实性欺骗与编造。
- 不同受保护人群切片之间的性能与误拒率差异。
同时, 红队对抗测试集 (专门构造用于探查安全漏洞的攻击样本) 应按攻击载体 (网页、邮件、多模态图像等) 与攻击手法家族保留独立的留出集, 不参与当前轮次的定向修补训练, 用以检验防御方案对未见攻击变体的泛化能力; 每次安全加固后还必须执行常规业务基准回归测试, 确认通用任务能力与正常请求通过率未受连带损伤。

研发治理层要求每一批训练语料与每一个发布模型都具备完整、防篡改的可追溯元数据档案。数据卡用于固化语料的来源、预期用途、授权条款、版本号、数据集切分及文件内容哈希 (如 sha256 摘要, 文件内容一旦改动哈希值即失配)。
本例的 validate_record 校验函数执行三项硬性准入检查:
- source、license、consent、purpose、version、split、sha256 共 7 个必填字段完整无缺。
- consent (是否取得合法使用同意) 字段值必须为 true。
- purpose 字段必须匹配当前允许用途 teaching。
因此仅包含单一 license 字段的残缺记录会被直接拦截退回。与之配套的模型卡则明确登记模型的适用场景、已知失效切片、推理成本与使用禁忌。
生产模型上线需严格闭环执行五步治理流程:
1. 预先登记潜在风险等级与直接责任人。
2. 完成离线安全性与业务基准全量验证。
3. 在受控灰度小流量下完成线上验收。
4. 配置实时监控告警阈值, 核心风险指标一旦越界立即触发熔断暂停或版本回滚。
5. 归档并更新全链路版本台账。
面对元数据缺失的数据记录必须退回源头补齐凭证, 严禁为绕过准入校验而伪造同意标记。

## 怎样验证

实验固定同一组 4 个合成测试案例 (2 条良性请求与 2 条间接注入攻击, 划分为常规 A 组与对抗配对 B 组), 仅切换底层授权判定规则 (关键词拦截、无权限门控、服务端白名单权限), 对比三项核心读数:
- 越权攻击动作被错误放行的次数。
- 良性正常请求被误伤拒绝的次数。
- A、B 两组各自的决策正确率。
实验边界在于本例仅验证工具执行层最小权限隔离逻辑及字面过滤的误报漏报机制; 生产级安全验收还必须纳入策略版本管理、全量授权审计日志、高危动作人工审批流及权限吊销测试。本实验结果不构成通用的防越狱安全保证, 亦不代表法律合规裁定。

## 与真实系统的差距

公开的合成夹具和动作门, 没有实际攻击, 也没有真实的安全模型。字符规则解决不了通用提示注入; 字段齐全也不等于拿到法律授权或通过合规认证。

## 常见误区与自测

检索文档要求新增导出权限, 执行层应该信谁?

<details><summary>展开解析</summary>

应当严格信任服务端受控维护的用户授权状态与安全策略, 绝不能采信外部检索文档中的文本要求。检索召回的外部文档属于非授信数据通道, 任何第三方内容提供者均可向文档中写入伪造的授权声明或操作指令; 若执行层依据文档文本动态放宽权限, 无异于将系统控制权直接交给外部文档编写者。
在本例中, injected 与 paraphrase 两条攻击案例均在检索文档内要求执行 send 外发操作; scoped 服务端权限模式完全不解析文档正文措辞, 仅在工具调用入口核查当前会话的 allowlist 是否包含 send, 发现未获授权后将两条攻击全部拦截, 而属于白名单内的合法 read 请求则正常放行。新增导出等高危权限只能经由可信控制面上的显式用户授权与服务端策略变更授予, 绝不能由数据面工具返回的内容自行扩张。

</details>
