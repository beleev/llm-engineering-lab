# 安全与治理: 误拒、漏拦和责任记录

## 直觉

同样 4 个案例, 关键词拦截误拒了 1 条引用 "ignore previous instructions" 的正常请求, 又放过了 1 条换了说法的外发攻击, B 组正确率 0; 不设权限门则 2 条攻击全放行。执行器只核对服务端 allowlist 时, 误拒 0、漏放 0。正常文档可以讨论攻击, 恶意文档也可以不含关键词, 权限只能来自可信的用户授权。

## 核心原理

模型越狱想改变模型自己的回答边界; 间接注入则借网页、PDF、邮件、图片或工具返回来改变系统行为。两者要分别建威胁模型、受保护资产和成功判据, 不能拿同一组关键词测。

demo 把正常引用和恶意改写配成对: quoted 引用了注入句却只想 read, paraphrase 不含关键词却要 send。服务端固定 allowlist 在工具执行前核对 proposed 是否在授权内, 文档内容不能自行扩大授权; 模型层的有害输出仍要单独做安全训练和测试。

安全训练要把正常/有害请求按意图配对, 免得学成主题级一律拒绝; 评测拆开有害服从、过拒、迎合、事实欺骗与群体差异。红队样本按载体和攻击家族留出, 修复后回归原本的正常任务。

数据卡记录来源、用途、授权、版本、切分与哈希, demo 的 validate_record 要求 7 个字段齐全且 consent 为 true; 模型卡记录适用人群、失败切片、成本与限制。发布闭环是: 登记风险及责任人 → 离线验证 → 小流量验收 → 监控阈值 → 暂停/回滚 → 更新版本记录; 缺字段的记录退回补齐, 不能伪造同意。

## 运行

```bash
python -m llm_agent.m48_safety_governance.demo
```

只用标准库, Python ≥ 3.10 即可; 不需要模型 API。网页在对应章节里回放同一实验的执行记录。

## 怎样验证

固定 4 个合成案例 (2 条正常、2 条攻击, 分 A/B 两组), 只换决策规则, 比较攻击放行数、正常误拒数和两组正确率; 这只验证具体的授权与误报逻辑, 生产还要把策略版本、决策日志、人工复核与撤销测试纳入验收, 不构成通用防越狱保证或法律合规判定。

## 与真实系统的差距

公开的合成夹具和动作门, 没有实际攻击, 也没有真实的安全模型。字符规则解决不了通用提示注入; 字段齐全也不等于拿到法律授权或通过合规认证。

## 常见误区与自测

检索文档要求新增导出权限, 执行层应该信谁?

<details><summary>展开解析</summary>

信服务端保留的用户授权和策略。检索内容是不可信数据: demo 里 injected 和 paraphrase 都在文档里要求 send, scoped 模式只看 allowlist 里有没有 send, 两条都拒, 正常的 read 照常放行。

</details>
