# m45 · 学出来的检索向量与联合重排

## 直觉

随机投影只能保留词面相似性。这里把词袋平均池化后送入可训练投影、归一化，再用 query/document 对比 CE 把配对拉近。重排器把查询和候选文档一起输入 MLP，学习联合判别；不是手写关键词加分。

## 核心原理

文档是三种设置（邮件、通知、备份）的开启/关闭，加两条稀有编号。训练双编码器使用 36 个中英同义表述，另外给联合重排器 36 个否定样本。每次对全部六个设置文档打分，错误对象和相反动作都是负样本；相反动作共享大部分词，是难负样本。代码中的平均池化会丢掉词序，无法理解任意嵌套否定。

按四层拆开错误：

1. exact：在所有文档向量中精确排序。错了是表征/训练覆盖问题，不能怪 ANN。
2. ann：两个人工分区，只搜最相似质心所属的一组；比较是否保留 exact 的赢家，区分索引近似误差。本实验不实现 HNSW。
3. rerank：只重排 exact 的 top-4；wide 则重排全体。top-4 没有答案时，重排不可能救回来。
4. hybrid：明确识别 ZX 编号并精确约束，再保留语义候选。编号规则不是神经模型学到的能力。

## 运行

```bash
python -m llm_agent.m45_semantic_retrieval.demo
```

## 运行后应该看到什么

seed=23，投影参数实际变化。四题分别检查同义、跨语言、否定、罕见编号。前两题只留出前缀组合，词语本身都已训练；否定是重排训练内机制探针，不是泛化测试。编码器会把“不要开启邮箱”排到开启；候选召回为假时，小范围重排也失败。两个 ZX 码都映射成未知词，向量相同，编号题需要词面精确约束。

网页可切换五种阶段，保留错误结果。提升召回范围能让重排接触到正确文档，但会增加联合前向成本，也不保证稀有编号正确。

## 边界与自测

这是有限任务上的真实小模型训练，不是预训练句向量模型、Transformer cross-encoder、真实向量数据库或通用多语言能力。只测四题不能估计线上准确率；真实验收需独立语料、同义/否定/编号切片和检索召回率，并单独验证答案引用。

为什么 exact 正确但 ANN 错误，不应重训 encoder？为什么 rerank 错误要先看 candidate_recall？答案分别是索引剪枝和召回上界；先找出丢答案的那一层。
