# m45 · 学出来的检索向量与联合重排

## 直觉

随机投影只保留词面相似: email 和 邮箱 没有共同字符, 投影后互不相近。m45 把词袋平均池化后送进一个可训练投影 (nn.Linear, 24 维, 再归一化), 用 query / document 对比 CE 把配对拉近。

重排器把查询和候选文档拼在一起送进一个 MLP, 学的是联合判别; 它不是手写的关键词加分规则。

## 核心原理

文档一共 8 条: 邮件、通知、备份 3 种设置各有开启 / 关闭 2 条, 再加 ticket ZX91、ticket ZX92 两条稀有编号。

- 双编码器: 36 条中英同义表述 (3 个对象 × 2 个动作 × 3 种动词写法 × 2 种对象写法) 当训练查询, 每条对全部 6 个设置文档打分做 CE, 训 160 步。错误对象和相反动作都是负样本; 相反动作和正样本共享大部分词, 是难负样本。
- 联合重排器: 除了这 36 条, 再看 36 条「不要 …」否定样本, 共 72 条, 训 240 步。双编码器看不到否定样本, 所以训练覆盖和 ANN 误差能分开。
- 平均池化丢掉词序, 模型理解不了任意嵌套的否定。

错误按四层拆开, 先定位丢答案的那一层:

1. exact: 在全部 8 条文档向量里精确排序。exact 错了是表征或训练覆盖的问题, 不能怪 ANN。
2. ann: 两个人工分区, 只搜质心最相似的那一组。看它有没有保留 exact 的赢家, 就能分出索引近似误差。本实验不实现 HNSW。
3. rerank: 只重排 exact 的 top-4; wide 则重排全部文档。top-4 里没有答案时, 重排不可能救回来。
4. hybrid: 先识别 ZX 编号做词面精确约束, 再保留语义候选。编号规则不是神经模型学到的能力。

## 运行

```bash
python -m llm_agent.m45_semantic_retrieval.demo
```

需要 torch, 单线程 CPU 训练。它不在默认 run_all 里, `python -m llm_agent.run_all --with-training` 才会带上。

## 运行后应该看到什么

seed=23, 投影参数真的在变 (demo 断言 parameter_delta > 0)。四道探针各查一件事: 同义改写、跨语言、否定、罕见编号。

- 同义改写 `today activate email`、跨语言 `today 关闭 备份`: 动词和对象词都在训练集里见过, 留出的只是 today 这个前缀组合。demo 断言这两题 exact 必须命中。
- 否定 `不要 开启 邮箱`: 编码器把它排给 enable email。这题参与过重排训练, 是机制探针, 不是泛化测试。
- 罕见编号 `ticket ZX92`: ZX91 和 ZX92 都映射成 <unk>, 两条文档向量完全相同, 只有词面精确约束能分开; demo 断言 hybrid 必须命中 ticket ZX92。

候选召回为假时, 小范围重排也一起失败。网页可以切换 exact / ann / rerank / wide / hybrid 五种阶段, 错误结果原样保留。放宽召回范围能让重排接触到正确文档, 但联合前向的次数跟着涨, 也不保证稀有编号正确。

## 边界与自测

这是有限任务上的真实小模型训练: 不是预训练句向量模型, 不是 Transformer cross-encoder, 不是真实向量数据库, 也没有通用多语言能力。只测 4 题估不出线上准确率; 真实验收需要独立语料、同义 / 否定 / 编号三类切片和检索召回率, 答案引用还要单独验证。

- exact 对、ANN 错, 为什么不该重训 encoder? 丢答案的是索引剪枝: 两分区只探了一组, 向量本身没错。
- rerank 错, 为什么先看 candidate_recall? top-4 是重排的召回上界, 答案不在里面, 重排怎么学都救不回。先找出丢答案的那一层, 再决定修哪里。
