# 工具学习：从候选调用到训练数据

## 直觉

工具调用执行成功，不代表值得教给模型。训练数据应保留能帮助后续预测的调用，并计算额外成本。

## 核心原理

Toolformer 式路径先提出插入位置与参数，执行工具，再比较有无工具输出时后续 token 的损失，只保留有收益的调用。工具结果必须作为观察插入，不能伪装成用户授权。

本例实际执行加法，使用公开的条件读出概率计算 log-likelihood 收益；从接受标签估计两类上下文的调用频率，在独立题目上验证。过滤器在这里固定，并未训练语言模型。

成本门槛过低会保留无用调用，过高会丢掉有益调用。真实数据还需去重、防答案泄漏、记录工具版本、超时和异常，再用 SFT loss mask 只监督应该学习的动作与回答。

## 运行

```bash
python -m llm_agent.m53_tool_data.demo
```

需要 Python ≥ 3.10，依赖使用仓库的 numpy / torch；不需要模型 API。网页在现有章节中提供同一实验的执行记录回放。

## 怎样验证

无过滤、收益过滤和高成本门槛分别验收调用数与正确数。真实 Toolformer 的候选生成、语言模型条件似然和再训练规模不在此小模型结果中。

## 与真实系统的差距

Toolformer 数据构造机制的最小对照。工具输出按观察而非用户指令插入；真实场景还要隔离执行、去重并计入延迟与权限成本。

## 常见误区与自测
