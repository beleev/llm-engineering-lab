# 工具学习: 从候选调用到训练数据

## 直觉

工具调用数据是用来教模型「什么时候该调用工具」的训练样本: 每条样本记下在哪里调用了哪个工具、传了什么参数、拿回什么结果。demo 只有一个加法工具和两类题: 算术题要答 a+b, 复述题只要把 a 原样说出来; 每类 60 题, 40 题用来构造训练数据, 20 题留出来验收。
三种收录规则的结果:
- 如果执行成功的调用全部收录, 学出的策略在留出的 40 题上每题都调用, 复述题也被答成 a+b, 只对 20 题。
- 按有、无工具时答对概率的对数差 (似然收益) 过滤后, 只在算术题上调用 (20 次), 40 题全对。
- 把收录门槛提到 6, 算术题的收益也不够, 0 次调用, 又只对 20 题。
工具执行成功, 不代表值得教给模型; 训练数据应保留能帮助后续预测的调用, 并把额外成本算进去。

## 核心原理

Toolformer (2023 年的一篇论文) 用一条自动流程构造工具调用数据:
1. 先让模型在文本里提出候选调用, 包括插在哪个位置、参数填什么。
2. 实际执行工具。
3. 再比较插入工具输出前后, 后面那些 token 的预测损失有没有下降。
4. 只保留让损失下降的调用。
工具结果要作为观察 (外部返回的信息) 插进去, 不能伪装成用户的指令或授权。

demo 实际执行了加法, 但「模型」用一组公开写死的读出概率代替: 在 200 个候选答案里, 给正确答案多大概率。
读出概率这样定:
- 无工具时, 算术题答对的概率是 0.005, 复述题是 0.9。
- 有工具时, 工具结果等于正确答案就给 0.9, 不等于就只剩 0.1/199。
似然收益是 $\log p_{\text{有工具}}-\log p_{\text{无工具}}$, 这个式子在说: 插入工具结果后, 正确答案的概率变大了多少倍 (取对数), 大于 0 表示工具帮了忙。
两类题的收益:
- 算术题的收益是 log(0.9/0.005), 约 5.19。
- 复述题的工具结果是 a+b 而不是 a, 收益约 -7.49, 是负的。
接着从 80 道训练题上「收或不收」的标签, 估计两类题各自的调用频率 (这就是学到的调用策略), 再在 40 道留出题上验收。过滤器在这里是固定规则, demo 没有训练语言模型。

成本门槛过低会留下没用的调用, 过高会丢掉有用的调用:
- 全收录时, 复述题的加法调用也进了训练集, 学出的策略在复述题上也调工具, 答成 a+b 而答错。
- 门槛 6 代表每次调用都有延迟、权限等成本, 收益要大过它才收; 可算术题的收益 log(0.9/0.005) 约 5.19, 也过不了 6, 训练集里一条调用都不剩, 留出题上 0 次调用。
真实数据还要:
- 去重。
- 防答案泄漏 (要预测的答案提前出现在输入里)。
- 记录工具版本、超时和异常。
- 再用 SFT loss mask (算损失时遮掉不该学的部分) 只监督模型该学的调用动作和回答。

## 怎样验证

固定同一批题 (算术、复述各 40 道训练题加 20 道留出题) 和同一个加法工具, 只换三种筛选规则:
- no-filter 全部收录。
- loss-filter 收益大于 0 才收。
- cost-aware 收益大于 6 才收。
比较留出题上的调用次数和答对的题数。真实 Toolformer 的候选生成、语言模型给出的条件似然和再训练规模, 都不在这个小模型结果里。

## 与真实系统的差距

Toolformer 数据构造机制的最小对照。工具输出按观察而不是用户指令插入; 真实场景还要隔离执行、去重, 并计入延迟与权限成本。

## 常见误区与自测

工具执行成功就应该把调用加入训练集吗?

<details><summary>展开解析</summary>

不应该。工具执行成功只说明加法算对了, 是执行层的事实, 不说明这次调用对回答问题有帮助。demo 里复述题的加法调用全部执行成功, 但复述题要的是 a 本身, 工具给的 a+b 反而把答案带偏了; 把这些调用也收进训练集, 学出的策略在复述题上也调用工具, 留出题只对 20/40。筛选还要看调用对后续预测的收益、任务是否正确, 以及权限和资源成本。
