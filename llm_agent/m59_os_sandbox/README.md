# m59 — OS 级沙箱: 权限门管调用, 沙箱管进程

[Agent 目录](../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/agent/sandbox)

## 直觉

m03 的权限门按规则判断一次工具调用放不放行, 它看到的只有命令文本。两件事它管不了:

- 提示注入可以让一条已经获准的命令去做别的事。`npm test` 在白名单上, 但被注入的文档可以让这次执行顺手读一下 `~/.ssh/id_rsa` 再往外连一个域名; 权限门看到的还是 `npm test`, 连问都不会问。
- 任意 shell 命令的形式无法用规则穷举。`bash -c "$(cat README.md)"` 这种写法, 黑名单里写多少条都漏得掉。

OS 级沙箱换一个位置下手: 进程已经获准在跑了, 它每一次文件和网络访问再判一遍。两层隔离各管一件事, 缺一不可 — 没有网络隔离, 被注入的进程能把密钥传出去; 没有文件系统隔离, 它能改掉沙箱配置再去联网。

- 文件系统: 只允许写工作区, 拒读密钥目录。路径必须先规范化 (展开 `..` 和符号链接) 再判断, 拼完字符串直接比前缀是经典漏洞。
- 网络: 进程本身没有出口, 出站流量走沙箱之外的代理, 代理按域名白名单放行, 遇到新域名问人。

本模块是一个策略评估模拟: 给一组系统调用事件按策略判定放行或拦截, 不真正隔离任何东西, 也不执行任何命令。对照四种配置, 看越界操作和人确认次数各是多少。

## 核心原理

### 两层各拦住什么

`verdict(kind, target)` 是沙箱对一次访问的判定, 同时也是「什么算越界」的定义:

- `connect`: 主机名在出站白名单上才放行。直连 IP 没有主机名可查, 一律不放。
- `read` / `write`: 路径先 `normalize`, 落在密钥目录里就拦。
- `write`: 规范化后不在工作区之内就拦。

`gate(command)` 是权限门, 按命令文本给出 deny / allow / ask 三档, 它看不到这条命令跑起来会碰什么。

四种配置的分工, 从 demo [1] 的计数读出来:

| 配置 | 越界发生 | 界内破坏性操作 | 人确认 |
|---|---|---|---|
| 都不开 | 8 | 1 | 0 |
| 只开权限门 | 7 | 0 | 8 |
| 只开沙箱 | 0 | 1 | 0 |
| 两者都开 | 0 | 0 | 4 |

只开权限门时越界从 8 降到 7: 降的那一次是黑名单恰好匹配上的 `curl ... | sh`, 剩下 7 次全部发生。只开沙箱时越界降到 0, 但 `rm -rf /work/build` 这种界内的破坏性操作沙箱不管, 它在界内。

### 先规范化, 再判断

```python
def normalize(path, links):
    for _ in range(8):                 # 符号链接可以嵌套, 给一个上限防成环
        parts = []
        for seg in path.split("/"):    # 先按字面展开 . 和 ..
            if seg == "..":
                if parts: parts.pop()
            elif seg not in ("", "."):
                parts.append(seg)
        path = "/" + "/".join(parts)
        ...                            # 再展开符号链接; 展开后可能又出现 .., 所以循环
```

demo [2] 的两条路径字面前缀都是工作区, 前缀匹配会放行:

- `/work/notes/../../home/u/.ssh/id_rsa` 规范化后是 `/home/u/.ssh/id_rsa`。
- `/work/vendor/id_rsa` 经工作区里的符号链接指向同一个真实位置。

### 沙箱为什么能减少人确认

权限门只能靠命令文本判断, 所以例行命令 (`ruff check`、`grep`、`node build.js`) 全部落在 ask 档, 一条一条问人。开了沙箱之后, 越界的后果有硬边界兜着, 这些命令可以直接跑, 只有真要出界时才需要人点一次。demo [1] 的事件表上确认次数从 8 次降到 4 次。

## 运行

```bash
python -m llm_agent.m59_os_sandbox.demo
```

纯标准库, 确定性, 不执行任何命令, 单线程 CPU 约 0.2 s。

## 与真实系统的差距

- 事件表是手写的, 不是 strace 或 eBPF 抓来的真实系统调用序列。越界与否由同一个 `verdict` 函数定义, 所以「不开沙箱时越界了几次」是按这套策略算出来的计数, 不是实测的攻击成功率; 确认次数的 50% 降幅同理, 只是这张表上的计数。
- 不真正隔离, 也不执行任何命令。真实实现靠 OS 原语: Linux 用 bubblewrap, macOS 用 Seatbelt, 覆盖范围包括被这条命令派生出来的脚本和子进程; Codex 在 Linux 上用 bwrap 加 seccomp, macOS 上用 `sandbox-exec`。本模块只模拟策略判定的结果。
- 网络隔离只模拟了「按主机名查白名单」。真实实现是把进程的网络出口整个拿掉 (Linux 上移除 network namespace), 流量经 unix domain socket 交给沙箱外的代理, 由代理查域名并在遇到新域名时问人。代理本身可能是最薄弱的一环: Anthropic 公开过一个案例, 出站代理看到目标是自家 API 域名就放行, 数据因此被带了出去。
- 权限门被问到时假设人会点同意。真实数据里人确实大多点同意: Anthropic 的遥测显示用户批准了约 93% 的权限提示, 这也是为什么要在提示之外再加一层硬边界。
- 不模拟检查与打开之间路径被换掉 (TOCTOU)、硬链接、沙箱自身的逃逸, 也不模拟 seccomp 层面的系统调用过滤。
- 真实沙箱的覆盖范围有缺口: Claude Code 的沙箱只管 shell 命令, 它自己的文件工具、MCP server 和 hook 都跑在沙箱之外, 所以 `denyRead` 挡不住 Read 工具, `allowedDomains` 也不限制 WebFetch。本模块没有建模这种「一部分通道在沙箱外」的结构。

## 常见误区

- **"有了权限门就不需要沙箱。"** 权限门看到的只有命令文本。demo [1] 里 `npm test` 在白名单上, 它被注入带去读密钥、往外连域名的那两次访问, 权限门连问都不会问, 越界从 8 次只降到 7 次。
- **"有了沙箱就不需要权限门。"** 沙箱只管出不出界。`rm -rf /work/build` 整个在工作区内, 沙箱放行, 只有权限门拦得住。两者拦的是不同的东西。
- **"沙箱能防住提示注入。"** 沙箱不阻止注入发生, 它让注入成功之后拿不到东西: 读不到密钥、连不上外面的服务器。识别注入是 m12 标记层的事, 而标记层只能降低概率。
- **"路径以工作目录开头就是安全的。"** demo [2] 的两条路径字面前缀都是 `/work`, 规范化之后都在 `/home/u/.ssh` 里。必须先展开 `..` 和符号链接再判断。
- **"黑名单列够了危险命令就行。"** demo [1] 里黑名单拦下了 `curl ... | sh`, 却拦不住 `bash -c "$(cat README.md)"`。任意 shell 命令的形式穷举不完, 这正是需要另一层的原因。

## 自测题

1. `npm test` 在权限门的白名单上。一份被注入的文档让这次执行顺便读了 `~/.ssh/id_rsa`。权限门为什么不会拦, 也不会问?

<details><summary>答案</summary>

权限门的输入是命令文本。它看到的是 `npm test`, 匹配白名单规则, 直接放行, 这次调用的全部判定就结束了。命令跑起来之后打开了哪些文件、连了哪些域名, 权限门根本不在这条路径上。要在这一层拦住, 得有人在进程执行期间逐次访问地判, 这就是 OS 级沙箱的位置。

</details>

2. 只开沙箱不开权限门, demo 里越界次数降到 0, 为什么还要保留权限门?

<details><summary>答案</summary>

沙箱只管出不出界, 不管界内有什么。`rm -rf /work/build` 整个落在工作区内, 沙箱放行, demo [1] 里「只开沙箱」这一行的界内破坏性操作仍然是 1 次。工作区里就是用户正在改的代码, 删掉它一样是损失。权限门是按意图判断的那一层, 两者拦的东西不重叠。

</details>

3. 开了沙箱之后, 为什么需要人确认的次数反而变少了?

<details><summary>答案</summary>

权限门只能靠命令文本判断, 所以 `ruff check`、`grep`、`node build.js` 这类例行命令全部落在 ask 档, 一条条问人。沙箱给了越界后果一条硬边界, 这些命令可以直接跑; 只有访问真的被沙箱拦下、确实需要出界时才问一次。demo [1] 这张事件表上是 8 次降到 4 次; Anthropic 公开的内部数字是减少 84% 的权限提示。

</details>
