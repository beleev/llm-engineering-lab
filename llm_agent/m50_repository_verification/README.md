# 代码任务：跨文件修改与独立验收

## 直觉

一个函数通过测试，不等于整个仓库的行为正确。接口单位变了，调用方也必须理解同一个约定。

## 核心原理

案例把折扣接口从百分数改为小数。只修改定义会让账单计算出错；完整补丁同步调用方。独立验证器使用候选无法修改的测试，检查多个价格与折扣组合。

代码模型可用 next-token 或 Fill-in-the-Middle（prefix/suffix/middle 重排）训练补全；测试生成则要考虑断言是否独立于实现。写出可编译代码、通过可见测试和解决用户需求是不同层次。

仓库级检索需要符号、调用关系、构建配置、依赖版本与变更范围。私有仓库适配应防数据泄漏，按时间与仓库族拆分，避免相同代码拷贝同时进入训练和测试。

漏洞任务需单独核验触发条件、修复与回归，不能把静态告警数量下降当作安全改善。真实候选执行应在受限容器/虚机中限制网络、资源和写路径；Python -I 只隔离导入环境，不是安全沙箱。

## 怎样验证

对完整、局部和投机补丁分别启动独立 Python 进程验收。可见测试被替换为 assert True 也不能影响外部判分；本例只运行本仓库生成的可信小片段。

## 与真实系统的差距

两个模块的受控 API 迁移，候选补丁由程序给定，不是通用 Coding Agent 或安全沙箱；-I 只隔离 Python 环境，不隔离操作系统权限。
