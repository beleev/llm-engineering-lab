# 代码任务: 跨文件修改与独立验收

## 直觉

仓库级验证是说: 改了一个接口之后, 要检查整个仓库里用到它的地方是不是都还对, 而且由候选 (提交补丁的代码 agent) 改不到的验收器来判。demo 把 rates.py 的折扣率从百分数改成小数 (20% 写成 0.2), 调用方 invoice.py 原来要把折扣除以 100, 现在不该再除。
三个补丁的结果:
- 只改 rates.py、不改 invoice.py 的补丁, 在工作区外的 4 个独立用例里只过 1 个, 验收进程退出码 1 (非 0 表示失败)。
- 同步改了调用方的完整补丁 4/4。
- 另一个候选把 total 直接写死成 80, 又把本地测试改成永远成立的 assert True, 自报全绿, 独立用例照样只过 1/4。
一个函数过了测试, 不等于整个仓库对了。

## 核心原理

这个案例考的是跨文件的接口约定。rates.py 里的 rate() 现在返回小数 0.2 (打八折), invoice.py 里的 total(price, quantity) 用它算总价: 价格乘数量, 再乘 1 减折扣率。
两种补丁:
- 只改定义时, invoice.py 还在把折扣除以 100, 折扣率变成 0.002, (30, 3) 算出 89.82 而不是 72。
- 完整补丁把调用方的除法一起删掉, 4 个用例全过。
独立验证器用的是候选改不到的测试, 覆盖 (100, 1)、(30, 3)、(0, 5)、(12.5, 2) 四组价格与数量组合, 期望总价依次是 80、72、0、20。只改定义的补丁还能过 1 个, 是因为价格为 0 时怎么算都是 0。

代码模型可以用 next-token (从左到右逐个预测下一个 token) 训练补全, 也可以用 Fill-in-the-Middle (FIM) 训练。FIM 把一段代码切成前缀 prefix、中间 middle、后缀 suffix 三块, 重排成前缀、后缀、中间的顺序, 让模型看着前后文补出中间。测试生成则要看断言是否独立于实现: 如果断言的期望值是照着被测代码算出来的, 代码错了测试也会跟着错。
代码任务有三个不同层次:
1. 写出能编译的代码。
2. 通过可见测试。
3. 解决用户需求。
demo 的 test-cheat 就停在第二层: 它让自己的可见测试通过了, 需求并没有解决。

仓库级检索要拿到的不只是相似的代码片段。
改一个接口前, 要知道:
- 它的符号定义。
- 有哪些地方调用它 (调用关系)。
- 构建配置。
- 依赖的版本。
- 这次改动会波及多大范围。
demo 里只改接口的补丁漏掉了 invoice.py 这个调用方, 原因就是没追踪调用关系。
用私有仓库做适配训练时还要防数据泄漏: 按时间和仓库族 (同源或互相拷贝的一组仓库) 拆分, 别让同一份代码的拷贝同时进训练集和测试集, 否则测试分数会虚高。

漏洞类任务要单独核验, 候选代码也要在隔离环境里跑。
修漏洞时要分别确认三件事:
- 漏洞原来怎么触发。
- 修复后还能不能触发。
- 正常功能有没有被改坏 (回归)。
静态扫描工具的告警数量下降, 不算安全改善。
真实的候选代码要放进受限的容器或虚拟机里运行, 限制网络、资源和可写的路径。demo 用 python -I 启动验收进程, -I 只让 Python 忽略 PYTHON 开头的环境变量、不加载用户目录里的包, 隔离的是导入环境, 不是安全沙箱, 也不隔离操作系统权限。

## 怎样验证

固定同一份验收器 verify.py 和 4 个用例, 对三种补丁 (partial 只改接口、complete 同步调用方、test-cheat 硬编码加假测试) 分别在候选目录之外另起一个独立的 Python 进程, 实际导入候选代码去跑, 以通过个数和进程退出码判定。候选只能改自己工作区里的文件, 所以它把可见测试改成 assert True, 也影响不到外部的判分。本例只运行本仓库自己生成的可信小片段。

## 与真实系统的差距

两个模块的受控 API 迁移, 候选补丁由程序给定, 不是通用 Coding Agent, 也不是安全沙箱; -I 只隔离 Python 环境, 不隔离操作系统权限。

## 常见误区与自测

候选把自己的测试改为恒真, 怎样继续可信验收?

<details><summary>展开解析</summary>

用候选改不到的独立测试, 另起一个进程去核验。候选既能改代码, 也能改自己目录里的测试和报告, 所以它说「测试全过」不算证据, test-cheat 的全绿就是把本地测试改成 assert True、把 total 写死成 80 换来的。验收器 verify.py 放在候选目录之外, 候选碰不到; 它用另一个 Python 进程导入候选的 invoice.py, 跑 4 个期望值各不相同的用例, 写死的 80 只对得上 (100, 1) 这一个。结果 1/4、退出码 1; 候选自报成功不构成验收证据。
