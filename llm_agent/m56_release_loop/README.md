# 评测到发布：均分变好，为什么仍要回滚

## 直觉

一次发布改变了模型、提示、索引或工具，就需要知道变好了什么、伤害了谁，以及怎样恢复旧版本。

## 核心原理

离线同时检查均分、配对 bootstrap 与关键切片。小样本区间仅说明当前夹具；真实验收还需代表性任务、预先设定门槛和统计功效，不能反复挑显著结果。

版本由 model/prompt/index/tools 共同确定。固定请求回放模拟灰度，质量、p95、安全与成本任一越界触发回滚；缺反馈先等待，不能当成成功。

失败样本按输入去重后进入回归集，并排除受保护训练/验证/测试集合。生产还要做实体级去重、隐私处理、标签审核与分布漂移监测，回流数据不能直接污染最终测试。

## 运行

```bash
python -m llm_agent.m56_release_loop.demo
```

需要 Python ≥ 3.10；使用现有 torch 依赖。默认 CPU、本机夹具，无模型 API 调用。

## 与真实系统的差距

固定请求回放模拟 10% 灰度，没有操作真实流量。复用配对 bootstrap；平均提升不能抵消关键切片退化。回归样本按规范化文本去重并排除受保护集合，仍需实体级去重和隐私审核；延迟反馈与缺失分别计数。

## 怎样验证

同一组固定请求对比旧版/候选版；让候选版平均分提升但某个重要切片下降，发布门槛应识别。；模拟线上延迟或质量漂移并触发回滚，能够追溯当时的模型、提示、索引与工具版本。；反馈延迟与缺失单独计数；回流样本去重并保持训练/验证/最终测试隔离。复用已有统计和 trace，避免再建一套评测基础设施。

边界测试见 [test_engineering_completion.py](../../tests/test_engineering_completion.py)。
