# 评测到发布: 均分变好, 为什么仍要回滚

## 直觉

本组实验完整模拟从离线门禁、灰度放量到故障回滚与样本回流的上线闭环。基线旧版与候选新版先在同一组 20 道离线评测题上配对评估, 候选版总体平均分从 0.4 提升至 0.9; 但在「关键切片退化」工况中, 两道关键业务切片样本由对变错, 离线发布门禁直接拦截阻断上线。其余离线达标工况进入 10% 流量灰度阶段, 按线上观测指标执行三态决策:
- 有效用户反馈回收比例不足时保持 hold 状态, 继续观察而不盲目扩量。
- 反馈样本充足且全部指标达标时执行 promote 全量切换。
- 一旦线上质量跌至 0.625、p95 延迟升至 500、单请求平均成本升至 0.029 或检出 1 条安全违例, 任一指标越过红线即立即自动回滚至稳定旧版 0ba6aad826f1。

应用系统的一次上线往往耦合了模型权重、prompt、检索索引与工具链变更, 工程上必须精确定位收益来源、受影响切片以及可一键退回的完整配置快照。

## 核心原理

离线发布门禁必须联合校验总体得分增益、配对置信区间下界与关键业务切片不退化三项准入条件, 任一未过即拒绝放行:
- 总体均分差 delta: 本实验中候选版较基线旧版提升 0.5。
- 配对 bootstrap 置信区间: 健康候选组测得区间为 [0.3, 0.7], 门禁要求下界不低于 -0.05; 其计算步骤为:
  1. 对每道测试题计算候选版与旧版的配对得分差。
  2. 对配对差集合执行 1000 次有放回重抽样并求每次的样本均值。
  3. 截取经验分布中间 95% 的分位区间。
- 关键业务切片门限: 关键切片子集上候选版的正确题数不得低于旧版。

在「关键切片退化」工况中, 尽管配对提升区间 [0.2, 0.75] 完全位于 0 以上, 但因两道关键题发生退化仍被门禁拦截。实验边界: 基于 20 道离线题计算的置信区间仅反映该固定夹具样本的波动; 真实生产验收必须在实验前预先冻结验收数据集与显著性门槛, 保证充足的样本量与统计功效, 严禁事后反复更换测试子集挑选有利结果。

可回滚的发布单元必须将 model、prompt、index 与 tools 四项配置联合计算哈希生成唯一版本 ID, 确保故障时能够原子恢复整套运行依赖。本实验中基线版本 0ba6aad826f1 与候选版本 a1f094f7c16c 保持模型与工具不变, 仅变更了 prompt 与 index。实验边界: 灰度阶段通过确定性请求日志回放模拟 10% 线上切流, 未接入真实生产流量。在线监控设定四条自动回滚红线, 任一越界即触发切回旧版:
- 已反馈请求的质量得分低于 0.8。
- 请求 p95 延迟高于 250。
- 单请求平均成本高于 0.02。
- 安全违规计数大于 0。

在线质量仅在已回收显式反馈的样本上统计; 当反馈覆盖率未达 80% 门限时系统保持 hold 观察状态, 严禁将缺失或延迟到达的反馈默认记为正向成功。

线上暴露出的失败请求应沉淀至持续回归评测集, 但入库前必须经过去重与数据防泄漏隔离两道清洗工序:
1. 规范化输入去重: 去除输入文本首尾空白字符后计算哈希, 相同请求仅保留单条记录。
2. 受保护集合隔离: 逐条比对并剔除已存在于受保护训练集、验证集与最终基准测试集中的样本, 防止评估集与训练回流池发生交叉泄漏。

在「线上质量下降」工况中, 原始日志包含 3 条失败请求且因重放翻倍重复, 经规范化去重后收敛为 3 条独立样本, 其中 query-0 因命中受保护集合被剔除, 最终安全入库 2 条回归用例。实验边界: 生产级数据飞轮还需叠加近重复语义与实体级去重、隐私脱敏、人工标签复核以及输入分布漂移监测, 严禁将线上回流样本直接混入最终盲测基准。

需要 Python ≥ 3.10, 只用标准库; 配对 bootstrap 复用 `llm_agent.m13_evals.diagnostics.paired_interval`。本机夹具, 不调用模型 API。

## 与真实系统的差距

固定请求回放模拟 10% 灰度, 没有碰真实流量。配对 bootstrap 复用 m13 的实现; 平均提升抵消不了关键切片退化。回归样本按规范化文本去重、排除受保护集合, 仍需实体级去重和隐私审核; 延迟反馈和缺失反馈分开计数。

## 怎样验证

固定同一组离线评测题与同一批线上灰度回放请求, 在基线旧版与候选新版之间对照测试六种典型发布工况: 关键切片退化、线上质量下降、尾延迟超标、单次成本超标、安全违规回归与健康候选全量上线。验收联合核对四项结果:
- 离线门禁是否按预设规则放行或拦截。
- 灰度监控是否准确触发 hold、promote 或自动回滚。
- 流程结束时线上承载流量的活动版本 ID 是否正确。
- 回归集实际新增收录条数, 以及缺失反馈与延迟待到达反馈的统计条数 (本例中各为 1 条) 是否准确。

边界测试见 [test_engineering_completion.py](../../tests/test_engineering_completion.py)。

## 常见误区与自测

候选版本的离线总体平均分显著提升, 但关键业务切片得分出现退化, 应当执行何种发布决策?

<details><summary>展开解析</summary>

应当由离线门禁直接拦截暂停发布, 并针对受损切片开展归因诊断。上线准入准则必须在查阅评测分数前预先锁定, 本实验要求同时满足三项条件方可进入灰度:
- 总体平均分不低于基线版本。
- 配对 bootstrap 提升区间下界不低于 -0.05。
- 关键业务切片不发生退化。

在该异常工况中, 尽管候选版总体均分大幅提升 0.5 且置信区间整体大于 0, 但两道关键业务题由对变错导致 slice_ok 判定为 false, 系统在离线阶段即拒绝放行。全集均值会将普通长尾题的得分涨幅与核心高优场景的退化线性抵消, 因此总体均分绝不能作为唯一上线依据; 同时也严禁通过事后更换测试集重新计算来绕过预设门禁。

</details>
