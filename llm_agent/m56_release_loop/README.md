# 评测到发布: 均分变好, 为什么仍要回滚

## 直觉

候选版均分从 0.4 涨到 0.9, 但两条关键切片从对变错, 离线门槛直接拦下。健康候选先 10% 灰度, 反馈不足时 hold, 到齐后 promote; 线上质量跌到 0.625、p95 到 500、成本到 0.029 或出现 1 条安全问题, 任一越界都回滚到旧版 0ba6aad826f1。一次发布改了模型、提示、索引或工具, 就得知道变好了什么、伤了谁, 以及怎样退回去。

## 核心原理

离线门槛同时看均分差、配对 bootstrap 区间和关键切片: 本例 delta 0.5、区间 [0.3, 0.7], 切片一退化就拒绝。小样本区间只说明当前夹具; 真实验收还要代表性任务、预先设定的门槛和统计功效, 不能反复挑显著结果。

版本由 model/prompt/index/tools 共同确定, 回滚才知道回到哪一版。固定请求回放模拟 10% 灰度, 质量 < 0.8、p95 > 250、成本 > 0.02、安全问题 > 0 任一越界就回滚; 反馈没到齐先 hold, 缺失反馈不能算成功。

失败样本按输入去重后进入回归集, 并排除受保护的训练/验证/测试集合: 线上质量下降那组 3 条失败请求去重、排除受保护的 query-0 后只收 2 条。生产还要实体级去重、隐私处理、标签审核和分布漂移监测, 回流数据不能直接污染最终测试。

## 运行

```bash
python -m llm_agent.m56_release_loop.demo
```

需要 Python ≥ 3.10, 只用标准库; 配对 bootstrap 复用 `llm_agent.m13_evals.diagnostics.paired_interval`。本机夹具, 不调用模型 API。

## 与真实系统的差距

固定请求回放模拟 10% 灰度, 没有碰真实流量。配对 bootstrap 复用 m13 的实现; 平均提升抵消不了关键切片退化。回归样本按规范化文本去重、排除受保护集合, 仍需实体级去重和隐私审核; 延迟反馈和缺失反馈分开计数。

## 怎样验证

固定同一组请求对比旧版和候选版, 比较关键切片退化、线上质量下降、尾延迟超标、成本超标、安全回归、健康候选六种情形; 判定看离线是否通过、是否回滚、活动版本是哪一个, 以及回归集条数和缺失/待到达反馈的计数。

边界测试见 [test_engineering_completion.py](../../tests/test_engineering_completion.py)。

## 常见误区与自测

候选均分更高, 但关键业务切片更差, 该怎么发?
