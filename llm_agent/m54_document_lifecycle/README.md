# 文档生命周期: 旧答案什么时候必须失效

## 直觉

这组实验搭了一个最小的检索系统: 两个租户 (共用一套系统、数据互相不能看的两家客户) 各有一份带表格的文档, A 的写着「退款天数 12」, B 的写着「退款天数 11」。A 提问「退款 11」时:
- 先过滤: 如果先按权限筛掉 B 的文档再找最相似的一段, A 能拿到自己的「退款天数 12」。
- 后过滤: 如果先找最相似的一段再删掉无权读的, 排第一的是 B 的「退款天数 11」, 删掉之后什么也不剩, 没有泄露, 但答案也没了。

再做几种改动:
- 文档改成 15、撤掉 A 的权限、删除文档这三种变更之后, A 之前拿到的旧引用全部失效。
- 换一个版本的编码器 (把文本变成向量的模型) 去查旧索引, 查询直接被拒绝。

所以检索结果对不对, 不只看文本像不像, 还要看此刻有没有权读、引用的版本是否仍然有效、能不能回到原文。

## 核心原理

检索系统先把文档切成小段 (chunk), 再按段查找, 所以切法决定了答案能不能追溯回原文。本例的解析器按段落和表格行切块: 表格里「退款天数」和「12」这一行作为一个整体, 不会把 12 拆成一个没有表头的孤立数字。每个 chunk 都记着:
- 它来自哪份文档 (source)。
- 文档第几版 (version)。
- 属于哪个父级 (parent)。
- 在原文里的字符起止位置 (offset)。
- 用哪个版本的编码器算的向量。

引用时按 offset 从原文里切出那一段, 重新解析一遍, 必须和 chunk 的文字一致。PDF 要保留页码和坐标, 扫描件还要 OCR (文字识别) 的置信度和版面顺序, 本模块遇到原始 PDF 直接报错; 解析失败必须报错, 不能当成「解析成功但内容为空」。

权限过滤放在哪一步, 决定了合法答案会不会被挤掉。两种放法:
- 前过滤: 先把 A 无权读的 chunk 全部排除, 只在 A 有权读的集合里找最相似的。
- 后过滤: 先在所有 chunk 里取最相似的前 k 个 (top-k, 本例 k 是 1), 再删掉 A 无权读的。

这里的「相似」用的是一个教学用的两维向量 (文本里最后一个数字, 加上有没有「退款」二字), 搜索时只查和问题数字落在同一区间的那一组, 这是一种简化的近似搜索 (ANN)。B 的「退款天数 11」和「退款 11」最像, 后过滤时它占了唯一的名额, 删掉后返回 0 条, A 自己的「退款天数 12」没有机会进候选。不管哪种方式, 最终返回前都要再校验一次权限, 原文、引用和缓存也要遵守同一个权限范围。

文档会改、权限会撤, 系统要保证旧答案跟着失效。具体有四处:
- 更新: 先把新版本完整解析成功, 再替换索引里的旧 chunk, 解析失败就保留旧快照不动。
- 代际: 每次更新、撤权或删除, 索引的代际 (epoch, 每次变更加一的计数) 都加一, 缓存整个清空; 缓存按代际区分, 旧代际的结果不会再被命中。
- 引用: 在被读取时还要再核对一次: 文档还在不在、版本是不是引用时那一版、读者还有没有权限, 任一不满足就失效, 所以本例三种变更之后 A 的旧引用都读不出来。
- 编码器: 新旧编码器算出的向量不能放在一起比相似度, 本例用 numbers-v2 去查 numbers-v1 建的索引会直接被拒绝, 要先重建索引。

## 与真实系统的差距

编码器是两维固定向量 (文本里最后一个数字, 加上有没有「退款」二字); ANN 只探测和查询数字落在同一区间 (每 20 一桶) 的那一个桶, 再保留 top-1。它们只用来隔离权限、召回和失效三种行为, 不代表真实语义效果。

HTML 保留字符偏移。PDF 和扫描件必须由单独的解析 / OCR 适配器提供页码和坐标, 本模块对原始 PDF 直接报错。缓存按租户和索引代际隔离, 一有变更就保守地全量失效。

## 怎样验证

固定 A、B 两个租户的同一批带表格文档, 每种情形都分三步:
1. 让 A 问一次「退款 11」并成功引用旧答案「退款天数 12」。
2. 做一种操作: 前过滤、后过滤、更新到 15、撤销 A 的权限、删除文档、换编码器版本。
3. 用同一个问题再问。

判定看四件事:
- A 拿到几个片段。
- 其中越权的是否为 0。
- 旧引用是否失效。
- 把索引存成快照再重新加载后查询结果是否不变。

边界测试见 [test_engineering_completion.py](../../tests/test_engineering_completion.py)。

## 常见误区与自测

权限后过滤没有泄露文档, 为什么仍可能找不到答案?

<details><summary>展开解析</summary>

因为无权的近邻先占了候选名额。后过滤的顺序是先找后删:
1. 在所有租户的文档里按相似度取前 k 个。
2. 把当前用户无权读的删掉。

本例 k 是 1, B 的「退款天数 11」比 A 的「退款天数 12」更接近查询「退款 11」, 于是唯一的名额给了 B; 删掉它之后候选是空的, A 的合法答案从来没有进过候选。前过滤先把范围限定在 A 有权读的文档里再找, 就返回了那 1 条。k 更大时不一定挤得这么彻底, 但无权的近邻越多, 合法答案被挤出名额的可能越大, 所以只看「越权返回为 0」不够, 还要看该找到的有没有找到。

</details>
