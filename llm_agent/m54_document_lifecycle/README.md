# 文档生命周期: 旧答案什么时候必须失效

## 直觉

本组实验构建了一个多租户最小文档检索系统: 隔离共享同一套基础设施的租户 A 与租户 B 各持有一份含表格文档, A 记录「退款天数 12」, B 记录「退款天数 11」。当租户 A 发起查询「退款 11」时, 对比两种权限注入时机:
- 检索前过滤: 先按租户 ACL 排除 B 的分块, 再于 A 的授权集合内检索最相近片段, A 正常召回自身的「退款天数 12」。
- 检索后过滤: 先在全量索引中取最相似片段再剔除无权项, 排名第一的 B 租户片段「退款天数 11」占满名额后被过滤剔除, 最终返回为空集, 虽未发生数据泄露, 但合法答案丢失。

进一步施加四类生命周期变更:
- 将源文档数值修订为 15、撤销租户 A 的读取授权或物理删除文档后, A 早前持有的历史引用在解引用核验时全部宣告失效。
- 升级查询端向量编码器版本后直接检索旧版索引, 系统因向量空间不兼容直接拒绝查询。

因此, 生产级检索的正确性不仅取决于语义相似度, 还同时受制于实时访问权限、文档版本时效、向量空间一致性与原文可追溯性。

## 核心原理

结构化切块策略与血缘元数据直接决定检索命中结果能否无歧义地回溯至源文档。本实验解析器按自然段落与表格整行切分 chunk, 将「退款天数」与「12」保留在同一语义单元内, 避免将数值拆解为脱离表头的孤立片段。每个 chunk 均持久化记录五项元数据:
- 源文档标识 (source)。
- 文档版本号 (version)。
- 所属章节或表格父节点标识 (parent)。
- 在源文档中的字符起止偏移 (offset)。
- 生成该嵌入向量的编码器版本标识。

解引用核验时按 offset 从当前源文档切片并重新规范化解析, 所得文本必须与 chunk 内容严格一致。真实工程处理版式 PDF 时还需保留页码与包围盒坐标, 扫描件则需额外记录 OCR 置信度与阅读版面顺序; 本最小模块不内置 PDF 解析器, 遇到原始 PDF 输入直接抛出显式错误, 且任何解析异常均须阻断上报, 严禁静默降级为「解析成功但内容为空」。

访问控制接入近邻检索的阶段直接决定高相似无权文档是否会挤占合法召回名额:
- 前过滤: 在距离排序前先剔除当前调用方无权访问的全部 chunk, 仅在授权子集内求解最近邻。
- 后过滤: 先在全量跨租户索引中取相似度最高的 top-k 候选 (本例设 k 为 1), 返回前再剔除无权项。

实验边界: 本实验使用教学简化的二维特征向量 (提取文本末位数值及是否包含「退款」关键词) 并按数值分桶执行近似最近邻检索 (ANN)。面对查询「退款 11」, 租户 B 的「退款天数 11」距离最近, 后过滤模式下该片段独占唯一的候选名额并在出口过滤时被清空, 返回 0 条结果, 使租户 A 合法的「退款天数 12」失去进入候选集的机会。无论采用何种过滤路径, 服务出口均须执行二次权限复核, 且源文档读取、引用展开与查询缓存必须遵循同一套权限边界。

文档内容变更、权限回收与编码器升级必须通过原子快照切换、代际失效与实时引用复核保证全链路状态一致:
- 原子更新切换: 新版文档必须先完整通过分块解析与向量化, 再原子替换索引中的旧版 chunk; 若解析失败则保持原索引快照不变。
- 代际计数与缓存失效: 每次执行文档更新、权限撤销或物理删除时, 索引代际计数 (epoch) 单调加一并立即清空查询缓存; 缓存键绑定当前代际号, 杜绝旧代际陈旧结果被再次命中。
- 解引用实时核验: 客户端持有的历史引用在展开读取时必须重新校验源文档是否存活、当前版本是否仍与引用记录一致以及调用方是否仍具读取授权, 任一条件失配立即拒绝访问, 因此本例三类变更后租户 A 的旧引用均无法读取。
- 编码器空间隔离: 不同版本编码器输出的向量空间不可直接计算内积或距离, 本实验中以 numbers-v2 查询编码器检索基于 numbers-v1 构建的索引会被直接拒绝, 必须先完成全量重索引。

## 与真实系统的差距

编码器是两维固定向量 (文本里最后一个数字, 加上有没有「退款」二字); ANN 只探测和查询数字落在同一区间 (每 20 一桶) 的那一个桶, 再保留 top-1。它们只用来隔离权限、召回和失效三种行为, 不代表真实语义效果。

HTML 保留字符偏移。PDF 和扫描件必须由单独的解析 / OCR 适配器提供页码和坐标, 本模块对原始 PDF 直接报错。缓存按租户和索引代际隔离, 一有变更就保守地全量失效。

## 怎样验证

固定租户 A 与租户 B 的同一批含表格源文档, 每组测试工况均按统一的三步序列执行:
1. 先由租户 A 查询「退款 11」, 获取初始结果并保存指向「退款天数 12」的合法引用。
2. 注入单一受控操作: 切换前过滤、切换后过滤、将文档数值更新至 15、撤销租户 A 访问权、删除源文档或切换编码器版本。
3. 以相同查询再次检索并尝试解引用早前保存的旧引用。

验收联合核查四项指标:
- 租户 A 实际召回的合法片段数量。
- 越权泄漏片段数是否严格保持为 0。
- 变更发生后历史旧引用是否按预期失效。
- 将当前索引序列化为磁盘快照并重新加载后, 查询输出是否完全一致。

边界测试见 [test_engineering_completion.py](../../tests/test_engineering_completion.py)。

## 常见误区与自测

检索后过滤并未泄露未授权文档, 为什么合法租户仍可能查不到原本存在的答案?

<details><summary>展开解析</summary>

因为其他租户的高相似无权分块提前占满了有限的 top-k 候选名额。后过滤遵循「先全库排序、后权限剔除」的执行顺序:
1. 不区分权限边界, 直接在全量跨租户索引中按相似度截取前 k 个候选。
2. 在返回出口剔除当前调用方无权读取的片段。

本实验中设 k 为 1, 租户 B 的「退款天数 11」相对查询「退款 11」的距离比租户 A 的「退款天数 12」更近, 因而独占唯一的候选名额; 出口权限校验将其剔除后候选集直接变为空集, 租户 A 的合法片段自始至终未能进入候选队列。改用前过滤先将搜索空间约束在租户 A 的授权文档集合内, 即可稳定召回该 1 条合法记录。增大 k 虽可缓解截断但无法根除高密度无权近邻造成的名额挤压, 因此评估多租户检索不能只核查「越权返回数为 0」, 还必须同时考核授权子集内的有效召回率。

</details>
