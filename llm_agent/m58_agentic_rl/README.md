# m58 — 多轮 Agent RL: 奖励只在结尾给, 中间几步的功劳怎么分

[Agent 目录](../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/agent/agentic-rl)

## 直觉

m32 在一个 3 步玩具上做了 SFT 加轨迹级策略梯度: 一条轨迹拿一个优势, 广播到这条轨迹的每个动作上。轨迹长到 4 轮、中间还夹着模拟用户的回复和工具结果时, 这种分法说不清是哪一步做对了。一条成功的轨迹里可能有一步纯属浪费, 一条失败的轨迹里前三步可能都对。

本模块在同一个小 LLaMA 上, 用完全相同的采样量对比三种信用分配:

- `traj`: 轨迹级奖励加轨迹级优势。奖励只在结尾给, 组内按回报归一化, 一条轨迹里每个动作拿同一个优势。
- `step`: 轨迹级奖励加逐步优势 (GiGPO)。把不同轨迹里出现过的同一个状态当作锚状态分一组, 组内比较从这个状态出发的折扣回报, 再和轨迹级优势相加。
- `turn`: 逐轮奖励加逐步优势 (per-turn reward 结构)。把那 1 分拆到四步上, 其余与 `step` 相同, 所以这两者之间只差「奖励在哪给」。

实测的方向是一致的: 奖励和优势给得越细, 同样采样量下的训练奖励越高, 到 0.9 用的轨迹越少 (1344 → 1184 → 1120 条)。代价也是实测到的: 逐步优势多了一项, 单条轨迹的梯度彼此更分散 (相对方差 13.4 → 33.5)。

第二个实测结论和「看策略熵就能发现崩塌」这个流行说法不一致: 把任务分布偏斜到 6/7 的答案都是 0、学习率调高 3 倍之后, 策略退化成一个不看用户回复的固定模板, 训练奖励 0.91 看着没问题, 均衡留出集只有 50%; 而它末步的策略熵 (0.386) 比学成协议那一组 (0.068) 还要高。查得出来的是输入依赖度: 贪心动作序列随 key 变化的比例从 100% 掉到 0%。

## 核心原理

### 环境: 4 轮, 模拟用户在循环里

用户先提一个缺少 key 的请求, agent 要走完这四步:

1. `ask`: 模拟用户回半个 key。
2. `ask`: 模拟用户回另外半个。
3. `lookup`: 工具按两半算出值 (两半之和的奇偶), 结果作为下一轮的状态。
4. `answer:v`: 答出看到的那个值。

只有这条路得 1 分。答案要对, 而且 `lookup` 必须发生在两次 `ask` 之后 (授权, 对应 m25 的授权门); `steal` 能直接看到值, 但轨迹判为未授权, 得 0 分。随机策略走通的概率不到 1%, 奖励确实稀疏。

SFT 只教两次 `ask` 的格式, `lookup` 与 `answer` 的协议留给 RL 发现。三种做法从同一份 SFT 权重出发。

### 三种优势

一组是同一个任务采的 8 条轨迹。记第 $i$ 条轨迹的回报为 $R_i$, 轨迹级优势是组内归一化:

$$A^E_i = \frac{R_i - \mathrm{mean}(R)}{\mathrm{std}(R) + \epsilon}$$

`traj` 把 $A^E_i$ 发给这条轨迹的每一个动作。

逐步优势先算每一步的折扣回报 $G_t = \sum_{k \ge t} \gamma^{k-t} r_k$ ($\gamma = 0.95$), 再按锚状态分组: 把 8 条轨迹里出现过的同一个状态 $s$ 归到一组, 组内比较从这个状态出发的折扣回报:

$$A_{i,t} = A^E_i + \omega \cdot \frac{G_{i,t} - \mathrm{mean}(G \mid s)}{\mathrm{std}(G \mid s) + \epsilon}$$

$\omega = 1$。前一项说这条轨迹整体好不好, 后一项说在同一个状态上这个动作比别人好不好。`step` 与 `turn` 的区别只在 $r_k$: `step` 只在结尾有 1 分, `turn` 把它拆成 0.2 / 0.2 / 0.2 / 0.4 当场发。

### 三个诊断量

- `credit_signal`: 在同一个状态上, 该做的那个动作拿到的平均优势减去其余动作的平均优势。它直接度量「功劳有没有落到该做的那一步上」, 越大越好。
- `grad_variance`: 每条轨迹各算一次梯度, 相对于批平均的方差除以批平均的模方。无量纲, 三种做法的优势都归一化过, 所以数量级可比。
- `input_dependence`: 贪心动作序列会不会随用户给的 key 变化。崩塌时它掉到 0, 而策略熵不一定掉。

## 运行

```bash
python -m llm_agent.m58_agentic_rl.demo
```

需要 torch, 不在默认 `run_all` 里; `run_all --with-training` 才会跑。单线程 CPU 约 33 s, 固定种子 11。

## 与真实系统的差距

- 动作只有 5 个 token, 状态是 2 个 token, 不是自然语言轨迹。真实的多轮 Agent RL 里一个动作是几十到几百个 token, 优势要分到 token 上, 还要处理把模拟用户与工具返回的 token 从 loss 里 mask 掉这类细节。
- 模拟用户是一条规则 (每轮回半个 key), 不是另一个 LLM。MUA-RL 训练时用 GPT-4o 当 user simulator, 评测时换成 GPT-4.1, 单条轨迹上限 30 轮; 这里演示的只是「模拟用户的回复进入轨迹、agent 必须读它」这个结构。
- 三个诊断量都是本模块定义的, 不是论文里的指标。信用信号依赖「已知最优动作」这张表, 真实任务上没有这张表; 梯度相对方差不是 token 级梯度方差的替代。
- 单种子 (11), 只有一个任务族。玩具规模上的差距大小不能外推: 这里三种做法最后都学到 100%, 区别只在到达得快慢。
- 崩塌是刻意用偏斜分布加 3 倍学习率诱发的, 不是自然发生的; 真实的推理崩塌涉及自然语言推理退化成固定模板, 本模块的动作空间里没有「推理」这一段。
- 方差筛选只筛掉了参与更新的组, 没有实现 StarPO-S 的另外两项 (去掉 KL 项、非对称 clipping), 也没有 PPO 的 critic 与 clip。
- 任务集是固定的 6 个实体加 4 种 key 组合, 不做在线合成。RODS 的做法是用已经算过的 rollout 识别能力边界, 再按边界难度合成新任务; 本模块只测到信号枯竭这个现象, 没有实现合成环。

## 常见误区

- **"策略熵不掉就说明没崩塌。"** [2] 里崩塌那一组末步的策略熵 (0.386) 比学成协议那一组 (0.068) 还高, 而它的贪心策略已经完全不看用户的回复了。熵度量的是同一个输入里的多样性, 查不出跨输入的退化, 要另看输入依赖度。
- **"逐步优势降低了梯度方差。"** 实测相反: 逐步优势把 $A^S$ 加在 $A^E$ 上, 单条轨迹的梯度相对方差从 13.4 升到 33.5。它换来的是功劳落得更准 (信用信号 0.57 → 1.61), 学得更快。
- **"按方差筛选 rollout 能省采样。"** 筛选省的是更新端: [3] 里每步仍然采 32 条轨迹, 只是用 1 组更新, 到 0.9 的轨迹数反而从 1184 升到 1632。它的收益在训练稳定性和单位更新的信息量上, 不在采样量。
- **"训练奖励涨到 1.0 就可以收工。"** 训练奖励只说明它在训练分布上成立。[2] 的训练奖励到过 1.00, 均衡留出集上只有 50%。

## 自测题

1. 一组 8 条轨迹里有 3 条成功。轨迹级优势和逐步优势分别怎么对待一条成功轨迹里那个纯属浪费的动作?

<details><summary>答案</summary>

轨迹级优势给这条轨迹的每个动作同一个正优势, 浪费的那一步也被加强。逐步优势按锚状态分组: 这个浪费的动作所在的状态上, 还有别的轨迹选了该做的动作, 它们从这个状态出发的折扣回报更高 (少绕一轮, 折扣少乘一次), 于是浪费的那个动作在组内拿到负的 $A^S$, 加上正的 $A^E$ 之后净优势被压下来。

</details>

2. 组内 8 条轨迹的奖励全是 0, 或者全是 1。这一组为什么给不出梯度, 在训练的哪两个阶段会大量出现?

<details><summary>答案</summary>

组内优势是按组内回报归一化算的: 回报全同时分子为 0, 这一组每个动作的优势都是 0, 乘上 log-prob 之后梯度也是 0。它在训练初期 (协议还没学会, 几乎全失败) 和后期 (任务已经学完, 几乎全成功) 都占多数, demo [3] 测到的是 47% / 6% / 70%。后期这一头就是静态任务集的信号枯竭: 继续采样也拿不到新的梯度, 要换成能力边界附近的新任务。

</details>

3. 训练奖励 0.91, 策略熵还有 0.386 没掉到 0, 看起来一切正常。还要看哪个量才能发现这个策略已经退化了?

<details><summary>答案</summary>

输入依赖度: 对同一个实体, 把用户给的 key 换成另外几种组合, 贪心动作序列会不会跟着变。demo [2] 里它是 0%, 说明策略对任何输入都走同一条路, 已经不读用户的回复了。训练奖励 0.91 是因为训练分布里 6/7 的任务答案恰好相同, 均衡留出集上它只有 50%。策略熵度量的是同一个输入内的多样性, 对这种跨输入的退化不敏感。

</details>
