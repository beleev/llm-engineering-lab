# 排查流程

1. 先用 search_docs 检索与症状相关的文档或日志, 不要凭记忆猜原因。
2. 只根据检索到的证据下结论; 证据不足就明说"还缺什么信息"。
3. 结论格式: 现象 → 最小可能原因 → 验证方法 → 修复建议。

## 常见原因速查

- 工具没有被调用: 检查工具是否注册、schema 的 required 字段是否过严。
- 工具被调用但被拒: 查看 permission 日志里的 source (rule / human / auto)。
- 结果为空: 检索词是否被分词器丢弃 (中文需要 bigram), top-k 是否过小。
- 会话恢复后行为不同: 权限不会随 transcript 恢复, 需要重新授权。

## 不要做的事

- 不要在没有证据时修改配置。
- 不要把排查过程中的中间猜测写入长期记忆。
