# 专业领域: 证据时效、地域与复核

## 直觉

领域工作流是医疗、法律、金融这类专业任务从找资料到给结论的整套流程: 找到资料, 核对它适不适用于这个地区和日期, 给出带引用的结论, 再交给专家复核。demo 用完全虚构的资料库测 3 个场景: 医疗和法律问 A 地区第 7 天, 金融问 C 地区第 7 天。只按领域取第一篇资料时, 医疗引了第 5 天就失效的 med-old, 法律引了 B 地区的 law-B, 金融拿 A 地区的资料答 C 地区的问题, 0 对。按地区和有效期过滤后医疗、法律各引到正确的那篇, C 地区没有金融资料就回答 "证据不足", 3/3; 专家复核状态来自场景里的 expert 标志, 模型自己写不出 "已复核"。专业任务的错误常常不是句子不通, 而是引错了版本、地域或人群。

## 核心原理

demo 用完全虚构的医疗、法律、金融资料, 测地域、日期、版本和证据过滤。每篇资料带领域、适用地区 region、生效日 start 和失效日 end, 比如 med-old 只在第 1 到 5 天有效, 第 6 天起由 med-new 接替。evidence 模式先按领域选出候选, 再只留下 region 和问题相同、问题日期落在 start 到 end 之间的资料; 筛完如果不是正好一篇 (一篇都没有或有好几篇), 就返回 "证据不足" 而不是硬判, 比如问医疗 A 地区第 11 天, 两篇医疗资料都已失效, 就返回证据不足。专家复核状态来自外部记录 (这里是场景给的 expert 标志): 模型输出的状态默认是 "待专家复核", 只有 reviewed 模式下场景给了 expert 标志才变成 "已复核", 模型不能自己宣称。

领域适配的三种手段作用不同。领域继续预训练 (拿领域文本接着做预训练) 补的是语言分布, 让模型熟悉这个领域的用词和文体; SFT (supervised fine-tuning, 用标注好的问答对做监督微调) 让模型适应这个领域的回答格式与任务; RAG (retrieval-augmented generation, 回答前先检索资料) 提供能随时更新的证据, 资料换了版本不用重新训练。独立测试要按机构、时间、文档族和人群拆分, 避免同源内容同时出现在训练和测试里; 还要留一组领域外的基准, 检查模型的通用能力有没有遗忘。

工作流验收不能只看准确率, 要逐项看引用是否正确、引用的资料是否适用于这个问题的范围、有没有关键遗漏、错误有多严重, 以及拿不准时有没有按升级流程交给人。高代价错误 (比如医疗场景引了过期的流程) 要单独计数, 不能和大量低风险的答案混在一起取平均。还要一起报告三个成本数字: 拒答覆盖了多少问题、专家复核要花多少工作量、平均每成功完成一个任务花多少钱。

敏感数据的保护分三个层次: 数据最小化 (只收集任务必需的数据)、访问隔离 (谁能看到哪些数据)、参数隐私 (训练进模型参数的内容会不会被套出来)。缓存和日志也会留下敏感内容, 一样要管。审查责任、当时引用的证据快照、发现错误后的撤回规则都要能追溯; 模型置信度再高, 也替代不了专家签字。

## 怎样验证

固定 3 个场景 (medical/A/7、legal/A/7、finance/C/7, 依次是领域、地区、日期) 和同一份资料库, 只换三种决策规则: naive 只按领域取第一篇, evidence 先按地区和有效期过滤, reviewed 在 evidence 的基础上接入外部的专家复核标志。比较三个读数: 引对资料或正确拒答的场景数、已复核数、证据不足数。全部术语与规则都是虚构夹具, 不提供专业结论; 真实上线要由领域专家制定标签与验收阈值。

## 与真实系统的差距

所有地区、日期和规则都是虚构夹具, 不提供医疗、法律或投资建议。没有实现真实的专家系统; 这里验证的是资料和工作流的边界。

## 常见误区与自测

答案有正确格式和引用, 就能通过专业任务验收吗?

<details><summary>展开解析</summary>

不能。一步步看: naive 模式的 3 条答案格式都对, 也都带着引用, 但医疗引的 med-old 第 5 天就失效了, 法律引的 law-B 适用于 B 地区而不是 A 地区, 金融拿 A 地区的资料答 C 地区的问题, 结果 0 对。引用存在只说明有出处, 不说明出处适用于这个问题。所以地域、日期、版本、人群和证据是否真的支持结论都要核对; 高风险结论还要走约定的复核流程。
