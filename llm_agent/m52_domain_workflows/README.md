# 专业领域: 证据时效、地域与复核

## 直觉

同样 3 个虚构场景, 只按领域取第一篇资料: 医疗引了过期的 med-old, 法律引了 B 地区的 law-B, 0 对。按地域和日期过滤后医疗、法律各对 1 条, C 地区没有金融资料就拒答, 3/3; 专家复核状态来自场景里的 expert 标志, 模型自己写不出 "已复核"。专业任务的错误常常不是句子不通, 而是引错了版本、地域或人群。

## 核心原理

demo 用完全虚构的医疗、法律、金融资料测地域、日期、版本和证据过滤: 候选资料按 region 和有效期筛完不唯一, 就返回 "证据不足" 而不是硬判。专家复核状态来自外部记录 (这里是场景给的 expert 标志), 模型不能自己宣称。

领域继续预训练补的是语言分布, SFT 适配格式与任务, RAG 提供可更新的证据, 三者作用不同。独立测试要按机构、时间、文档族和人群拆分, 并留一组域外基准检查遗忘。

工作流验收看引用是否正确、适用范围、关键遗漏、错误严重度和升级流程。高代价错误要单独计数; 拒答覆盖率、专家复核负担和每成功任务的成本一起报告。

数据最小化、访问隔离和参数隐私是三个层次; 缓存与日志也会泄漏敏感内容。审查责任、证据快照与撤回规则要能追溯, 模型置信度再高也替代不了专家签字。

## 运行

```bash
python -m llm_agent.m52_domain_workflows.demo
```

只用标准库, Python ≥ 3.10 即可; 不需要模型 API。网页在对应章节里回放同一实验的执行记录。

## 怎样验证

固定 3 个场景 (medical/A/7、legal/A/7、finance/C/7) 和同一份资料库, 只换 naive / evidence / reviewed 三种决策规则, 比较正确证据或拒答数、已复核数和证据不足数; 全部术语与规则都是虚构夹具, 不提供专业结论, 真实上线要由领域专家制定标签与验收阈值。

## 与真实系统的差距

所有地区、日期和规则都是虚构夹具, 不提供医疗、法律或投资建议。没有实现真实的专家系统; 这里验证的是资料和工作流的边界。

## 常见误区与自测

答案有正确格式和引用, 就能通过专业任务验收吗?

<details><summary>展开解析</summary>

不能。naive 模式 3 条答案都带引用, 却引了过期版本和错误地域, 0 对。地域、日期、版本、人群和证据支持关系都要核对, 高风险结论还要走约定的复核流程。
