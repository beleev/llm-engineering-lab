# 专业领域: 证据时效、地域与复核

## 直觉

专业领域工作流涵盖医疗、法律、金融等高合规场景从资料检索到结论签发的完整闭环:
1. 按业务主题检索候选规范文档。
2. 严格核验候选文档是否覆盖目标辖区并处于生效时效窗口之内。
3. 基于唯一适用的有效证据生成附带明确出处引用的结论, 证据缺失或冲突时主动拒答。
4. 移交外部领域专家完成人工复核签字。
本实验使用纯虚构规范库评测 3 个场景: 医疗与法律查询 A 地区第 7 天的适用规则, 金融查询 C 地区第 7 天的适用规则。仅按领域名称取首篇文档时, 3 个场景正确数为 0:
- 医疗场景错误引用了第 5 天即已失效的旧版文档 med-old。
- 法律场景错误引用了仅适用于 B 地区的跨区文档 law-B。
- 金融场景在 C 地区无对应规范的情况下强行套用 A 地区文档作答。
引入地域与生效期双重过滤后, 医疗与法律场景各自精准命中有效规范, 金融场景因无适用文档而如实返回「证据不足」, 实现 3/3 全部正确; 同时「已复核」状态完全由外部场景传入的 expert 标志受控写入, 模型自身无法伪造复核签章。高风险专业场景的典型事故往往并非语句不通顺, 而是张冠李戴地引用了错误版本、错误辖区或过期条款。

## 核心原理

本实验通过完全虚构的医疗、法律与金融规范夹具, 验证地域边界、生效时效、版本更替与确定性证据过滤逻辑。语料库中每篇文档均显式标注所属领域、适用地区 region、生效起始日 start 与失效截止日 end (例如医疗旧规 med-old 仅在第 1 至 5 天有效, 第 6 天起由新规 med-new 接替)。
evidence 模式按三步确定性规则筛选证据:
1. 首先匹配业务领域召回同领域候选文档。
2. 接着仅保留 region 与查询地区一致且查询日期落在 start 至 end 闭区间内的有效文档。
3. 若过滤后命中文档数并非严格等于 1 (即无任何适用文档或存在多篇未消歧文档), 系统立即终止结论生成并返回「证据不足」, 例如查询医疗 A 地区第 11 天时新旧两版规范均已过期, 系统即按规拒答。
在审批流控制上, 复核状态严格绑定外部工作流记录 (本例由场景元数据中的 expert 布尔标志模拟): 模型侧生成的默认状态恒为「待专家复核」, 仅当 reviewed 模式下外部显式传入 expert 确认标志且结论非拒答时状态才变更为「已复核」, 杜绝模型越权自封已审核结论。

面向垂直专业领域的继续预训练、SFT 与 RAG 三类适配技术各司其职, 解决的并非同一层能力短板:
- 领域继续预训练利用大规模无标注专业文献做自回归预训练, 用于对齐专业术语表征与行业行文分布。
- SFT 利用高质量领域指令与问答示范做监督微调, 用于规范输出结构、推理步骤与专业表达口吻。
- RAG 在推理阶段动态接入受控外部知识库, 用于提供可实时更新、可溯源核验的现行法规与临床指南证据, 文档版本更迭时无需重训模型参数。
领域评测集拆分必须同时按来源机构、发布时间、同源文档族及目标受众人群做严格正交隔离, 防止同源病例或合同模板跨训练测试集泄漏; 同时还须保留通用能力基准做回归测试, 监测领域微调是否引发通用推理与指令遵循能力的灾难性遗忘。

专业领域工作流的上线验收不能简化为单一总体准确率, 必须联合审计证据适用性、遗漏严重度、升级转交率与单位成功任务成本:
- 所附引用文档编号是否真实存在且内容准确。
- 所引条款的地域、时效与适用人群是否严格匹配当前查询范围。
- 回答是否遗漏了关键禁忌症、免责前提或法定例外条件。
- 错误结论在真实业务中造成的潜在危害等级。
- 面对证据缺失、版本冲突或超纲疑难情形时是否准确触发拒答并升级转交人工处理。
高代价致命错误 (如医疗场景引用已废止流程) 必须单独设立零容忍或极低上限红线, 绝不能与大批量低风险常规问答混算算术平均分。
同时还须并列披露三项运营成本指标:
- 触发「证据不足」拒答所覆盖的请求比例。
- 下游领域专家人工复核所需承接的审核工作量。
- 端到端平均每成功闭环交付一个合规任务的综合成本。

高敏专业场景的数据保护与合规审计需贯穿数据最小化、运行时访问隔离、参数记忆防护与全链路责任留痕。隐私与机密数据防护分为三个递进层次:
- 数据最小化: 仅采集与传入完成当前专业判断所必需的最少字段。
- 访问隔离: 基于租户与角色权限严格隔离不同机构、科室或案件的检索可见范围。
- 参数隐私: 防止微调语料中的个体病历或非公开案情被模型参数记忆并在后续查询中泄露。
推理中间缓存与运维调用日志同样会残留敏感原文, 必须纳入同等级别的脱敏与生命周期销毁管控。此外, 每笔业务输出都必须固化当时的审查责任人、所引文档的不可变版本快照以及事后发现法规勘误时的撤回重审机制; 模型输出的自评置信度再高, 也绝不能替代具备执业资质的专家复核签字。

## 怎样验证

实验固定同一组 3 个测试场景 (medical/A/7、legal/A/7、finance/C/7, 依次表示业务领域、目标地区与查询日期) 及同一份受控规范库, 仅切换三种工作流决策规则:
- naive 模式仅匹配业务领域并直接取首篇候选文档。
- evidence 模式在领域匹配后叠加地区一致性与生效起止日双重过滤, 并在非唯一命中时拒答。
- reviewed 模式在 evidence 基础上接入外部场景提供的专家复核确认标志。
验收横向对比三项统计读数:
- 准确命中有效规范或合理触发拒答的正确场景数。
- 获得外部确认的已复核条数。
- 因无适用规范而返回证据不足的条数。
实验边界在于所有规范条目、日期与辖区规则均为教学构造的纯虚构夹具, 不构成任何真实医疗、法律或金融专业意见; 生产级行业系统上线必须由持证领域专家制定标注规范、错误分级权重与准入阈值。

## 与真实系统的差距

所有地区、日期和规则都是虚构夹具, 不提供医疗、法律或投资建议。没有实现真实的专家系统; 这里验证的是资料和工作流的边界。

## 常见误区与自测

答案有正确格式和引用, 就能通过专业任务验收吗?

<details><summary>展开解析</summary>

不能。在本例的 naive 模式中, 系统输出的全部 3 条回答均具备规范的结构化格式并附带了真实存在的文档编号引用, 但业务验收正确数为 0:
- 医疗场景引用的 med-old 早在第 5 天即已过期失效。
- 法律场景引用的 law-B 仅适用于 B 地区, 不适用于所查询的 A 地区。
- 金融场景在 C 地区缺乏对应规范时错误套用了 A 地区的文档作答。
存在表面引用仅说明文本标明了某篇文档出处, 并不证明该出处在管辖范围与时效上适用于当前问题, 更不证明原文条款真正支持模型给出的结论。因此专业任务验收必须逐一核验地域、生效日期、版本号、适用人群及证据蕴含关系, 高风险结论还必须严格履行约定的外部专家复核流程。
