# RAG: 答案误差如何反传到检索器

## 直觉

RAG (retrieval-augmented generation, 检索增强生成) 先由检索器从文档库里挑文档, 再由生成器看着挑出的文档写答案。联合 RAG 训练要解决的问题是: 训练数据只标了答案对不对, 没人标注哪篇文档才是对的, 能不能拿答案的对错去教检索器挑文档。
demo 只有 3 篇文档, 只有第 2 篇支持正确答案:
- 检索器冻结 (不训练) 时, 它给第 2 篇的概率停在 0.1142, 概率最高的 top-1 是错的那篇, 答案边缘似然 (按检索概率加权后答对的总概率) 只有 0.2013。
- 让答案的损失反传到检索器训练 100 步, 第 2 篇的概率升到 0.9802。
- 检索器和生成器两侧一起训时检索也到 0.9771, 但生成器看着错文档时答对的概率从 0.1 涨到 0.2613, 这是它开始不看文档、直接背答案的苗头。

## 核心原理

答案的误差能传回检索器, 是因为答对的总概率里含有检索器给出的概率。这个总概率叫边缘似然, 写成 $p(a\mid q)=\sum_d p(d\mid q)\,p(a\mid q,d)$, 其中 q 是问题, a 是答案, d 是某一篇文档, $p(d\mid q)$ 是检索器选中 d 的概率, $p(a\mid q,d)$ 是生成器看着 d 答出 a 的概率。这个式子在说: 对每篇文档, 把「选中它的概率」乘上「看着它答对的概率」, 再把三篇加起来。demo 把 $-\log p(a\mid q)$ 当损失做梯度下降; 式子里的 $p(d\mid q)$ 是检索器的打分 (logits, softmax 之前的原始分数) 经过 softmax 得到的, 所以梯度会一路传到这些打分上, 把概率挪给能让答案答对的文档。
两种训练模式:
- joint 模式只更新检索器, 生成器在三篇文档下答对的概率固定为 0.1、0.95、0.2, 第 2 篇的检索概率从 0.1142 推到 0.9802。
- co-train 模式让检索器和生成器两组 logits 一起变。

损失下降不等于模型用上了证据。co-train 把边缘似然做到 0.9659, 比 joint 的 0.9339 还高, 单看损失它更好。但它的生成器在两篇错文档 (第 1、3 篇) 下答对的概率, 从 0.1、0.2 涨到了 0.2613、0.2351。
原因是损失只看答对的总概率:
- 检索器把概率挪到对的文档上, 总概率会变大。
- 生成器看着错文档也答对, 总概率同样会变大。
梯度不区分这两条路。沿第二条路学下去, 生成器学到的是不看文档也能答对, 等于把答案背了下来。
所以评测要分开测三件事:
- 召回: 检索有没有找到对的文档。
- 生成: 答案对不对。
- 引用支持: 答案是不是真由引用的文档支持。
还要加三种对照, 看答案会不会跟着变:
- 把证据换成别的文档。
- 完全不给证据。
- 给一篇内容与事实相反的文档 (反事实文档)。

查询改写是在检索之前先把用户的问题改写成更容易搜到的说法, 改写时实体、版本、否定和权限范围一个都不能丢。demo 的查询是 "Comet v2 不要 邮件", 别名表 (同一个东西不同名字的对照表) 只把 Comet 换成 Atlas, 得到 "Atlas v2 不要 邮件"; 版本 "v2" 和否定词 "不要" 原样留下, 所以读数「保留否定」是 true。
改写如果丢词:
- 丢了 "不要", 搜到的就是意思相反的文档。
- 丢了 "v2", 可能搜到别的版本。
执行记录里也提醒: 别名表要写明作用域和版本, 不能看到同名的词就无条件替换。
通用的生成式改写 (让模型自由重写整句) 要拿改写前后的检索结果和最终答案一起验收, 不能只看改写后的句子通不通顺。

真实系统的检索是一道离散的门: 检索器只把得分最高的 k 篇 (top-k) 交给生成器, 没进前 k 的文档不参与后面的计算。demo 只有三篇文档, 对三篇全部精确求和, 所以每一篇都拿得到梯度。真实系统里, 没被召回的文档不在求和式里, 拿不到任何梯度, 检索器也就没机会知道它其实是对的; 后面再怎么重排 (rerank, 对已召回的候选重新排序) 也救不回来。
所以下面这些是联合训练之外的另一层工程:
- 定期更新索引。
- 挖困难负样本 (看起来很相关、其实不支持答案的文档) 来训练检索器。
- 保证正确文档能进入候选。

## 怎样验证

固定三篇文档、一个答案和训练设置 (100 步梯度下降), 比较 frozen (不训练)、joint (只训检索器)、co-train (两边一起训) 三种模式实际更新了哪组参数; rewrite 模式在 joint 的基础上再检查查询改写。
判定看三个读数:
- 正确文档的概率。
- top-1 是否命中正确文档。
- 生成器在每篇文档下答对的条件概率。
最后一个读数用来发现生成器是不是在背答案。模式名字叫 "joint" 不能当作检索器拿到了梯度的证据, 要看读数有没有变。

## 与真实系统的差距

三篇文档、一个答案的可微机制实验, 不是通用 RAG 模型, 也不做端到端的自然语言生成。固定 generator 的对照用来识别答案记忆捷径。

## 常见误区与自测

共同训练后答案 loss 下降, 检索一定更好吗?

<details><summary>展开解析</summary>

不一定。共同训练时, 答案的损失同时传给检索器和生成器, 损失下降有两条路:
- 检索器把概率挪到对的文档上。
- 生成器不看文档也学会答对。
demo 里 co-train 的边缘似然 0.9659 比 joint 的 0.9339 还高, 可生成器看着错文档时答对的概率也从 0.1 涨到 0.2613, 说明有一部分下降来自背答案。所以损失下降之后, 还要单独测检索命中 (正确文档有没有排第一) 和证据依赖 (换掉证据后答案会不会变), 才能说检索变好了。

</details>
