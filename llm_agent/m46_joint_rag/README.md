# RAG: 答案误差如何反传到检索器

## 直觉

RAG 先由检索器从语料库中筛选候选文档, 再由生成器依据候选文档生成回答。联合 RAG 训练旨在解决的核心问题是: 当监督数据仅标注最终答案正误而未标注支撑文档时, 能否利用答案误差反向指导检索器优化文档排序。
本实验设置 3 篇候选文档, 其中仅有第 2 篇包含支持正确答案的证据:
- 冻结检索器参数时, 第 2 篇文档的检索概率停留在 0.1142, 得分最高的 top-1 为错误文档, 答案边缘似然 (按文档检索概率加权求和后的总答对概率) 仅为 0.2013。
- 将答案损失反向传播至检索器训练 100 步后, 第 2 篇文档的检索概率升至 0.9802。
- 检索器与生成器双侧共同训练时, 第 2 篇文档检索概率同样升至 0.9771, 但生成器在错误文档条件下的答对概率从 0.1 升至 0.2613, 暴露出绕过外部证据直接记忆答案的倾向。

## 核心原理

答案监督误差能够反向传播至检索器, 源于边缘似然目标将检索器的文档分布显式纳入可微求和路径。答案边缘似然定义为 $p(a\mid q)=\sum_d p(d\mid q)\,p(a\mid q,d)$, 其中 $q$ 为查询问题, $a$ 为目标答案, $d$ 为候选文档, $p(d\mid q)$ 为检索器选中文档 $d$ 的概率, $p(a\mid q,d)$ 为生成器在给定文档 $d$ 时输出答案 $a$ 的条件概率; 该目标对全部 3 篇文档的「选中概率与条件答对概率之积」求和。实验以负对数边缘似然 $-\log p(a\mid q)$ 为损失执行梯度下降; 由于 $p(d\mid q)$ 由检索器原始打分 logits 经 softmax 归一化得到, 损失梯度可直接反传至检索器 logits, 将概率质量推向能够高概率支撑正确答案的文档。
实验对比了两种参数更新范围:
- joint 模式仅更新检索器 logits, 将生成器在 3 篇文档下的条件答对概率固定为 0.1、0.95、0.2, 使第 2 篇正确文档的检索概率从 0.1142 提升至 0.9802。
- co-train 模式同时放开检索器与生成器两组 logits 联合更新。

边缘似然损失下降并不等价于模型学会了忠实依赖外部证据。实验里 co-train 模式将答案边缘似然推高至 0.9659, 高于 joint 模式的 0.9339, 仅看训练损失似乎更优; 但其生成器在两篇错误文档 (第 1 篇与第 3 篇) 条件下的答对概率也分别从 0.1、0.2 上升至 0.2613、0.2351。
根源在于总边缘似然损失对两条优化捷径不加区分:
- 检索器将概率集中到正确支撑文档上, 可提高总答对概率。
- 生成器在给定无关或错误文档时依然强行输出正确答案, 同样能提高总答对概率。
梯度下降同时沿两条路径更新参数, 第二条路径实质上驱使生成器将答案硬编码进自身参数而无视检索上下文。
因此 RAG 系统验收必须将三项指标拆开独立评测:
- 检索召回率: 检索器是否准确召回黄金支撑文档。
- 端到端生成准确率: 最终输出答案是否正确。
- 引用忠实度: 生成结论是否真正由所引文档支撑。
此外还需引入三组干预对照检验答案的证据敏感性:
- 将上下文替换为无关文档。
- 完全移除检索证据。
- 注入与事实相反的反事实文档, 观察模型输出是否随证据同步改变。

检索前查询改写必须完整保留原始问题中的核心实体、版本号、否定极性与权限边界, 任一约束丢失都会扭曲检索意图。查询改写旨在将用户的口语或别名表述规范化为索引易匹配的形式; 本例原始查询为「Comet v2 不要 邮件」, 受控别名表仅将实体别名 Comet 映射为标准名 Atlas, 生成「Atlas v2 不要 邮件」, 版本标识「v2」与否定词「不要」均原样保留, 因此「保留否定」核验项读数为 true。
一旦改写过程丢失关键限定词, 将直接引发严重检索偏差:
- 丢失否定词「不要」会召回语义完全相反的文档。
- 丢失版本号「v2」则会混入过期或其他版本的冲突规范。
实验记录同时指出, 生产环境的别名映射表必须明确限定业务作用域与适用版本, 不能见同名字符串就做全局无条件替换; 若采用通用生成式重写模型自由改写整句, 必须联合验收改写前后的检索召回率与端到端答案准确率, 不能仅凭改写语句通顺放行。

大规模检索系统中的 top-k 截断是一道离散门控, 未进入前 k 名的候选文档无法从联合损失中获得任何梯度信号。本例玩具语料库仅有 3 篇文档, 边缘似然对全部 3 篇文档做精确遍历求和, 因此每篇文档都能分到反传梯度。而在百万级文档的真实系统中, 生成器仅接收检索得分排在前 k 位的子集, 落在 top-k 之外的正确文档根本未进入前向求和图, 梯度恒为零, 检索器无从得知该文档能够支撑正确答案, 后续重排器 (rerank) 也无法挽回首轮漏召回的文档。
因此在端到端可微联合训练之外, 工程上仍必须配套独立的基础检索建设:
- 在检索器向量表示更新后定期异步重建文档索引。
- 持续挖掘语义相近但并不支撑答案的困难负样本以提升初筛区分度。
- 通过多路召回保障黄金文档能够稳定进入 top-k 候选池。

## 怎样验证

实验固定同一组 3 篇候选文档、单一目标答案及 100 步梯度下降超参数, 横向对比 frozen (冻结全部参数)、joint (仅更新检索器)、co-train (检索器与生成器同步更新) 三种模式下各参数组的实际变化, rewrite 模式则在 joint 基础上叠加查询改写约束核验。
验收综合核查三项读数:
- 正确支撑文档的检索概率。
- 检索 top-1 是否命中正确文档。
- 生成器在每篇候选文档下的条件答对概率。
其中条件答对概率专门用于监测生成器是否出现脱离证据的参数记忆; 代码配置命名为「joint」本身不构成联合反传生效的证据, 必须以检索器概率读数的实质提升为准。

## 与真实系统的差距

三篇文档、一个答案的可微机制实验, 不是通用 RAG 模型, 也不做端到端的自然语言生成。固定 generator 的对照用来识别答案记忆捷径。

## 常见误区与自测

共同训练后答案 loss 下降, 检索一定更好吗?

<details><summary>展开解析</summary>

不一定。检索器与生成器共同训练时, 边缘似然损失梯度会同时流向两侧参数, 总损失下降存在两条竞争路径:
- 检索器将概率分布集中至正确支撑文档。
- 生成器绕过输入上下文直接将目标答案编码进自身参数。
本例中 co-train 模式的边缘似然达到 0.9659, 高于 joint 模式的 0.9339, 但生成器在错误文档条件下的答对概率也从初始的 0.1 上升至 0.2613, 表明一部分损失下降来自生成器的无证据硬记。因此观察到总 loss 下降后, 仍必须独立评测检索召回命中率 (如 top-1 是否命中正确文档) 与反事实证据依赖度 (替换或移除文档后答案是否随之改变), 才能确认检索质量真正得到改善。

</details>
