# RAG: 答案误差如何反传到检索器

## 直觉

检索器冻结时, 正确文档概率停在 0.1142, 答案边缘似然 0.2013, top-1 是错的那篇。让答案损失反传到检索 logits, 100 步后正确文档概率 0.9802; 两侧一起训时检索也到 0.9771, 但生成器在错文档下答对的概率从 0.1 涨到 0.2613, 这就是背答案的苗头。

## 核心原理

边缘似然 p(a|q)=Σ_d p(d|q) p(a|q,d)。demo 对 -log p(a|q) 反传, 检索 logits 拿到来自答案对错的梯度: joint 模式只更新检索器, 把正确文档概率从 0.1142 推到 0.9802; co-train 模式让检索和生成器两组 logits 一起变。

损失下降不等于用上了证据。co-train 把边缘似然做到 0.9659, 比 joint 的 0.9339 还高, 但生成器在两篇错文档下答对的概率从 0.1、0.2 涨到 0.2613、0.2351, 它在学着不看文档也答对。要分开测召回、生成和引用支持, 还要加证据替换、无证据和反事实文档对照。

查询改写要保住实体、版本、否定和权限范围。demo 的别名表只把 Comet 换成 Atlas, "v2" 和 "不要" 原样留下 (保留否定 = true); 通用的生成式改写要用改写前后的检索结果和最终答案一起验收, 不能只比句子通不通。

真实 top-k 检索是离散的候选门, demo 对三篇文档精确求和, 所以每篇都有梯度。没被召回的文档拿不到梯度; 更新索引、挖困难负样本、保证候选覆盖是另一层工程。

## 怎样验证

固定三篇文档和一个答案, 比较 frozen / joint / co-train 三种模式实际更新了哪组参数, 看正确文档概率、top-1 和生成器条件概率三个读数, 不拿 "joint" 这个名字当梯度证据。

## 与真实系统的差距

三篇文档、一个答案的可微机制实验, 不是通用 RAG 模型, 也不做端到端的自然语言生成。固定 generator 的对照用来识别答案记忆捷径。

## 常见误区与自测

共同训练后答案 loss 下降, 检索一定更好吗?

<details><summary>展开解析</summary>

不一定。可微目标让检索拿到梯度, 也让生成器能把答案背下来: demo 里 co-train 的边缘似然 0.9659 高于 joint 的 0.9339, 但错文档下的答案概率也涨到 0.2613。要单独测检索命中和证据依赖。
