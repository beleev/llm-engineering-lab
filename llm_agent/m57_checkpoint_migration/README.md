# 任务恢复: 旧检查点遇到新代码

流程型 agent 任务在「等待审批」节点暂停并将状态持久化为磁盘检查点 (checkpoint), 代码升级后由 v2 执行器读取该检查点恢复运行。实验覆盖三类情形:
- 兼容迁移:
  1. 迁移函数为新增可选字段补齐默认值。
  2. 将状态格式版本升级为 2。
  3. 继续执行后续节点, 向外部账本提交 1 笔 10 元记录。
- 四种不兼容情形: 已保存节点在新版代码中被移除、缺失必填字段、工具约定发生变更、恢复时权限已被撤销。这四种情形均在触发外部提交前被拦截拒绝, 外部提交笔数为 0。
- 外部提交后强退: 子进程在外部账本完成记账、本地检查点尚未写入时以退出码 17 终止; 重启恢复时先按稳定操作键查得已有收据并跳过重复提交, 外部账本仍保持 1 笔提交、合计金额 10。

旧状态能够成功反序列化, 并不意味着旧任务能够安全继续执行。

## 怎么跑

```bash
python -m llm_agent.m57_checkpoint_migration.demo
```

只用标准库: 临时目录里一个 state.json 检查点, 一个 SQLite 外部账本。「外部提交后强退」会真的起一个子进程, 并让它 os._exit(17)。

## 先看这几件事

- schema_version (状态格式版本) 决定持久状态的解析与迁移方式。迁移函数在读取检查点时逐项执行校验:
  - 格式版本是否受支持 (1 或 2)。
  - 已保存节点是否仍然存在 (须为 await_approval、submit、done 之一)。
  - 金额字段 amount 是否为正整数。
  - 工具版本与操作键是否符合原有约定 (tool_version 为 1、operation 为 invoice-1)。

  新增可选字段可通过补齐默认值完成兼容迁移, 本例中为 summary 补齐空字符串; 若遇到缺失必填字段、未知节点或不兼容的工具约定则直接报错终止。上述校验全部在产生外部副作用之前完成, 因此所有被拒绝情形的外部提交笔数均为 0。
- flow_version (业务流程版本) 决定任务恢复后遵循哪套业务规则。v2 代码新增了「金额超过 20 则拒绝」的规则, 但仅对 flow_version 为 2 的任务生效; v1 任务仍按创建时的规则继续执行, 不会被新版代码静默改写原有业务语义, 因此仅「新业务版本」对照组的「执行新业务规则」读数为是。权限校验则是另一道独立门禁: 任务恢复时必须重新校验授权状态, 已撤销的权限不得从旧检查点直接继承。本例中「权限已撤销」对照组的状态格式合法且通过了版本迁移, 但因重新授权失败而同样被拒绝恢复。
- 外部服务提交与本地检查点写入属于两个独立操作, 进程随时可能在两者之间异常终止。本实验在两步之间调用 os._exit (退出码 17) 强制终止子进程: 此时外部账本已记录 1 笔 10 元入账, 而本地检查点仍停留在等待审批状态。重启恢复时, 执行器先持稳定操作键 invoice-1 向外部账本查询收据:
  - 若查得已有收据且金额一致, 则跳过外部提交, 直接将本地检查点补齐为完成状态。
  - 若收据金额与本地记录不一致则立即报错拒绝, 避免掩盖状态分歧。

  若每次重试都生成新的操作键, 或未先核对收据便直接发起提交, 重启恢复就会导致重复入账。

## 怎样验证

固定一份暂停于等待审批节点、金额为 10 的 v1 任务, 交由 v2 执行器恢复执行, 对比七种测试条件: 兼容迁移、新业务版本、节点已移除、缺必填字段、工具约定变更、权限已撤销、外部提交后强退。评估指标包含三项:
- 执行器是否拒绝恢复。
- 外部账本记录的提交笔数与合计金额。
- 外部提交后强退并再次恢复后, 外部副作用是否仍严格保持为单笔。

7 张表的「外部提交笔数」要么 1 要么 0, 没有 2。

### 外部提交后强退

| 指标 | 实际结果 |
| --- | --- |
| 拒绝恢复 | false |
| 外部提交笔数 | 1 |
| 外部合计 | 10 |
| 查询已有收据 | true |
| 执行新业务规则 | false |
| 状态格式版本 | 2 |
| 故障子进程退出码 | 17 |

子进程先往账本写了 1 笔 10 元, 还没写本地检查点就 os._exit(17); 磁盘上 node 仍是 await_approval。父进程重新恢复: 按 invoice-1 查到收据 (查询已有收据 = true), 金额对得上, 跳过提交, 直接把本地状态补到 done。账本最终 1 笔, 合计 10。

实验用真实文件、SQLite 和进程强退, 但不恢复任意 Python 栈, 不实现分布式租约, 也不做任意 schema 的自动迁移。原子重命名没有对目录 fsync, 不承诺断电持久性。
