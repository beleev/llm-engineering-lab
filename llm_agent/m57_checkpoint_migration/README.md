# 任务恢复: 旧检查点遇到新代码

一个在审批节点暂停的 v1 任务交给 v2 执行器: 兼容的迁移补上默认值、把状态格式升到 2; 节点被移除、缺必填字段、工具约定变了、权限被撤销四种情形全部在副作用前拒绝, 外部提交 0 笔。外部服务入账后子进程以退出码 17 强退, 重启先查到收据再继续, 外部仍只有 1 笔、合计 10。能读回旧状态不等于能继续旧任务。

## 怎么跑

```bash
python -m llm_agent.m57_checkpoint_migration.demo
```

只用标准库: 临时目录里一个 state.json 检查点, 一个 SQLite 外部账本。「外部提交后强退」会真的起一个子进程, 并让它 os._exit(17)。

## 先看这几件事

- schema_version 决定怎么读持久状态: 新增的可选字段补默认值 (本例 summary), 缺必填字段、未知节点和不兼容的工具约定都在副作用之前拒绝, 这几种拒绝的外部提交笔数都是 0。
- flow_version 决定业务规则: v2 代码不能静默改写 v1 任务当初的承诺, 也不能让旧任务继承已经撤销的权限。格式兼容性和执行授权是两道分开的检查, 本例权限撤销后即使格式合法也拒绝恢复。
- 外部服务提交和本地检查点是两个事务: 实验在两者之间真正退出子进程 (退出码 17); 重启后用稳定操作键 invoice-1 核对参数, 查到已有收据就直接完成本地状态, 不重复入账, 外部合计仍是 10。

## 怎样验证

固定一份暂停在审批节点的 v1 任务, 交给 v2 执行器, 比较兼容迁移、新业务版本、节点已移除、缺必填字段、工具约定变更、权限已撤销、外部提交后强退七种情形; 判定看是否拒绝恢复、外部提交笔数和合计, 以及强退恢复后是否只有一笔副作用。 7 张表的「外部提交笔数」要么 1 要么 0, 没有 2。

### 外部提交后强退

| 指标 | 实际结果 |
| --- | --- |
| 拒绝恢复 | false |
| 外部提交笔数 | 1 |
| 外部合计 | 10 |
| 查询已有收据 | true |
| 执行新业务规则 | false |
| 状态格式版本 | 2 |
| 故障子进程退出码 | 17 |

子进程先往账本写了 1 笔 10 元, 还没写本地检查点就 os._exit(17); 磁盘上 node 仍是 await_approval。父进程重新恢复: 按 invoice-1 查到收据 (查询已有收据 = true), 金额对得上, 跳过提交, 直接把本地状态补到 done。账本最终 1 笔, 合计 10。

实验用真实文件、SQLite 和进程强退, 但不恢复任意 Python 栈, 不实现分布式租约, 也不做任意 schema 的自动迁移。原子重命名没有对目录 fsync, 不承诺断电持久性。
