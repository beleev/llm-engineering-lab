# 有效上下文: 看得到, 不等于用得上

## 直觉

上下文利用说的是: 信息放进了上下文窗口 (模型一次能读入的那段 token), 模型回答时能不能把它用上。demo 用一个规则写明的 softmax 读出器代替模型: 证据所在的位置得 4 分, 其余干扰位置得 0 分, softmax 把分数换成权重, 证据分到的权重之和叫证据质量, 超过 0.5 才算够用。证据放在 64 个 token 的开头、中间、末尾时:
- 带首尾偏好 (开头和结尾额外加分) 的读出器给出 0.8132、0.0286、0.8132。
- 去掉偏好后三处都是 0.4643, 因为 63 个干扰位置把权重分走了一大半。
- 先检索出分数最高的 4 个位置 (top-4) 再读, 三处都到 0.9479, 在全部 18 组组合 (3 种证据位置、3 种窗口长度、单证据或两证据) 里都够用。
窗口装得下、证据被召回、多条证据被一起用上, 是三件要分开测的事。

## 核心原理

这组实验固定问题和答案, 只改三样东西: 证据放在哪、窗口多长、要几条证据。
取值分别是:
- 证据位置取开头、中间、末尾。
- 窗口长度取 16、64、256 个 token。
- 证据数量取单证据和两证据 (两跳题, 答案要同时用到两条证据)。
三种位置、三种长度、两种证据数全部组合, 一共 18 组。
「够用」有两个条件:
- 读出器分给证据的权重之和大于 0.5。
- 多跳题需要的每一条证据都在读出器读的候选里。
对真实模型做同类测试时, 要比较答案对不对、引用的证据对不对、每一跳是否都有证据支持; 不能只在长文里藏一句话 (needle, 「大海捞针」测试里的那根针), 看模型能不能把它找出来就算完。

三种模式的差别全在打分和候选上:
- biased (首尾偏好) 按离两端的远近给每个位置加分, 最两端加满 5 分, 正中间几乎不加, 用来模仿真实模型更容易看开头和结尾的倾向; 证据放在 64 个 token 正中时只剩 0.0286, 因为靠近两端的干扰位置加分后比证据得分还高, 18 组里 15 组够用, 不够用的 3 组都是单条证据放在中间。
- position-neutral (位置中性) 去掉偏好, 证据 4 分、干扰 0 分, 64 个 token 时证据的权重是 $e^4/(e^4+63)$, 这个式子在说: 证据占 $e^4$ 约 54.6 份, 63 个干扰各占 1 份, 证据拿不到一半, 头、中、尾都是 0.4643; 从 64 个 token 起单条证据就被干扰稀释到 0.5 以下, 18 组里只剩 9 组够用。
- retrieve (检索后阅读) 先按分数挑出最高的 4 个位置 (top-4), 只在这 4 个里做 softmax, 证据的对手从 63 个降到 3 个, 所以到 0.9479。它只在打分能认出证据时才有帮助: demo 里证据 4 分、干扰 0 分, 分数已经把证据挑了出来, 真实检索器打错了分就帮不上忙。

窗口不够用时, 常见的两种补法是递归记忆和分层注意力:
- 递归记忆把读过的旧内容块压缩成一个固定大小的状态, 带着它往后读。
- 分层注意力先挑出相关的块, 再进块里细读。
两者都在前后两段之间多开了一条通道, 但都会失败: 压缩会丢细节, 路由 (决定读哪一块) 选错了块也照样答错。foundation/hierarchical_memory 用数组级对照演示了这一点: 每块只留一个均值的块均值记忆, 在 24 个细节查询上命中 0; 它还特意把一块设成另一块的倒序, 两块均值相同、细节却不同, 说明压缩之后回不到原样。

## 怎样验证

固定题目、答案和 18 组位置、长度、证据数的组合, 只切换读出器的三种模式, 比较两个读数:
- 18 组里够用的比例 (证据充分比例)。
- 64 个 token 时证据放在开头、中间、末尾各拿到多少质量。
这是一个规则写明的机制模型, 不是在某个真实 LLM 上测出的 Lost in the Middle 曲线 (一篇 2023 年的论文, 报告模型对放在长上下文中间的信息利用得最差); 真实评测还要控制输出预算 (允许输出多少 token) 和检索器本身的变化。

## 与真实系统的差距

这是带公开位置偏好的 softmax 阅读器, 不是实测 LLM 的 Lost in the Middle 曲线。本例的阈值和窗口长度不能外推成任何模型的有效上下文。

## 常见误区与自测

上下文窗口变大, 可以直接认为有效知识范围变大吗?

<details><summary>展开解析</summary>

不可以。下面三件事不等价:
- 窗口变大只说明模型能接收更多 token。
- 证据在不在窗口里, 是可达的问题。
- 读答案时证据有没有分到足够的注意力, 是用得上的问题。
demo 的位置中性读出器里, 证据 4 分、每个干扰 0 分, 窗口从 16 拉到 256 个 token, 干扰越来越多, 证据分到的权重就越来越少: 16 个 token 时单条证据还够用, 64 个 token 时只剩 0.4643, 已经跌破 0.5。所以要判断有效知识范围, 得移动证据的位置、增加干扰, 再测多条证据能不能组合起来用。
