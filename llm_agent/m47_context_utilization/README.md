# 有效上下文: 看得到, 不等于用得上

## 直觉

同一个读出器, 证据放在 64 个 token 的开头、中间、末尾, 带首尾偏好时拿到的质量是 0.8132、0.0286、0.8132; 去掉偏好三处都是 0.4643, 仍被 63 个干扰稀释到 0.5 以下。先检索出 top-4 再读, 三处都到 0.9479, 18 组组合全部够用。能装下、能召回、能组合是三件事。

## 核心原理

固定问题和答案, 把证据移到头/中/尾, 再交叉 16/64/256 三种长度和单证据/两证据, 一共 18 组; "够用" 的判定是证据拿到的读出质量 > 0.5 且多跳证据都在候选里。对真实模型要比较答案、证据引用和逐跳支持, 不能只测一根 needle。

biased 模式给首尾位置加 5 分偏好, 证据在中间只剩 0.0286, 18 组里 15 组够用; position-neutral 去掉偏好后头中尾一样是 0.4643, 但从 64 个 token 起单证据就被干扰稀释到 0.5 以下, 只剩 9 组够用。retrieve 先按评分取 top-4 再归一化, 只在评分能认出证据时才有帮助。

递归记忆把旧块压成一个状态, 分层注意力先找块再读块; 两者都增加跨段通道, 但压缩丢细节、路由选错块照样失败。foundation/hierarchical_memory 用数组级对照演示这一点: 块均值记忆在 24 个细节查询上命中 0。

## 怎样验证

固定题目、答案和 18 组位置×长度×证据组合, 只切换读出器模式, 比较证据充分比例和 64 位置的三处证据质量; 这是显式机制模型, 不是某个 LLM 的 Lost in the Middle 实测, 真实评测还要控制输出预算和检索器变化。

## 与真实系统的差距

这是带公开位置偏好的 softmax 阅读器, 不是实测 LLM 的 Lost in the Middle 曲线。本例的阈值和窗口长度不能外推成任何模型的有效上下文。

## 常见误区与自测

上下文窗口变大, 可以直接认为有效知识范围变大吗?

<details><summary>展开解析</summary>

不可以。能接收、可达、用得上不等价: demo 里窗口从 16 拉到 256, 位置中性读出器的证据质量一路被干扰稀释, 64 时只剩 0.4643。要移动证据位置、增加干扰, 再测多证据组合。

</details>
