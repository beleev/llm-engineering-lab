# 有效上下文: 看得到, 不等于用得上

## 直觉

有效上下文利用关注的核心问题是: 关键信息虽然已经放入上下文窗口, 模型在生成答案时能否真正为其分配足够的注意力权重。实验使用显式规则定义的 softmax 读出器模拟这一竞争机制: 证据所在位置基础得分为 4 分, 其余干扰位置得分为 0 分, 经 softmax 归一化后证据位置获得的权重总和记为证据质量, 超过 0.5 方视为充分可用。
当单条证据分别置于 64 个 token 窗口的开头、中间与末尾时, 三种读出模式呈现鲜明对比:
- 带首尾位置偏好 (两端位置额外加分) 的读出器在开头、中间、末尾依次给出 0.8132、0.0286、0.8132, 中间位置严重失焦。
- 去除位置偏好的中性读出器在三处均给出 0.4643, 因为其余 63 个干扰位置分走了超过一半的归一化权重。
- 先筛选得分最高的 4 个位置 (top-4) 再做局部读出时, 三处证据质量均达 0.9479, 在全部 18 组受控组合 (3 种证据位置、3 种窗口长度与单证据或双证据两跳设置) 中全部达标。
窗口物理容量装得下、单条证据被成功定位、多跳证据被同时组合利用, 是长上下文评测中必须分开核验的三件事。

## 核心原理

本实验固定查询问题与目标答案不变, 通过正交改变证据位置、窗口长度与所需证据条数构造 18 组受控压力测试:
- 证据位置分别取窗口开头、正中与末尾 3 种分布。
- 上下文窗口长度分别取 16、64、256 个 token 3 个档位。
- 证据数量分别取单条证据与两条证据 (需要同时结合两处信息求解的两跳推理题)。
判定当前配置「充分可用」需同时满足两项条件:
- 读出器分配给全部证据位置的归一化权重之和严格大于 0.5。
- 多跳题所需的每一条支撑证据均进入了读出器的实际候选集合。
将这一评测框架迁移至真实大模型时, 必须同步核验最终答案正误、引用证据准确性以及多跳推理每一跳的证据覆盖度, 不能仅凭在长文本中检索单句孤立事实的「大海捞针」 (needle-in-a-haystack) 测试通过就断言长上下文有效。

三种读出模式的表现差异完全由位置打分偏置与 softmax 归一化候选范围决定:
- biased (首尾偏好) 模式按距窗口两端的距离附加位置偏置, 两端最高额外加 5 分而正中几乎不加分, 用以复现真实模型偏重首尾上下文的现象; 在 64 个 token 窗口中将单条证据置于正中时, 两端干扰项加分后反超证据得分, 导致证据权重跌至 0.0286, 18 组测试中 15 组达标, 未达标的 3 组均为单条证据落在窗口正中。
- position-neutral (位置中性) 模式移除位置偏置, 证据恒得 4 分、干扰恒得 0 分; 窗口长度为 64 个 token 时单条证据权重为 $e^4/(e^4+63)$, 即证据项权重 $e^4$ (约为 54.6) 需与 63 个各占 1 份权重的干扰项共同归一化, 因而在开头、正中、末尾三处均被稀释至 0.4643, 从 64 个 token 起单条证据均跌破 0.5 阈值, 18 组中仅 9 组达标。
- retrieve (检索后阅读) 模式先按打分截取 top-4 候选位置再执行局部 softmax, 参与分母竞争的干扰项从 63 个锐减至 3 个, 证据权重随之升至 0.9479。该收益的前提是初筛打分能够准确区分证据与噪声: 本例设定证据 4 分、干扰 0 分从而保证了准确召回, 若真实检索器打分失准则同样会漏掉关键证据。

超出有效窗口容量时常用的递归状态压缩与分层路由注意力均存在固有的信息损耗边界:
- 递归记忆将已读历史文本块逐步压缩为固定维度的摘要状态向后传递。
- 分层注意力先由粗粒度路由筛选相关文本块, 再在选中块内执行细粒度 token 级注意力。
两类机制虽都在远距离上下文之间建立了跨块通道, 但各自面临明确的失效模式: 定长状态压缩不可避免地丢弃细粒度数值与顺序特征, 而粗粒度路由一旦选错目标块便无法挽回遗漏证据。仓库中的 foundation/hierarchical_memory 模块以数组级对照实验验证了这一边界: 仅保留块均值的压缩记忆在 24 个细粒度位置查询上命中数为 0; 实验还将其中一个数据块构造为另一块的严格逆序, 两块均值完全相等而局部序列截然相反, 直接表明定长均值摘要无法逆向还原原始细节。

## 怎样验证

实验固定同一查询、目标答案及 18 组位置、窗口长度与证据条数的笛卡尔积组合, 仅切换读出器的三种工作模式, 对比两项核心读数:
- 18 组测试中满足证据充分条件的达标比例。
- 64 个 token 窗口下证据分别置于开头、正中、末尾三处时的读出权重。
实验边界在于本例是一个规则透明的解析机制模型, 并非在真实预训练 LLM 上实测得到的 Lost in the Middle 经验曲线 (2023 年提出的长上下文中间位置性能退化现象); 真实模型长上下文评测还必须严格对齐最大输出 token 预算并控制外部检索器自身的召回波动。

## 与真实系统的差距

这是带公开位置偏好的 softmax 阅读器, 不是实测 LLM 的 Lost in the Middle 曲线。本例的阈值和窗口长度不能外推成任何模型的有效上下文。

## 常见误区与自测

上下文窗口变大, 可以直接认为有效知识范围变大吗?

<details><summary>展开解析</summary>

不可以。长上下文处理中以下三个层次并不等价:
- 上下文窗口变大仅代表位置编码与显存允许模型接收更多输入 token。
- 目标证据落在窗口范围内仅代表信息在理论上可达。
- 生成阶段证据能否分到足以主导决策的读出权重, 才决定信息是否被模型有效利用。
在本例的位置中性读出器中, 证据固定得 4 分、每个干扰 token 得 0 分, 随着窗口长度从 16 扩展至 256 个 token, 分母中累加的干扰项成倍增加, 证据分到的归一化权重持续衰减: 16 个 token 时单条证据尚能跨过充分阈值, 到 64 个 token 时权重已降至 0.4643 (低于 0.5)。因此评估模型的真实有效上下文范围, 必须系统移动证据位置、逐步增加无关干扰密度, 并检验跨位置多条证据的组合推理能力。

</details>
