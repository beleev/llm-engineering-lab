# M28 — DiLoCo: 本地跑 H 步再同步一次, 通信次数降到 1/H

[llm_train 目录](../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/train/fault-tolerance)

## 直觉

DDP 每走一步就要 all-reduce 一遍梯度。同一个机房里这没问题, 跨数据中心时带宽和延迟都撑不住。

DiLoCo 的做法是让每个 worker 用自己的数据分片连着跑 H 步本地优化, 只在每 H 步末尾同步一次:

1. 各 worker 从同一份外层参数 $\theta^{(t-1)}$ 出发, 各跑 H 步 AdamW, 得到 $\theta_i^{(t)}$。
2. 把 $\theta^{(t-1)} - \theta_i^{(t)}$ 在 worker 之间取平均, 得到伪梯度 $\Delta^{(t)}$。
3. 外层用带 Nesterov 动量的 SGD 把 $\Delta^{(t)}$ 当梯度走一步, 更新 $\theta^{(t)}$。

同步次数从总步数变成总步数除以 H, 通信量同比例下降。

## 核心原理

### 伪梯度与外层更新

$$\Delta^{(t)} = \frac{1}{k}\sum_{i=1}^{k}\left(\theta^{(t-1)} - \theta_i^{(t)}\right)$$

方向是**旧参数减新参数**, 所以它和真梯度同向 (下降要减掉它)。外层这一步是:

```
buf   <- mu · buf + Delta
step  <- Delta + mu · buf        # Nesterov: 动量再往前推一步
theta <- theta - lr_out · step
```

有效步长约为 $\mathrm{lr_{out}}/(1-\mu)$: 论文的 0.7 与 0.9 配起来是 7 倍。这解释了 H 很小时为什么会走坏 —— 每一步都被放大 7 倍。

### 退化成 DDP 的那一组参数

H = 1、内层用朴素 SGD、外层 $\mathrm{lr_{out}} = 1$ 且无动量时:

$$\theta \leftarrow \theta - 1 \cdot (\theta - \bar\theta) = \bar\theta$$

外层变成恒等映射, 而 $\bar\theta$ 正是 DDP 走一步会到的地方。demo 用这组参数和手写的 DDP 对表, 差 1.79e-07, 这个差来自 $\theta - 1.0 \cdot (\theta - \bar\theta)$ 在 fp32 下不是逐位的 $\bar\theta$。

### Streaming DiLoCo

参数分成 G 份轮流同步, 每 H/G 步同步其中一份。每一份仍然每 H 步被同步一次, 所以总通信量不变, 但单次同步只发 1/G 的参数, 峰值带宽同比例降下来。

断言:

1. H=1 且外层退化时与手写 DDP 相差 < 1e-6; H=40 时相差 > 1e-3 (不该再等于 DDP)。
2. 通信量与 H 成反比: H=16 的通信量 × 16 等于 H=1 的。
3. H=16 与 H=48 的留出集 MSE < 1e-6 (训得动)。
4. H=1 的 MSE 比 H=16 大六个数量级以上 (被外层动量放大后走坏)。
5. H=240 的 MSE 高于 H=48 (同步太少跟不上)。
6. 分片错峰的总通信量与整块同步相同, 单次字节数降到 1/G。

## 与真实系统的差距

- 玩具模型是一层线性回归 (16 维进 4 维出, 272 字节), 数据严格 IID。论文在 1.5 亿参数、C4 语料、8 个 worker 上取 H=500, 通信次数是每步同步的 1/500, 困惑度与每步同步持平, 还测了非 IID 分片的鲁棒性; 这些在 272 字节的线性模型上都验证不了。
- 本文件的最优 H 是 48 (960 步里同步 20 次)。这个数字由玩具问题的条件数和学习率决定, 不能外推到真实模型。
- 单进程模拟, worker 之间不是真的异步。论文还有一个关键工程点是 worker 可以不同步地跑 (某个 worker 慢了不阻塞别人), 这里没有建模。
- Streaming DiLoCo 原文按 transformer 的层分片 (默认每 3 层一片, 24 层模型峰值带宽降 8 倍), 还叠加了把外层梯度量化到 4 位 (E3M0) 和"同步期间继续训练"。本文件的玩具模型没有层, 所以改成按输出维轮转分片, 只演示"错峰"这一点, 量化和重叠都没做。
- 外层超参直接用论文的 0.7 / 0.9 (Streaming DiLoCo 用 0.4), 没有在玩具问题上重新搜。

## 常见误区

- "H=1 就是 DDP" —— 只有在外层同时退化成恒等映射 (lr 1、无动量) 时才成立。照搬论文的 0.7 / 0.9, H=1 的有效步长是内层的 7 倍, demo 里 MSE 是 1.18, 比全 0 预测的 4.458 只好一点。
- "通信省了 H 倍, 所以 H 越大越好" —— H=240 时只同步 4 次, MSE 从 1.4e-11 回升到 2.9e-03。worker 之间漂得太远, 平均一下补不回来。
- "DiLoCo 等于联邦平均" —— 它确实是联邦平均的一个变体, 区别在内层步数 H 很大 (几百步) 而且外层有一个带动量的优化器; 直接取平均 (外层 lr 1、无动量) 在大 H 下明显更差。
- "Streaming 省通信量" —— 它省的是**峰值带宽**, 总字节数一点没少 (demo 里三档都是 8160 B/rank)。真正省总量的是那篇论文的第三项改动: 把外层梯度量化。
- "伪梯度是新参数减旧参数" —— 反了。论文的定义是旧参数减新参数, 这样它才和梯度同向, 外层优化器才能照常用。

## 自测题

1. 总步数 60000、H=500、8 个 worker 时同步几次? **答: 120 次。**
2. 外层 lr 0.7、动量 0.9 的有效步长约是多少倍? **答: $0.7/(1-0.9) = 7$ 倍。**
3. Streaming DiLoCo 分 8 片、H=400 时, 每隔多少步会发生一次同步事件, 每次发多少参数? **答: 每 50 步一次, 每次发 1/8 的参数; 每一片仍然每 400 步被同步一次。**
