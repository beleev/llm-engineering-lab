# M21 — 通用 LLM 评测

运行: `python -m llm_train.m21_llm_eval.demo`

## 直觉
m19 / m20 决定了训多大的模型、用什么 lr。训完要回答的是: 它到底好不好。

评测给出的是一个数字, 但这个数字很容易骗人。这里演示四个最常见的坑:

- **perplexity**: `PPL = e^CE`, CE 是逐 token 交叉熵的均值。直观含义是 "模型平均在几个词里犹豫"。按 token 平均和按文档平均, 结果不同; 分词器不同, 数字也不能直接比。
- **污染**: 测试题混进了训练语料, 分数就是背出来的。n-gram 重叠能查出原题和轻改的题, 查不出改写过的。
- **pass@k**: 每题采 n 个样本, c 个对。直接代 `1 − (1 − c/n)^k` 会系统性低估, 要用无偏估计。
- **LLM-as-judge 位置偏差**: 裁判偏爱先出现的回答。交换 A/B 各判一次, 两次一致才算数, 偏差就抵消了。

## 核心数据结构与控制流
- `demo.py:token_nll` — 逐 token 负对数似然; 均值 = CE。
- `demo.py:ngram_flags` — 训练集所有 8-gram 建一个 set, 测试题任一 8-gram 命中即判脏 (GPT-3 用 13-gram)。
- `demo.py:pass_at_k` — Codex 论文的数值稳定写法。
- `demo.py:rule_judge` / `demo.py:judge_swap` — 带 0.8 分 "先手加分" 的规则裁判; 交换后按一致性给出 A 胜 / B 胜 / 平局。

## 核心公式
```
CE = −(1/T) Σ_t log p(x_t | x_<t),    PPL = e^CE,    bits/字符 = CE · T / (字符数 · ln 2)
pass@k (无偏) = 1 − C(n−c, k) / C(n, k) = 1 − Π_{i=n−c+1..n} (1 − k/i)
pass@k (朴素) = 1 − (1 − c/n)^k            ← 对 c/n 是凹函数, Jensen 不等式 → 期望偏低
```

## 运行后应该看到什么
```
均匀分布 CE / PPL          = 2.9957 nats / 20.000
unigram                    = 2.8595 nats / 17.453
bigram (训练集计数)         = 1.7050 nats / 5.501
真实分布                    = 1.6952 nats / 5.448
按 token 平均 / 按文档平均的 PPL = 5.501 / 5.573
若 1.0 token/字符: PPL / bits-per-char =  5.501 / 2.4598
若 0.5 token/字符: PPL / bits-per-char = 30.265 / 2.4598

verbatim / light / heavy / clean 被标为污染的比例 = 1.00 / 1.00 / 0.00 / 0.00
报告分 0.570 → 去掉被标记的题后 0.436 → 真实能力 (只算 clean) 0.300

k=1  真值 0.1883 / 无偏 0.1884 (+0.0001) / 朴素 0.1884 (+0.0001)
k=5  真值 0.4638 / 无偏 0.4639 (+0.0001) / 朴素 0.4435 (−0.0203)
k=10 真值 0.5864 / 无偏 0.5861 (−0.0003) / 朴素 0.5470 (−0.0394)

单次判: 选第一个的比例 0.700 (真实 A 更好 0.498);  准确率 好的在 A 0.994 / 在 B 0.593
交换判: 平局 0.407;  A 胜 0.508;  准确率 好的在 A 0.993 / 在 B 0.991
```
- 均匀分布的 PPL 恰好等于词表大小 20, 这是 PPL 的 "等效分支数" 含义。
- 同一段文本, 分词器把 token 数减半, PPL 从 5.5 变成 30.3, 但 bits-per-char 不变。
- 重度改写的题一道都没查出来, 所以 "去污染后" 的 0.436 仍比真实能力 0.300 高。

## 与真实系统的差距
- 语料是合成的 (二元马尔可夫链 / Zipf 词表)。随机文本里 8-gram 几乎不会撞上, 所以干净题零误标。
- 真实语料里的常见短语 (版权声明、代码模板) 会造成误标。实际检测一般会忽略高频 n-gram, 即在训练集里出现太多次的那些。
- "见过就 90% 答对" 的模型是假设的。它用来说明污染如何抬高分数, 不代表真实模型的记忆率。
- 改写题逃过 n-gram 检测是真实问题。实际做法还有:
  - embedding 相似度检索;
  - 让模型补全题目, 看能否逐字复现 (成员推断);
  - 用发布日期之后的新题。
- 规则裁判的偏差是写死的常数 0.8。真实 LLM 裁判还有长度偏差 (偏爱长回答) 和自我偏好 (偏爱自家模型的回答)。交换顺序只能消掉位置偏差。
- 交换判有 40.7% 平局, 都是质量接近、偏差压过真实差距的对。真实做法会把平局算 0.5 分, 或者再加多个裁判投票。
- 只做了 perplexity 和 pass@k 这类指标。没做 MMLU 式多选题的 prompt 格式敏感性、few-shot 数量等问题。

## 常见误区
- "PPL 越低模型越好, 可以跨模型比" —— 只有分词器和测试集都相同时才能比。否则比 bits-per-byte。
- "pass@k 就是采 k 个看有没有对的" —— 这样也无偏, 但方差大。标准做法是采 n ≥ k 个, 用无偏公式。直接把 c/n 代进 1−(1−p)^k 是有偏的。
- "去掉被 n-gram 标记的题就干净了" —— 改写的题还在。

## 自测题
1. 词表 50000, 模型输出均匀分布, PPL 是多少? **答: 50000。**
2. n=20 个样本里 c=2 个对, pass@10 的无偏估计? **答: 1 − C(18,10)/C(20,10) = 1 − 43758/184756 ≈ 0.763; 朴素公式给 1 − 0.9¹⁰ ≈ 0.651, 偏低。**
3. 交换 A/B 顺序判两次, 为什么能消掉位置偏差? **答: 每个回答在两个位置各出现一次, 只有两次都选它才算赢。先手加分对两边一样。**
