# 多语言: 采样、分词与翻译偏差

## 直觉

「不要开启邮件」在原词表里被切成 6 个单字 token, 加 3 个本地词条后是 3 个; 160 条预算按频率抽, 中文只分到 21 条, 均衡后是 82 条。同样一句意思, 不同语言消耗的 token 数不同; 同样一份数据预算, 也可能几乎没训练到低资源语言。

## 核心原理

实验实际抽样英中两种短语并从频率估计标签, 比较按规模抽样 ([139, 21])、按语言均衡 ([78, 82]) 和错误翻译标签三个条件。简化分词器算出同一句话的 token 膨胀 (6 对 3), 预算要按 token 而不是句数对齐。

跨语言迁移可以共享词嵌入、子词与参数, 也可以用平行语料对齐表示或共享 adapter。共享不保证正迁移: 高资源语言的梯度可能压过低资源语言, 要做单语、混训、平衡混训三组对照。

翻译测试集可能抹掉否定、敬语、习语和地方常识: 本例把「不要开启邮件」的标签翻成「开启」, 否定判断就从正确变成错误。测试集要保留原生作者题、代码混合文本、不同文字系统与文化语境; 标签由本地使用者校验, 记录译者分歧。

温度采样 p(language) ∝ n^α 用 α 调低资源语言的上采样比例; 同时报告各语言的数据重复率、准确率、校准与每正确任务 token 成本。中文池只有 2 句不同短语时, 均衡抽到 82 条也只是反复重复同一批数据, 不等于新覆盖。

## 怎样验证

固定 160 条抽样预算和同一个短语分类器, 先跑按频率、语言均衡、翻译标签三个条件, 再核对「中文否定正确」的错误来自训练覆盖还是翻译标签; 当前短语分类不验证通用跨语言语义迁移, 真实模型要留出未见实体和原生表达。

## 与真实系统的差距

两种受控语言模板，不是低资源语言 benchmark。分词器扩词还需处理新增 embedding、旧分词兼容和训练成本。

## 常见误区与自测

语言均衡训练后还要单独测原生题, 原因是什么?

<details><summary>展开解析</summary>

因为翻译数据可能带来标签和语境偏差: 本例均衡采样后中文样本 82 条, 否定句一旦用翻译标签就判错。均衡采样只调整训练分布, 代替不了原生语言的独立验收。

</details>
