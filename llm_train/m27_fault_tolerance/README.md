# M27 — 容错训练: 卡越多挂得越勤, 多久存一次盘才最划算

[llm_train 目录](../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/train/fault-tolerance)

## 直觉

千卡任务里"挂掉"不是异常, 是日程。N 张卡各自独立出故障, 任意一张挂掉整个同步训练任务就得停, 所以整体 MTBF 等于单卡 MTBF 除以 N: 单卡 10 万小时在 16384 张卡上只剩 6.1 小时。

于是要排四件事:

- **多久存一次盘**: 存得太勤, 时间花在落盘上; 存得太稀, 每次挂掉要重跑很长一段。两头都亏, 中间有个最优点。
- **慢节点**: 同步训练一步要等最慢的那个 rank, 所以每步时间是 N 个样本里的最大值, N 越大这个最大值越大。
- **静默数据损坏 (SDC)**: 算错了但没报错。要靠副本之间对校验和, 或者在同一个 rank 上确定性重算。
- **少几张卡怎么接着跑**: 重切数据与优化器状态, 用梯度累积把全局 batch 补回原来的大小。

## 核心原理

### 最优 checkpoint 间隔

设 $\delta$ 是一次落盘阻塞的时间, $M$ 是整体 MTBF, $R$ 是重启恢复耗时, $\tau$ 是两次 checkpoint 之间的**纯计算时间**。两笔开销是:

- 落盘占比 $\delta / \tau$: 每跑 $\tau$ 就要额外花 $\delta$。
- 重跑占比 $\tau / (2M)$: 故障平均落在一段的中间, 期望丢掉半段。

两者相加在 $\tau = \sqrt{2 \delta M}$ 处最小, 这就是 Young 1974 的一阶近似; 最优点上这两笔开销正好相等 (demo 实测两边都是 0.118)。Daly 把重启耗时算进去并减掉落盘本身占的那一段, 给出 $\tau = \sqrt{2 \delta (M + R)} - \delta$, 适用条件是 $(\tau + \delta)/M < 1/2$。

### goodput 的解析式与蒙特卡洛

```
goodput = tau / (M · e^(R/M) · (e^((tau+delta)/M) - 1))
```

分母是"为了保住 $\tau$ 秒有效进度平均要花多少墙钟时间": $e^{(\tau+\delta)/M} - 1$ 是这一段期望重试的次数, $e^{R/M}$ 把每次重启的代价摊进去。demo 另外按泊松过程抽样做了一遍蒙特卡洛, 八组参数上两者差最多 0.39 个百分点。

### 慢节点

每个 rank 单步耗时 $t_i = 1.0 + \mathrm{Exp}(0.1)$ 时, 同步一步要 $\max_i t_i$。指数分布最大值的期望随 $N$ 对数增长, 所以从 8 个 rank 到 1024 个 rank, 被拖掉的比例从 13.6% 升到 37.2%。


断言:

1. 整体 MTBF × N 等于单卡 MTBF; 卡越多整体 MTBF 越短。
2. 落盘越快最优间隔越短; Young 间隔处落盘占比与重跑占比相等 (差 < 1e-9)。
3. 异步快照的最优 goodput 高于同步落盘; 解析模型与蒙特卡洛差 < 1 个百分点。
4. 1024 个 rank 被慢节点拖掉的比例 > 30%, 单 rank 时 < 1%。
5. 指数位翻转在 1e-6 阈值下抓得到, 尾数末位翻转抓不到; 同一个 rank 确定性重算的校验和逐位相同。
6. 8 卡与 6 卡 (每卡累积 2 次) 的全局平均梯度相差 < 1e-7, 但不是逐位相同。

## 与真实系统的差距

- 故障按单一指数分布的泊松过程到达。真实集群有相关故障: 一个机架掉电、一次固件升级会同时带走很多卡, 这时实际 goodput 比模型低。
- 异步 checkpoint 只建模"阻塞时间变短", 没有建模后台落盘还没写完又挂掉的情况; 真实实现要处理这个窗口 (保留上一份完整的 checkpoint)。
- 慢节点用一个固定分布抽样。真实的慢节点来自热降频、网络拥塞、数据加载不均, 而且往往是同一张卡持续慢, 要靠检测并换卡。
- SDC 用位翻转模拟, 只在一个梯度张量上翻一位。真实的 SDC 可能发生在前向中间、持续出现在同一个 SM 上, 定位要靠逐层对比和换卡复现。
- 弹性缩容只重切数据和梯度累积步数, 没有真的重切 ZeRO 分片和 TP/PP 拓扑 (真实框架要做 checkpoint resharding)。
- Llama 3 405B 的 54 天预训练快照里有 466 次中断, 其中 47 次计划内、419 次意外, 报告的有效训练时间高于 90%。这份统计只能作为引用, demo 的参数是自己设的。

## 常见误区

- "存得越勤越安全" —— 落盘占比 $\delta/\tau$ 会把 goodput 吃掉。同步落盘 10 分钟时, 15 分钟存一次的 goodput 只有 56.4%, 比最优的 75.9% 还低近 20 个百分点。
- "Young 和 Daly 差很多" —— 这两个式子在常用参数下很接近 (85 分钟对 76 分钟), 而且 goodput 曲线在最优点附近很平: 60 分钟到 90 分钟之间 goodput 只差 0.6 个百分点。真正影响大的是 $\delta$ 和 $M$ 本身。
- "异步 checkpoint 省的是带宽" —— 它写的字节数一点没少, 省的是**阻塞时间**。公式里只有阻塞时间 $\delta$ 说话。
- "弹性缩容之后还能逐位续上" —— 全局 batch 补回来了, 平均梯度在 fp32 噪声内相同 (2.2e-08), 但求和顺序变了, 浮点加法不满足结合律, 所以不是逐位相同。m08 的逐位续训要求连求和顺序都不变。
- "副本间逐位比较就能抓 SDC" —— 只有在两个副本的归约顺序完全一致时才成立。顺序不同时只能设阈值, 阈值以下的损坏 (比如尾数末位翻转, 差 7.45e-09) 查不出来。

## 自测题

1. 单卡 MTBF 10 万小时, 要让整体 MTBF 不低于 24 小时, 最多能用多少张卡? **答: 100000/24 ≈ 4166 张。**
2. 落盘阻塞从 10 分钟降到 2.5 分钟, Young 的最优间隔和两笔开销各变成原来的多少? **答: 间隔变 1/2 ($\sqrt{1/4}$), 两笔开销各变 1/2 (都正比于 $\sqrt{\delta/M}$)。**
3. 为什么 NaN guard (m10) 挡不住 SDC? **答: NaN guard 只查非有限值; SDC 产生的是一个看起来正常的数, 有限、量级也可能正常, 只能靠副本间对比或重算发现。**
