# PRM vs ORM — 给每一步打分, 还是只看最终答案

```bash
python -m llm_finetune.run_finetune.prm.train_prm      # ~25 s
```

## 直觉
多步推理的解, 最终答案错了, ORM 只知道 "这条不行", 不知道坏在哪一步: 它得从一个 0/1 里自己做信用分配, 信号稀疏, 学得慢; 而且 "过程错、答案蒙对" 的解它也照样打高分。
PRM 给**每一步**一个 "对 / 错" 标签: 监督信号稠密 K 倍, 每个标签只要求一个局部判断 ("这一行算式对不对"), 还能直接指出第一个错步。代价是标签贵 (PRM800K 要人逐步标)。

## 核心数据结构与控制流
- `methods/prm.py:ArithChain.sample` — 题目 `a0 op1 k1 … op4 k4 SEP`, 解 `op1 k1 v1 … op4 k4 v4 EOS`, 模 10 的 + / − / ×。候选解来自带噪的程序求解器: 每步以 p_err=0.2 写错, 之后照着写错的值往下算 (像真人一样)。每步标签可程序判定。
- `methods/prm.py:prm_loss` / `orm_loss` — 同一个 `RewardModel` (主干 + 标量头), PRM 在 4 个 v_i 位置上做 BCE, ORM 只在 EOS 位置上做 BCE。
- `methods/prm.py:token_scores` — 逐位置取分 (`RewardModel.forward` 只取末位置)。
- `methods/prm.py:solution_scores` — 整条解的分: PRM 取各步概率的最小值, ORM 取末位置概率。

## 核心公式
`s_t = σ(value_head(h_t))`
`L_ORM = BCE(s_EOS, [答案对])`，`L_PRM = mean_i BCE(s_{v_i}, [第 i 步对])`
PRM 的解分 = `min_i s_{v_i}` (一步错整条错, 取短板)

## 运行后应该看到什么
留出集 512 题 × 每题 8 个候选; 两个打分器同一初始化、同一串训练数据 (600 步 × 96 条, lr=5e-4):

| | 数值 |
|---|---|
| 候选解: 答案对 / 每步都对 / 过程错但答案蒙对 | 0.459 / 0.414 / 0.045 |
| 训练后 BCE: ORM | 0.682 (ln 2 = 0.693, 几乎没学) |
| 训练后 BCE: PRM | 0.359 (只猜 "都对" = 0.500) |

| best-of-8 | 答案对 | 每步都对 |
|---|---|---|
| 随机挑 1 个 | 0.473 | 0.426 |
| ORM | 0.488 | 0.422 |
| **PRM** | **0.648** | **0.627** |

定位第一个错步 (至少错一步的候选): PRM 打分最低的一步 = 第一个错步的比例 **0.575**; 最好的常数猜法 "总说第 1 步错" 0.341; ORM 只有一个分, 无从定位。

**如实解读**:
- 同样的解、同样的步数, 只是标签粒度不同: PRM 把 best-of-8 从 0.47 提到 0.65, ORM 几乎等于随机挑。
- ORM 不是学不会, 是学得慢: 脚本外另跑同配置 ORM 3000 步, BCE 到 2000 步后才开始下降 (约 0.55)。这里比的是 "同样的训练预算"。
- PRM 本身也只训了一半 (8 个里至少一个对的比例是 0.992, PRM 只挑中 0.648), 离上限还远。

## 诚实边界
- 候选解来自带噪的程序求解器, 不是 LM 采样; 错误的分布 (均匀地随机写错一个数) 比真实 LM 的错误简单。
- 逐步标签是程序判的, 不花钱; 真实场景里 PRM 的主要成本正是标签 (人标或 Math-Shepherd 式的 rollout 估计), 本脚本体现不了。
- 同时错多步时, "分最低的一步" 可能指向后面那个错步, 所以定位准确率会被低估一点。
- 解每步写成 "op k 结果" 一行, 让每步的判断是局部的; 只写结果 v_i (不重抄 op k) 时, PRM 学得明显更慢 (开发中试过, 未留在脚本里)。

## 常见误区
- 把 PRM 的分取在 v_i 的**前一个**位置: 那时还没读到 v_i, 判断不了它对不对。
- 解分用各步概率的平均: 一步错整条就错, 平均会被其余对的步稀释; 取 min (或乘积)。
- 以为 ORM 分高 = 过程对: ORM 的标签就是 "答案对不对", 4.5% 过程错但答案蒙对的解在它的训练数据里就是 "好"。

## 自测题
1. 同样 N 条解, PRM 和 ORM 各拿到多少个标签? — PRM N·K 个, ORM N 个。
2. 为什么 PRM 的解分取 min 而不是平均? — 一步错整条错; 平均会被其余正确的步稀释。
3. ORM 在这里只比随机好一点, 是因为它的上限低吗? — 不是, 是同样预算下学得慢; 训更久它也会开始下降。
