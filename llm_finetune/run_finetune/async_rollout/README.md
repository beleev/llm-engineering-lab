# 异步 RL: 样本来自哪一版策略

## 直觉

异步 RL 训练将轨迹生成与参数更新解耦为并行流水线:
- 生成器持续以当前持有的模型快照采样回答并评定奖励 (单次完整采样记录称为一条 rollout), 写入共享缓冲队列。
- 训练器异步从队列消费轨迹并执行梯度更新。

本组实验中训练器参数已迭代至 v3, 而缓冲队列中仍驻留着旧版策略 v1 采出的历史轨迹。对比四种消费策略的结果:
- 直接混用旧样本: 忽略策略差异直接按同策略公式求均值, 估得奖励期望仅为 0.2, 显著偏离 v3 的真实期望 0.8。
- 重要性权重校正: 按目标策略与采样行为策略的概率比加权校正, 奖励期望准确恢复至 0.8, 但极端权重导致相对 ESS (有效样本比例, 满分 1 代表等权无损) 降至 0.3077。
- 权重截断裁剪: 将重要性权重限制在 [0.8, 1.2] 区间内以抑制方差, 相对 ESS 回升至 0.968, 但有偏截断使估计期望停留在 0.24。
- 超龄样本拒收: 对策略版本跨度超出容忍上限的陈旧样本直接丢弃, 本步跳过无效参数更新。

向生成器广播同步新版模型权重仅改变后续新任务的采样分布, 队列中已生成的存量轨迹仍属于历史策略样本。

## 核心原理

异步 rollout 必须在采样生成的当下持久化记录采样策略版本号与动作对数概率 (行为 logp), 并通过有界队列背压与最大滞后步数双重约束样本陈旧度。向推理侧同步新版权重仅对同步点之后新发起的采样生效, 队列中早先入队的记录仍保留 v1 版本标记。运行时通过两道流控机制兜底稳定性:
- 有界队列与背压: 缓冲队列容量上限设为 2, 满载后继续提交新任务会被拒绝并记入背压信号以抑制生产速率 (本例触发 1 次), 防止历史积压无限膨胀。
- 滞后版本拒收: 消费端核对当前训练器版本与样本携带版本的跨度, 超出最大允许滞后阈值时直接拒收, 防止分布偏移过大。

此外, 已标记取消的在途任务在出队时直接丢弃并同步登记为已回收状态, 确保生命周期结束时未回收悬空任务数为 0。

重要性采样通过目标分布与行为分布的似然比消除跨策略期望偏差, 但新旧分布差异较大时会放大梯度方差并压缩有效样本量。为给出精确解析结果, 本实验构造离散双动作空间 (动作 0 奖励为 0, 动作 1 奖励为 1), 两组策略分布如下:
- 行为策略 v1 (采样端实际执行的旧模型): 选择动作 0 与动作 1 的概率分别为 0.8 与 0.2。
- 目标策略 v3 (训练端当前更新的新模型): 选择动作 0 与动作 1 的概率分别为 0.2 与 0.8。

因此 v3 的真实奖励期望为 0.8, 而直接对 v1 样本取无权均值仅得 0.2。重要性校正为每个动作乘以目标概率与行为概率之比: 动作 1 的权重为 0.8 除以 0.2 等于 4, 动作 0 的权重为 0.25, 加权期望精确恢复至 0.8; 代价是估计值由少数高权重样本主导, 相对 ESS 降至 0.3077, 即 100 条异步样本仅折合 31 条独立同分布样本的统计效率。若将重要性权重截断裁剪至 [0.8, 1.2] 区间, 相对 ESS 回升至 0.968, 但奖励期望仅恢复至 0.24, 清晰呈现了以有偏估计换取低方差的偏差-方差折中。

重要性权重的分母必须严格采用采样执行当下记录的行为 logp, 不能在训练端用参数快照事后重算替代。真实分布式 RL 系统中, 推理引擎与训练引擎往往采用不同的采样温度、算子数值精度、算子融合核或 logits 截断处理, 即便加载同一版模型权重, 训练器前向重算出的 token 概率仍可能与生成端实际采样分布存在系统性偏差。实验边界: 本实验按固定顺序确定性重放提交、权重同步、取消与出队事件序列, 未在多 GPU 集群上运行真实并发流水线, 因此不对异步训练硬件吞吐加速比下结论。

## 运行

```bash
python -m llm_finetune.run_finetune.async_rollout.demo
```

需要 Python ≥ 3.10; 使用现有 torch 依赖。默认 CPU、本机夹具, 无模型 API 调用。

## 与真实系统的差距

这是异步执行顺序的确定性重放，不是多 GPU 吞吐实测。ESS 是有效样本比例；裁剪会引入偏差。拒收时期望 0 表示没有更新，不能解释成策略奖励降为零。引擎温度与数值精度差异应保留实际行为 logp，不能用训练器重算值替换。

## 怎样验证

固定行为策略 v1、目标策略 v3 以及容量上限为 2 的有界缓冲队列, 重放同一条确定性生命周期事件流 (提交旧版采样任务、同步权重至 v3、中途取消单个任务、训练端出队消费), 横向对比四种陈旧样本处理方式: 直接无权使用、精确重要性校正、裁剪重要性权重与超龄拒收。验收联合核查三项指标:
- 校正后的奖励期望能否恢复至目标真值 0.8, 或按裁剪规则呈现预期偏差。
- 各加权方案对应的相对 ESS 退化幅度。
- 队列满载背压触发次数与最终未回收任务数是否严格符合预期。

边界测试见 [test_engineering_completion.py](../../../tests/test_engineering_completion.py)。

## 常见误区与自测

模型权重完成向生成器同步后, 缓冲队列中此前由旧版本策略采出的存量 rollout 应当如何处理?

<details><summary>展开解析</summary>

必须原样保留每条存量 rollout 在采样时刻记录的策略版本号与行为对数概率, 再按滞后程度执行合规处理:
- 滞后在允许范围内时做重要性采样校正 (或裁剪校正): 以当前目标策略概率除以采样行为概率作为样本权重; 本实验中精确加权将奖励期望拉回真值 0.8, 同时相对 ESS 降至 0.3077。
- 策略版本跨度超出最大允许上限时直接拒收丢弃: 跳过基于严重过期轨迹的梯度更新以保护训练稳定性。

工程实现中严禁两类错误操作:
- 在权重同步时将队列中存量记录的版本号批量覆写为当前新版本。
- 丢弃原始行为 logp, 改用当前训练器前向重算出的概率充当校正分母。

上述两种错误均等价于将重要性权重强行置为 1、把跨策略旧样本伪装成同策略新样本, 会导致估计期望停留在偏误值 0.2。

</details>
