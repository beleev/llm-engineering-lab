# 异步 RL: 样本来自哪一版策略

## 直觉

异步 RL (强化学习) 训练里, 生成答案和更新模型分开跑:
- 生成器不停地用当时的模型采样答案 (采样一次得到的答案和奖励叫一条 rollout), 放进队列。
- 训练器从队列里取出来更新模型。

这组实验里训练器已经从 v1 更新到 v3, 队列里却还躺着 v1 采的答案。四种处理办法:
- 直接使用旧样本: 把旧答案直接当成 v3 的样本用, 算出的奖励期望是 0.2, 而 v3 真实的期望是 0.8。
- 重要性校正: 按采样时的概率做重要性校正, 期望回到 0.8, 但相对 ESS (有效样本比例, 1 表示每条样本都同样有用) 掉到 0.3077。
- 裁剪权重: 把校正权重限制在 0.8 到 1.2 之间, ESS 回到 0.968, 期望却只有 0.24。
- 拒收过期样本: 版本差超过上限的旧样本直接拒收, 这一步就不更新。

模型权重同步到新版本, 不会让已经采出来的样本自动变成新版本的样本。

## 核心原理

每条 rollout 在采样那一刻就要记下两样东西: 用的是哪一版策略 (策略就是当时的模型), 以及采到这个动作的概率的对数 (行为 logp)。权重同步只影响同步之后才提交的新任务, 队列里的旧记录仍然写着 v1。这里有两道限制:
- 队列容量是 2, 塞满后再提交就被拒绝, 并记一次背压 (让生成器慢下来的信号), 本例发生 1 次; 这样积压不会无限变多。
- 版本差超过上限的样本还会被拒收, 样本也不会无限变旧。

被取消的任务出队时直接丢弃, 同时登记为已处理, 所以最后未回收的任务数是 0。

重要性校正能把期望拉回真值, 代价是有效样本变少。为了得到精确的数字, 实验只有两个动作, 奖励分别是 0 和 1, 期望可以直接枚举算出来。两个策略:
- v1 是行为策略 (实际采样的那一版), 选两个动作的概率是 0.8 和 0.2。
- v3 是目标策略 (正在训练的这一版), 概率是 0.2 和 0.8。

所以 v3 的真实期望是 0.8, 直接拿 v1 的样本算只得 0.2。重要性校正给每条样本乘一个权重, 权重是目标概率除以行为概率: 动作 1 的权重是 0.8 除以 0.2 得 4, 动作 0 是 0.25, 加权后期望恢复到 0.8。代价是权重悬殊, 少数样本说了算, 相对 ESS 降到 0.3077, 大约 100 条样本只顶 31 条用。把权重裁到 [0.8, 1.2] 区间, ESS 拉回 0.968, 期望却只有 0.24, 这是用偏差 (估计系统性地偏离真值) 换方差 (估计忽高忽低) 的取舍。

校正公式里的分母必须是采样那一刻实际用的概率, 这个概率就记在 rollout 的行为 logp 里。真实的生成引擎可能和训练器用不同的温度、数值精度或 logits 处理, 所以就算是同一版权重, 训练器事后重算出来的概率也可能和采样时不一样, 不能拿它来替代。这里是按固定顺序重放的一串确定性事件 (提交、同步、取消、取出), 没有真的在多张 GPU 上并发运行, 所以不给出异步训练吞吐的结论。

## 运行

```bash
python -m llm_finetune.run_finetune.async_rollout.demo
```

需要 Python ≥ 3.10; 使用现有 torch 依赖。默认 CPU、本机夹具, 无模型 API 调用。

## 与真实系统的差距

这是异步执行顺序的确定性重放，不是多 GPU 吞吐实测。ESS 是有效样本比例；裁剪会引入偏差。拒收时期望 0 表示没有更新，不能解释成策略奖励降为零。引擎温度与数值精度差异应保留实际行为 logp，不能用训练器重算值替换。

## 怎样验证

固定 v1、v3 两个策略版本和一个容量为 2 的队列, 用同一串事件 (提交旧任务、同步到 v3、取消一个任务、取出样本) 比较四种处理旧样本的做法: 直接使用、重要性校正、裁剪权重、拒收过期样本。判定看三件事:
- 奖励期望能不能回到目标 0.8。
- 相对 ESS 是多少。
- 背压次数和未回收任务数是否符合预期。

边界测试见 [test_engineering_completion.py](../../../tests/test_engineering_completion.py)。

## 常见误区与自测

权重同步之后, 队列里那些旧版本采的 rollout 该怎么办?

<details><summary>展开解析</summary>

保留它们的版本号和行为概率, 然后二选一:
- 按行为概率做重要性校正。校正的意思是给每条旧样本乘上「目标概率除以行为概率」这个权重, 本例这样做之后期望回到 0.8, 代价是相对 ESS 只剩 0.3077。
- 版本差超过上限就拒收。拒收就是这一步不用它们, 也不更新。

有两件事不能做:
- 把旧记录的版本号改成当前版本。
- 用当前模型重新算出的概率当分母。

这两种做法都是把旧样本当成新模型采的, 权重全变成 1, 期望就停在直接使用时的 0.2。

</details>
