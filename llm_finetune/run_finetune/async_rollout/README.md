# 异步 RL: 样本来自哪一版策略

## 直觉

训练器从 v1 更新到 v3 后, 队列里还躺着 v1 采的答案。直接拿来算, 奖励期望 0.2, 目标是 0.8; 按行为概率做重要性校正, 期望回到 0.8, 相对 ESS 掉到 0.3077; 把权重裁到 [0.8, 1.2], 期望 0.24, ESS 0.968; 超龄拒收则干脆不更新。权重同步不会让已经采出的样本自动变成新策略的样本。

## 核心原理

每条 rollout 在采样时记下策略版本和行为 logp, 权重同步只影响之后提交的新任务。容量为 2 的队列用背压限制积压 (本例 1 次), 过期拒收限制偏移, 取消的任务要回收计数, 未回收任务为 0。

两个动作、奖励 (0, 1) 可以枚举期望: 行为策略 (0.8, 0.2), 目标策略 (0.2, 0.8), 目标期望 0.8, 直接用旧分布只得 0.2。重要性校正恢复到 0.8, 但相对 ESS 降到 0.3077; 裁剪到 [0.8, 1.2] 把 ESS 拉回 0.968, 期望却只有 0.24, 这是拿偏差换方差。

真实生成引擎的温度、精度或 logits 处理可能和训练器不同, 分母必须是实际采样时的概率, 不能用当前模型重算的概率替代。这里是确定性的事件顺序重放, 不给异步吞吐结论。

## 运行

```bash
python -m llm_finetune.run_finetune.async_rollout.demo
```

需要 Python ≥ 3.10; 使用现有 torch 依赖。默认 CPU、本机夹具, 无模型 API 调用。

## 与真实系统的差距

这是异步执行顺序的确定性重放，不是多 GPU 吞吐实测。ESS 是有效样本比例；裁剪会引入偏差。拒收时期望 0 表示没有更新，不能解释成策略奖励降为零。引擎温度与数值精度差异应保留实际行为 logp，不能用训练器重算值替换。

## 怎样验证

固定 v1、v3 两个策略版本和容量为 2 的队列, 比较直接使用旧样本、重要性校正、裁剪权重、拒收过期样本四种做法; 判定看奖励期望是否回到目标 0.8、相对 ESS 多少, 以及背压次数和未回收任务数。

边界测试见 [test_engineering_completion.py](../../../tests/test_engineering_completion.py)。

## 常见误区与自测

权重同步之后, 队列里那些旧版本采的 rollout 该怎么办?

<details><summary>展开解析</summary>

留着它们的版本号和行为概率, 然后二选一: 按行为分布做重要性校正 (期望回到 0.8, ESS 0.3077), 或者超过允许的版本差就拒收。不能把版本号改成当前的, 也不能用当前模型重算的概率当分母, 那样期望会停在 0.2。

</details>
