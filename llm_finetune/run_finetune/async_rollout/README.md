# 异步 RL：样本来自哪一版策略

## 直觉

训练器更新了策略，不会让队列里已经采出的答案自动变成新策略样本。

## 核心原理

rollout 固定采样时策略版本和行为 logp；权重同步只影响新任务。队列容量限制积压，过期拒收限制偏移，取消要回收任务计数。

枚举两个动作按行为分布计算期望：目标奖励为 0.8，直接用旧分布得到 0.2。重要性校正恢复期望，但有效样本比例降低；裁剪减少极端权重，同时引入偏差。

实际生成引擎的温度、精度或 logits 处理可能与训练器不同。分母必须是实际采样分布，不能用当前模型重算的概率替代。此处是确定性事件顺序重放，不提供异步吞吐结论。

## 运行

```bash
python -m llm_finetune.run_finetune.async_rollout.demo
```

需要 Python ≥ 3.10；使用现有 torch 依赖。默认 CPU、本机夹具，无模型 API 调用。

## 与真实系统的差距

这是异步执行顺序的确定性重放，不是多 GPU 吞吐实测。ESS 是有效样本比例；裁剪会引入偏差。拒收时期望 0 表示没有更新，不能解释成策略奖励降为零。引擎温度与数值精度差异应保留实际行为 logp，不能用训练器重算值替换。

## 怎样验证

用两个策略版本和队列构造固定延迟，记录行为策略版本、采样概率和消费版本。；比较无校正、重要性校正、过期拒收，报告偏差、有效样本量及吞吐代价；说明裁剪并不保证无偏。；队列满、任务取消、权重切换均不混淆样本归属。CPU 模拟足以验证机制，真实多 GPU 接入单列选做。

边界测试见 [test_engineering_completion.py](../../../tests/test_engineering_completion.py)。
