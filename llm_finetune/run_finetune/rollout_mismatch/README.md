# 训练-推理不一致: 同一份权重, 采样引擎和训练器算出的概率不一样

[llm_finetune 目录](../../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/finetune/rollout-mismatch)

## 直觉

RL 框架为了吞吐, 让推理引擎 (vLLM、SGLang 这类) 负责采样, 让训练框架 (FSDP、Megatron) 负责算梯度。两边每一步都加载同一份权重, 但推理引擎用融合算子、低精度和自己的 softmax 实现, 训练器用另一套算子重算一遍, 同一个 token 的概率在两边不完全相同。

样本是按推理引擎的分布 π_infer 采出来的, 训练器却按 π_train 把它们当成自己采的样本来算策略梯度, 这个梯度就成了异策略梯度, 带着偏差。Yao et al. (2025-08) 在 vLLM 与 FSDP 之间量到过同一个 token 一边概率接近 1、一边接近 0 的情况。

它和 [异步 rollout](../async_rollout/README.md) 讲的不是一回事: 那边训练器已经到了 v3, 队列里还有 v1 采的样本, 差的是策略版本; 这边版本完全相同, 差的是数值路径。

## 核心原理

### 概率比与三种校正

记 $r_t = \pi_{\text{train}}(o_t) / \pi_{\text{infer}}(o_t)$。把它乘到每个 token 的策略梯度上, 就能把行为分布从 π_infer 换回 π_train; 问题是 r 偶尔很大, 方差跟着变大。三种处理:

| 方法 | 权重 | 出处 |
|---|---|---|
| TIS (截断重要性采样) | $w_t = \min(r_t, C)$ | Yao et al. 2025-08; verl 中阈值默认 2 |
| token 级 MIS (屏蔽重要性采样) | $w_t = r_t \cdot \mathbb{1}[r_t \le C]$ | Liu et al. 2025-09 |
| 序列级 MIS | $w = \rho \cdot \mathbb{1}[\rho \le C]$, $\rho = \prod_t r_t$ | Liu et al. 2025-09, 认为是最稳的一种 |

权重乘在 GRPO / PPO 的裁剪目标外面: loss_t = −w_t · min(ρ_t A, clip(ρ_t) A), 其中 ρ_t = π_θ / π_train_old 不变。TIS 把过大的比率截到 C, 方向还在; MIS 把超过 C 的 token 或整条序列丢掉。

第三种修法是让不一致本身变小。Qi et al. (arXiv 2510.26788) 指出 BF16 只有 7 位尾数, FP16 有 10 位, 把训练和推理都换成 FP16 就能消掉大部分不一致 (他们报告序列级不一致约小 24 倍), 代价是 FP16 的数值范围小, 训练要做 loss scaling。

### 本库怎么模拟推理引擎

`Engine` 每次采样前从训练器拷贝最新权重, 只换数值路径:

- fp32: 与训练器同一条路径, 当对照。
- fp16 / bf16: 权重和激活用低精度算, logits 转回 fp32 再做 softmax。
- bf16+int4: 线性层权重再按 INT4 (g=32) 取整, 模拟低精度 rollout。

训练器始终用 fp32 重算 log-prob。代码在 [methods/is_correction.py](../../methods/is_correction.py) (`is_weights`, `mismatch_stats`) 和 [train_rollout_mismatch.py](train_rollout_mismatch.py) (`Engine`, `bias_report`, `grpo_arm`)。

### 梯度偏差怎么量

为了不被采样噪声淹没, 第二部分不采样: 沿留出集 512 题的正确前缀, 在回复的每个位置做一次单步决策, 下一个 token 采对得 1 分, 对整个词表求和得到期望梯度。真实同策略梯度是 $\sum_v \pi_{\text{train}}(v)(r_v - b)\nabla\log\pi_{\text{train}}(v)$; 估计量把 π_train 换成 π_infer 再乘校正权重。报的是相对偏差 ‖E[ĝ] − g‖ / ‖g‖。

```
fp32 none                   0.535   0.324         0.0000        0.00%
bf16 none                   0.473   0.303         0.0070        0.00%
bf16+int4 none              0.543   0.316         0.0315        0.00%

bf16+int4 mis_seq           0.539   0.318         0.0321        0.45%
```

怎么读:

- **bf16 的不一致是 fp16 的 8.2 倍**: 0.00771 对 0.00094, 与 "FP16 精度高 8 倍" (尾数多 3 位) 的说法一致。
- **不一致集中在低概率 token**: 推理引擎认为不太可能 (π_infer < 0.1) 的 token, |log r| 是很有把握 (π_infer > 0.9) 的 token 的 37–67 倍。Liu et al. 在真实系统里观察到的也是这一点。
- **不校正的梯度偏差随不一致增大**: fp16 0.7%, bf16 5.2%, bf16+int4 42.7%。
- **C=2 时 TIS / MIS 基本消除偏差**: fp16 / bf16 下没有 r > 2 的 token, 两者都等于完整的重要性采样, 偏差为 0; bf16+int4 下 TIS 0.017、MIS 0.058。
- **阈值太紧时 MIS 比不校正还偏**: C=1.1 时 MIS 把大量普通 token 丢掉, bf16+int4 下偏差 0.829, 超过不校正的 0.427; TIS 只截断, 偏差 0.118。阈值要放在真正的离群值上。
- **这个规模下不一致没有让训练失败**: 五臂 60 步后 pass@1 都在 0.30–0.32, 都比起点 0.186 高; 彼此的差别在单种子噪声内, 不能读成哪种校正更好。偏差 42.7% 的梯度照样能把 pass@1 推上去, 因为它和真梯度的方向仍然大体一致。

断言 (每条都在脚本末尾):

1. fp32 的不一致为 0; fp16 < bf16 < bf16+int4; bf16 比 fp16 大 4 倍以上。
2. bf16 下低概率 token 的 |log r| 是高概率 token 的 10 倍以上。
3. 不校正的偏差 fp16 < bf16 < bf16+int4, bf16+int4 的相对偏差 > 0.1。
4. C=2 时 TIS / MIS 的偏差都不到不校正的 1/5; fp16 / bf16 下 TIS 的偏差 < 1e-6。
5. C=1.1 时 TIS 的偏差小于不校正, MIS 的偏差大于不校正 (bf16 与 bf16+int4 都如此)。
6. 五臂的留出集 pass@1 都比起点高 0.04 以上。

## 与真实系统的差距

- **推理引擎是模拟的**: 不一致只来自 dtype 和权重取整。真实系统里还有融合算子、不同的归约顺序、张量并行切分、采样时的 top-p 截断, 不一致的分布和长尾都会不同。
- **infer log-prob 用整段前向重算**: 真实引擎是增量解码 (KV cache) 时顺手记下采样概率, 那条数值路径和整段前向还会再不同。Yao et al. 也提到要让 vLLM 返回真正用于采样的概率。
- **回复只有 9 个 token**: 序列级比率 ρ 是逐 token 比率的连乘, 长回复里小误差会累积。这里序列 ρ > 2 的比例只有 0.68%, 真实的长推理和多轮工具调用里会大得多, Liu et al. 认为这正是 token 级校正在那些场景里不够用的原因。
- **训练只有 60 步、单种子**: Yao et al. 和 Liu et al. 报告的崩溃发生在长时间训练里, 这个规模看不到。第三部分只说明 "不一致没有让短训练失败", 不说明它无害。
- **梯度偏差只在单步决策上精确计算**: 第二部分沿正确前缀逐位置求和, 每个位置是独立的单步决策, token 级与序列级校正在这里相同。序列级 MIS 的效果只在第三部分的训练里出现。
- **没有实现 Geo-MIS 和 FP16 训练**: Liu et al. 的几何平均版 MIS (ρ^{1/T} 双侧阈值) 没有实现; FP16 只在采样侧模拟, 训练器始终是 fp32。

## 常见误区

- **把它当成异步 RL 的版本陈旧**: 那边要记录策略版本号, 拒收过旧的样本; 这边版本号完全相同, 记录版本号解决不了。两个问题可以同时存在, 校正权重会相乘。
- **用训练器重算的 log-prob 当行为策略**: 这正是不校正的做法。行为策略是推理引擎真正用来采样的分布, 它的 log-prob 要由引擎在采样时给出。
- **阈值越紧越安全**: C=1.1 时 MIS 的偏差 0.829, 是不校正的两倍。屏蔽掉的 token 越多, 梯度里缺的项越多。
- **bf16 和 fp16 都是 16 位, 精度差不多**: 位数相同, 分配不同。bf16 是 8 位指数、7 位尾数, 范围大精度低; fp16 是 5 位指数、10 位尾数。本例 bf16 的不一致是 fp16 的 8.2 倍。

## 自测题

1. 同一份权重、同一个版本, 为什么推理引擎采样出来的数据对训练器来说是异策略的? — **答**: 样本按 π_infer 采, 梯度按 π_train 的同策略公式算; 两边数值路径不同, π_infer ≠ π_train, 期望就不是在 π_train 下取的。
2. TIS 和 MIS 在 r 超过 C 时分别怎么处理? 哪个更容易在阈值太紧时引入大偏差? — **答**: TIS 把权重截到 C, MIS 把这个 token (或整条序列) 丢掉。MIS: 本例 C=1.1 时偏差 0.829, TIS 0.118。
3. 为什么把采样侧从 bf16 换成 fp16 能减小不一致? — **答**: fp16 的尾数是 10 位, bf16 是 7 位, 每次取整的相对误差小 8 倍。本例 |log r| 均值 0.00094 对 0.00771。
