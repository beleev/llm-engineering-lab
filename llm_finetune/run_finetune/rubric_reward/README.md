# 生成式与 rubric 奖励: 标量 RM 学到长度捷径, 逐条清单不吃长度

[llm_finetune 目录](../../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/finetune/rlhf)

## 直觉

Bradley-Terry 标量 RM 只从 "A 比 B 好" 的标签里学一个分数。标注者如果偏爱长回答, 这份偏爱会原样进入 RM 的系数, RM 自己分不清 "讲得全" 和 "写得长"。

策略被这个 RM 优化时, 能不能利用这条捷径取决于优化压力有多大:
- best-of-N 只从基座分布里挑, 长度变化有限, 长度偏差只分走一点选择力。
- RL 让策略自己移动, 可以把长度推到训练数据里从没出现过的位置, RM 的长度项一路加分, 真实质量反而下降。这就是 reward hacking。

rubric 奖励换一种做法: 为每道题写一份评分清单, judge 逐条判 "满足 / 不满足", 奖励 = 满足的比例。分数里没有长度这一项, 只能靠真的满足条目来涨分。代价是每题都要写清单, judge 本身也会判错。

## 核心原理

### 三种奖励

- **标量 RM**: $P(A \succ B) = \sigma(r_A - r_B)$, 用 $-\log\sigma(r_w - r_l)$ 训练。本脚本的 RM 是线性的, 输入 5 个条目指示和长度 L/100。
- **GenRM** (Zhang et al. 2024, arXiv 2408.15240, "Generative Verifiers: Reward Modeling as Next-Token Prediction"): 让 LM 回答 "这个解对吗", 分数 = 下一个 token 是 "Yes" 的概率; 可以先写一段推理再判, 多条推理的 Yes 概率取平均。论文在 best-of-N 上把算法题从 5% 提到 45.3%, GSM8K 从 73% 提到 93.4%。
- **rubric / 清单奖励**: Rubrics as Rewards (Gunjal et al. 2025, arXiv 2507.17746) 为每题写一份 rubric, judge 逐条判, 按权重加权求和再归一化 (显式聚合); 对照的隐式聚合把整份 rubric 交给 judge 打一个 1–10 分。论文在医学 (HealthBench) 和科学 (GPQA-Diamond) 上用 Qwen2.5-7B + GRPO, 相对直接让 judge 打 Likert 分最多提升 31% 和 7% (相对提升)。RLCF (Viswanathan et al. 2025, arXiv 2507.18624, "Checklists Are Better Than Reward Models For Aligning Language Models") 从指令里抽出清单, 逐条用 AI judge 和专门的验证程序评分, 在 Qwen2.5-7B-Instruct 上 FollowBench +4、InFoBench +6、Arena-Hard +3。

长度偏差的现实依据: Singhal et al. (2023, arXiv 2310.03716, "A Long Way to Go: Investigating Length Correlations in RLHF") 发现只按长度给奖励就能复现大部分 RLHF 的下游提升, 偏差主要来自奖励模型。

### 植入的设定

数据是合成的, 下面每一条都是写进脚本的假设, 不是从真实数据里测出来的:

- 回复 = 5 条 rubric 条目是否满足 + 长度 L。前 4 条是内容条目, 第 5 条是 "简洁": L ≤ 300 才算满足。真实质量 q = 满足的比例。
- 基座策略: 内容条目各以 0.5 的概率满足, L ~ N(200, 60²), 截在 [20, 600]。
- 偏好标签: $P(A \succ B) = \sigma(\gamma (q_A - q_B) + \beta (L_A - L_B)/100)$, $\gamma = 4$, $\beta = 0.8$。多写 100 token 在标注者眼里值 0.8 个 logit, 与多满足一条内容条目一样多。对照组 $\beta = 0$。
- judge: 每条以 ε 的概率判反, 错误彼此独立。"投票" = 同一个 judge 独立判 5 次取平均, 是 GenRM 取平均的离散版。

### 两种优化压力

- **best-of-N**: 从基座采 N 条, 按奖励挑最高的一条, 2000 道题取平均。
- **RL**: 参数化策略 = 4 个内容条目的 logit + 长度均值 μ (标准差固定 60), REINFORCE, 批均值当 baseline, 每步 256 条, 300 步, Adam lr 0.05。长度上限 600, 相当于 max_new_tokens。

**怎么读**:
- RM 把标注里的长度偏差原样学了进去: 长度系数 0.81, 标注值 0.8。β=0 的对照组长度系数 −0.06。
- best-of-N 下长度偏差的影响有限: RM β=0.8 挑出的回复从 199 token 变到 256 token, 真实质量 0.974, 仍高于 rubric ε=0.1 的 0.916。原因是候选都来自基座分布, 而这里的 RM 直接看得见每条条目, 比真实 RM 读文本容易得多。
- RL 下结论反过来: RM β=0.8 把长度推到 600 上限, 真实质量停在 0.792 (4 条内容条目学会了, "简洁" 条目全丢), RM 分却从 4.16 涨到 8.24。rubric 的两臂都到 0.99, 长度留在 300 以内。
- judge 判错的代价: best-of-N 下 ε=0.3 只到 0.754, 5 次取平均后到 0.880。挑中者的 judge 分比真实质量高出 0.233 (N=64), 说明 judge 的随机误差也被优化压力利用了 (挑得越多, 越容易挑到被误判成好的那一条)。RL 下 ε=0.3 同样到 0.993: 独立、对称的判错只让学习变慢, 不改变最优点。

断言 (每条验证一个结论):
1. RM 在带偏差的标签上学到的长度系数 > 0.6; β=0 的对照组 |长度系数| < 0.15。
2. 5 次取平均把 ε=0.3 的逐条判错率降到 0.2 以下。
3. best-of-N: β=0.8 的 RM 挑出的回复 N=64 比 N=1 长 40 token 以上; rubric 挑出的长度变化 < 15。
4. best-of-N: N=64 时 β=0.8 的 RM 真实质量高于 rubric (ε=0.1)。
5. best-of-N: ε=0.3 的真实质量低于 ε=0.1; 投票后高于单次判定。
6. best-of-N: ε=0.3 时挑中者 "judge 分 − 真实质量" 在 N=64 比 N=1 大 0.1 以上。
7. RL: β=0.8 的 RM 把平均长度推到 590 以上, 真实质量 < 0.85, RM 分末步比第 0 步高 1 以上。
8. RL: rubric (ε=0.1 和 ε=0.3) 的真实质量 > 0.95, 平均长度 ≤ 300。

## 与真实系统的差距

- **回复是特征, 不是文本**: 没有 LM, 没有 tokenizer。RM 直接看到每条条目满不满足, 这对 RM 是偏宽松的设定; 真实 RM 读文本, 还会学到长度以外的其他捷径 (格式、语气、讨好)。
- **长度偏差和 "简洁" 条目都是植入的**: β=0.8 和 300 token 的上限是脚本里写死的数。真实偏好数据里长度偏差有多大, 要在具体数据上量。
- **judge 是带噪的规则, 错误彼此独立**: 真实 LLM judge 的错误有系统偏向 (偏爱长回答、偏爱自己的风格、被回答里的说辞带偏), 同一个 judge 多次采样的错误也相关。独立错误取平均能降判错率, 相关错误不能; 有偏向的错误在 RL 下同样会被钻空子。
- **策略是一个 5 参数的 bandit**: 没有 prompt, 没有逐 token 生成。RL 用 REINFORCE 而不是 GRPO, 长度用高斯分布直接参数化。
- **rubric 是现成的**: 真实系统里写 rubric 本身是成本 (Rubrics as Rewards 用更强的模型按参考答案生成 rubric), rubric 写漏的方面同样学不到, 这一点与 RLAIF 章 "judge 没查的学不到" 是同一个问题。
- **单种子**: 所有数字来自一个种子。best-of-N 每格是 2000 道题的平均, RL 每格是一批 256 条的平均。

## 常见误区

- **"标量 RM 一定会被钻空子"**: best-of-N 那张表里 RM β=0.8 的真实质量是 0.974, 高于 rubric。分布内的 RM 往往够用; 问题出在优化把策略推出 RM 见过的分布。
- **"rubric 奖励不会被 hack"**: judge 的误差同样被利用, best-of-N 下挑中者的 judge 分比真实质量高 0.233。rubric 难钻的是 "长度" 这类分数里根本没有的维度, 不是 judge 的错误。
- **"多问几次 judge 就能消除判错"**: 只有错误彼此独立时才成立。同一个模型、同一个 prompt 的多次采样, 错误往往相关。
- **只看 RM 分判断训练好坏**: RL 那张表里 RM 分从 4.16 涨到 8.24, 真实质量只从 0.594 到 0.792, 同期按真实质量优化的 oracle 到了 0.992。要留一个不参与训练的评估。

## 自测题

1. 线性 Bradley-Terry RM 在 β=0.8 的标签上学到的长度系数为什么接近 0.8? — **答**: 标签恰好是特征差的 logistic 函数, 模型设定正确, 最大似然估计收敛到生成标签用的系数。实测 0.81。
2. 同一个 RM, best-of-N 下真实质量 0.974, RL 下只有 0.792, 差在哪? — **答**: best-of-N 的候选都来自基座分布, 长度集中在 200 ± 60; RL 的策略能把长度推到 600, RM 的线性长度项在训练分布外继续加分, 策略为此放弃了 "简洁" 条目。
3. judge 每条以 0.3 的概率判反, 为什么 RL 最后仍到 0.993, 而 best-of-N 只有 0.754? — **答**: 独立对称的判错让 judge 分的期望是真实满足率的仿射函数 (ε + (1 − 2ε)·真值), RL 优化期望, 最优点不变, 只是信号变弱; best-of-N 挑的是单次判定的最大值, 挑得越多越容易挑到被误判的那一条。
