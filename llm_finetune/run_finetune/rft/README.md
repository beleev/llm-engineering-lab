# RFT：先让当前策略尝试，再用通过验证的轨迹教它

## 直觉

示范 SFT 由人提供正确路线；RFT 从模型自己的候选中挑合格路线，再做同一种监督 loss；在线 RL 根据当前采样的奖励直接改变动作概率。这里 RFT 指 rejection-sampling fine-tuning，不是某些产品命名中的 reinforcement fine-tuning。

## 核心原理

三个分支复制同一个小 LLaMA 初始化，复用 m32 的状态/动作编码和 m25 独立执行验证器。任务必须先 lookup 再回答观察值，偷看、乱答、超预算都不合格。

- SFT：16 条人工成功轨迹，拆成 32 个状态/动作样本，40 步 CE 更新。
- RFT：冻结采样策略，每个训练任务采 16 次，共 256 条；只保留 `eligible` 的轨迹，40 步 CE 更新。
- RL：每轮当前策略采 8 条，共 32 轮、256 条，组内均值基线和策略梯度更新。

RFT/RL 的候选数相同，优化步数和前向成本不同，不能声称算力预算完全公平。无成功候选时 `supervised([], ...)` 直接返回 0，参数不变；不能拿空 batch 算 loss，也不能暗中注入示范。

## 运行

```bash
python -m llm_finetune.run_finetune.rft.train_rft
```

## 运行后应该看到什么

seed=7 初始化、各分支 seed=101。RFT 在 256 次中保留 18 条，覆盖 10/16 个任务；六个任务没有被直接教到。三个分支的留出通过率均从 0 到 1，参数确实改变，RFT 并没有胜过 SFT/RL。

留出集实体名不与训练重合，但编码器只看协议状态和值域；没有把实体文本送入模型。因此这是协议迁移验收，不是实体语义泛化，也不是新数值/新任务泛化。报告保留数分布比单报最终 100% 更能看出选择偏差。

## 常见误区与自测

为什么奖励筛选不是策略梯度？因为筛选结果成为固定标签，更新仍是监督 CE。为何易题占比会越来越大？因为成功概率高的任务更容易留下候选。可以按任务分层、重采困难题、审计验证器，但不能通过放宽合格条件伪造收益。
