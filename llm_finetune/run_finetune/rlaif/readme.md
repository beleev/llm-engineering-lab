# RLAIF / Constitutional AI — 用 AI 反馈代替人工偏好标注

```bash
python -m llm_finetune.run_finetune.rlaif.train_rlaif    # ~7 s
```

## 直觉
RLHF 的偏好标签来自人: 贵、慢、标注员之间不一致, 有害内容还得有人一条条看。
Constitutional AI 的做法: 先把 "什么是好回答" 写成一份条文 ("宪法"), 再让一个 AI 反馈者按条文**批评**回答、**改写**回答。
改写前后的两个版本天然就是一个偏好对 (改写后 ≻ 改写前), 不需要人。之后的训练照旧用 DPO。
代价只有一句话: **标签的质量上限就是 judge 的质量上限**。

## 核心数据结构与控制流
- [`methods/rlaif.py`](../../methods/rlaif.py)
  - `CONSTITUTION`: 每条原则 = `Principle(名字, 条文, violated, fix)`。条文给人看, 真正生效的是后两个函数。
  - `critique(y)` → 批评列表;  `revise(y)` → 改写;  `violation_rate(ys)` → 各原则违规比例
  - `build_preference_pairs(prompts, responses)`: 只对被批评的回复造 (chosen = revise(y), rejected = y), 输出格式与 `PreferenceDataGenerator` 相同
  - `AIPreferenceData`: 偏好对只造一次 (一轮), DPO 每步从池子里随机取 batch
- 脚本 [`train_rlaif.py`](train_rlaif.py): `pretrained_base()` (照抄一切的 "只求有用" 模型) → 温度 1 采样 4096 条 → critique / revise → `PairwiseForward.with_frozen_copy` + 现成的 `DPOLoss` → 留出集 `evaluate`
- 玩具宪法: 「无害」不说脏话 15 (条文还写了 "以及变体 14"), 「隐私」不复述电话号码 13; 两条都要求用 *** (token 3) 代替。**规则 judge 只查了 15 和 13, 没查 14。**

## 核心公式
流程: `y ~ π(·|x)` → `c = critique(y)` → 若 c 非空: `y' = revise(y, c)`, 偏好对 `(x, y_w = y', y_l = y)`
训练: 与 DPO 完全相同 `L = −log σ(β·[(log π_θ(y_w) − log π_ref(y_w)) − (log π_θ(y_l) − log π_ref(y_l))])`
上限: 若 judge 对某类违规的检出率为 0, 这类违规在 y_l 里出现时 y_w 里也原样保留 —— 它对 loss 的贡献恒为 0, 训练对它**没有任何直接压力**。

## 运行后应该看到什么
4096 条采样中 judge 批评了 2539 条 → 2539 个偏好对。示例:
```
prompt   [4, 8, 12, 15, 13, 15]
回复     [4, 8, 12, 15, 13, 15]  ← ['违反「无害」: 位置 [3, 5]', '违反「隐私」: 位置 [4]']
改写后   [4, 8, 12, 3, 3, 3]
```
DPO β=0.5, lr=1e-4, 150 步, 留出 prompt 上贪心回复:

| 留出集 | DPO 前 | DPO 后 |
|---|---|---|
| 违反「无害」 | 0.367 | **0.008** |
| 违反「隐私」 | 0.398 | **0.023** |
| 违反任一原则 | 0.648 | **0.031** |
| 含变体 14 (judge 漏检) | 0.418 | 0.320 |
| 非敏感位置照抄率 (有用性) | 1.000 | 0.856 |
| 整条 = 理想回复 (照抄 + 打码) | 0.352 | 0.488 |

**如实解读**:
- judge 查得到的违规几乎清零 (0.648 → 0.031)。
- judge 漏检的变体 14 基本没动 (0.418 → 0.320)。降的那一点不是学会了原则, 是 DPO 的副作用: 第一个回复 token 常被带偏, 偶尔也把 14 打了码。宪法条文里写了 14, 没用 —— 生效的是规则。
- 有用性付出了代价: 该照抄的位置正确率 1.000 → 0.856, 错误集中在第一个回复 token。这是 DPO 的老毛病 (见 [dpo](../dpo/readme.md) 的 likelihood displacement), 不是 RLAIF 特有的。

## 诚实边界
- **AI 反馈的质量上限 = judge 的质量上限**。这里的 judge 是两行规则, 上限一眼可见; 换成 LLM judge, 漏检不会消失, 只是更难被发现。RLAIF 省掉的是标注成本, 不是 "定义什么是好" 的责任。
- **judge 造出的偏好对会带着系统性偏差, DPO 会学偏差而不是原则**。调参时宪法里有第三条「不啰嗦: 不要连说两遍」, 改写 = 删掉重复 → chosen 总比 rejected 短。DPO (β=0.5, lr=3e-4, 200 步, 1024 条采样) 学到的是 "早点说 EOS": 违规率 0.605 → 0.000, 但理想回复 0.395 → **0.000** —— 模型只说 1 个 token 就结束。lr 降到 1e-4 也一样。所以最终版本只保留了不改长度的原则。
- **lr 要比 dpo 脚本小**: 同样 3e-4 / 200 步 (1024 条采样) 时, 违规率同样降到 0, 但理想回复 0.352 → 0.051, 有用性几乎全毁。现在的 1e-4 / 150 步是在 "守规矩" 和 "还有用" 之间挑的。
- 只跑了一轮 (离线 DPO)。真实 RLAIF 常迭代多轮、或用 AI 偏好训 RM 再做 PPO; 这里没做。
- 批评和改写都是规则, 所以 "critique → revise" 在这里是确定性的; 真 CAI 里这两步是 LLM 生成, 改写本身也会出错。

## 常见误区
- "条文写得越全越好"。条文只是给人看的; 训练信号只来自 judge 真正检查的东西。
- "违规率降了 = 对齐成功"。同时要看有用性: 什么都不说也能 0 违规 (上面「不啰嗦」的例子几乎就是这样)。
- 把 judge 没批评的回复当成 chosen、随便配一个 rejected。没问题的回复没有 "更好的版本", 这里直接丢掉。

## 自测题
1. 为什么变体 14 的违规几乎不降? — judge 不查 14, 所以 14 在 chosen 和 rejected 里同时出现, 对 DPO 的 loss 没有贡献。
2. RLAIF 相比 RLHF 省掉了什么, 没省掉什么? — 省掉了逐条人工标注; 没省掉 "把好坏标准写对" 的工作, judge 错了训练就跟着错。
3. 如果改写总是让回答变短, DPO 会学到什么? — 很可能学到 "变短" 本身 (更早输出 EOS), 而不是原则。上面「不啰嗦」的调参记录就是这样。
