# GRPO / DAPO / Dr.GRPO / GSPO — 在线 RL + 可验证奖励

```bash
python -m llm_finetune.run_finetune.grpo.train_grpo    # ~31 s
```

## 直觉
同一个 prompt 采 G 条回复, 用程序判对错, 比组内平均好的就提高概率。组内均值就是 baseline, 不需要 critic; 判分是规则, 不需要 reward model。
奖励 = `task.verify`: 排序全对 (含 EOS) 得 1 分, 否则 0 —— **依赖 prompt**, 不看 prompt 的策略拿不到分 (像 "token 落在词表后半区" 这种不看 prompt 的奖励就测不出这一点)。

## 核心公式
`A_i = (r_i − mean_G r) / std_G r`，`ρ_t = π_θ(o_t)/π_old(o_t)`，`J = E[min(ρ_t A, clip(ρ_t, 1−ε_low, 1+ε_high) A)] − β·KL`
一批 rollout 更新 μ=2 次: 第 1 次 ρ≡1, 第 2 次起 ρ≠1, 裁剪才起作用。变体只是 `GRPOConfig` 的开关:

| 变体 | 改了什么 | 修的是什么 |
|---|---|---|
| DAPO | ε_high=0.28 > ε_low; 丢掉组内奖励全相同的 prompt; 按 token 平均 | 熵塌缩; A≡0 的样本白占 batch; 长回复的 token 被稀释 |
| Dr.GRPO | 不 ÷std; 不 ÷\|o_i\| (改 ÷ 常数 C) | ÷std 放大极难 / 极易题; ÷\|o\| 让答错的长回复每 token 受罚更轻 |
| GSPO | ρ 取序列级几何平均, 整条回复一起裁剪 | token 级 ρ 噪声大 |

## 运行后应该看到什么
确定性小实验 (每个变体改动的那一项单独量出来):
- (a) 题目权重 难题(1/8 对) / 中等题(4/8 对): GRPO **0.66**, Dr.GRPO **0.44**
- (b) 3-token 回复与 9-token 回复的单 token 权重比: seq_mean **3.0**, token_mean **1.0**, fixed_len **1.0**
- (c) T=0.5 采样的经验分布与 softmax(z/T) 的 TV 距离 0.000, 与 softmax(z) 的 0.039 → log-prob 必须带同一个 T

训练 (SFT 150 步起点; 32 prompt × G=8 × 60 步; lr=3e-4), **留出集**:

| | 贪心 EM | 采样 pass@1 | A≡0 的 prompt | 进 loss 的 A=0 样本 | \|ρ−1\| ep1 | \|ρ−1\| ep2 | std log ρ | 裁剪比例 |
|---|---|---|---|---|---|---|---|---|
| SFT 起点 | 0.562 | 0.186 | | | | | | |
| grpo | 0.531 | **0.287** | 32.1% | 32.1% | 0.000 | 1.037 | 0.0672 | 0.88% |
| dapo | 0.531 | **0.326** | 32.3% | **0.0%** | 0.000 | 0.750 | 0.0635 | 1.07% |
| dr_grpo | 0.535 | **0.324** | 32.4% | 32.4% | 0.000 | 0.934 | 0.0726 | 0.90% |
| gspo | 0.539 | **0.320** | 32.5% | 32.5% | 0.000 | 0.158 | **0.0270** | 3.49% |

**如实解读**: 60 步的 RL 把**采样**正确率从 0.19 提到 0.29–0.33 (RL 优化的正是它), 但贪心 EM 基本没动 (略降, 在 ±0.03 的评估噪声边缘)。这与文献一致: RLVR 主要是把 pass@k 挤进 pass@1, 而不是教会新能力。四个变体最终成绩的差别在噪声内 —— 它们的差异体现在上面那些可测的中间量上, 不要从这张表读出 "谁更强"。

## 常见误区
- **采样用温度 T, 算 log-prob 用 T=1**: ρ 的分母不再是行为策略, 第 1 个 epoch 就 off-policy。(c) 专门测这个。
- 每批只更新一次就说 "实现了 PPO clip": 那时 ρ≡1, clip 是死代码。看 `|ρ−1| ep1 = 0`。
- 以为 ρ=1 时梯度为 0: ∇ρ = ρ∇log π, 在 ρ=1 处就是普通策略梯度。
- 用贪心 EM 验收 RL: 看不到效果。应看采样 pass@1。
- 硬塞进通用 Trainer: 数据由当前策略采样, 且一批数据更新 μ 次, "取 batch → 更新一次" 的约定不成立。
- 本实现的动态采样只过滤不补采 (代码里有 `ponytail:` 注释), batch 会变小; DAPO 原版会继续采到凑满。

## 自测题
1. 一组 8 条回复全对, GRPO 从这组得到多少梯度? — 0 (A≡0)。DAPO 把它从 batch 里拿掉, 分母不再被它稀释。
2. 为什么 GSPO 的裁剪区间比 GRPO 小得多? — 序列级 ρ 是 C 个 token 比率的几何平均, 波动约小 √C 倍 (表中 std log ρ: 0.027 vs 0.067)。
3. seq_mean 聚合下, 一条答错的 9-token 回复和一条答错的 3-token 回复, 谁的每个 token 受罚更重? — 3-token 的, 重 3 倍 → 策略被鼓励 "错就错得长一点"。
