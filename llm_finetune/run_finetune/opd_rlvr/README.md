# OPD + RLVR — 在线蒸馏与可验证奖励: 先蒸馏再强化, 还是一起训

[llm_finetune 目录](../../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/finetune/onpolicy-distill)

## 直觉

在线蒸馏 (OPD) 和 RLVR 都让学生自己采样, 区别在于采完之后拿到什么信号:
- OPD: 老师在学生走到的每个位置给出整张词表的分布, 学生逐 token 最小化 reverse KL。信号稠密, 但学生学的是老师的分布, 老师采样时犯的错也一起学, 上限就是老师。
- RLVR: verifier 给整条回复一个 0/1 分。信号稀疏, 学生采不到对的回复时这道题没有梯度; 但奖励来自规则, 不以老师为上限。

两种信号放在一起有三种用法: 先 OPD 再 RLVR、把两种损失加在同一个 loss 里联合训练、多位领域老师按领域分工打分。本脚本在 sort 任务上把这几种用法并排跑一遍。

## 核心原理

### 两种损失

- OPD (`methods/on_policy_distill.py`): $y \sim \pi_s(\cdot|x)$ 在 no_grad 下采样, $L_{\text{OPD}} = \mathrm{mean}_t\, \mathrm{KL}(\pi_s(\cdot|x,y_{<t}) \,\|\, \pi_t(\cdot|x,y_{<t}))$。
- RLVR (`methods/grpo.py`): 同一 prompt 采 G 条, $A_i = (r_i - \mathrm{mean}\, r)/\mathrm{std}\, r$, PPO 式 ratio + clip。
- 联合 (`joint_steps`): 同一批 GRPO rollout 上, 每个 token 的 loss = $-\text{surrogate}_t + \lambda \cdot \mathrm{KL}_t$, λ=1, 按 GRPO 的方式聚合, 一次反传, 一个 lr。
- 先 OPD 再 RLVR (`combine` 里的第三臂): 前一半步数只跑 OPD, 后一半只跑 RLVR, 两段各用自己的 lr 和一个新的 AdamW。

### 文献里的结论

- Thinking Machines "On-Policy Distillation" (Kevin Lu 等, 2025-10-27): 学生采样, 老师逐 token 打分, 把逐 token reverse KL 当作折扣为 0 的稠密奖励。博客引用 Qwen3 技术报告的数字: RL 用 17,920 GPU 小时把 AIME24 训到 67.6, 在线蒸馏用 1,800 GPU 小时到 74.4。
- "Sequential Beats Joint" (arXiv 2609.04108, Boyan Li 等, 2026-09): 先 OPD 再 RL 稳定优于纯 OPD、纯 RLVR 和各种联合基线。解释是 OPD 扩大学生的覆盖范围, RL 在覆盖范围内锐化, 联合优化时两者互相干扰; 建议用 OPD 的验证分数决定何时切到 RL。
- "Beyond GRPO and On-Policy Distillation" (arXiv 2605.12483, Yuanda Xu 等, 2026-05): 稀疏奖励适合能自己探索的模型, 稠密的老师 token 级监督适合把能力压缩进小模型。Qwen3-1.7B 上 "老师 RL → forward-KL 预热 → OPD" 的流程 MATH 79.3、AIME24 25.2, 直接 GRPO 是 75.9、19.8。
- MiMo-V2-Flash 技术报告 (arXiv 2601.02780, 2026-01): 通用 SFT 之后先训各领域老师, 再做多教师在线蒸馏 (MOPD), 按 prompt 所属领域选老师给逐 token 奖励, 同时叠加可验证的结果奖励。

### 多教师路由

`MixTask` 用 prompt 末尾的分隔符区分子任务 (SEP 做 sort, CPY 做 copy)。`RoutedTeacher` 是一个 `nn.Module`: 按每条序列的分隔符, 把它交给对应领域的老师打分。它的接口和单个老师一样, 所以 `on_policy_distill_step` 一行不用改。

## 运行

python -m llm_finetune.run_finetune.opd_rlvr.train_opd_rlvr    # 单线程 CPU 约 2 分钟

## 运行后应该看到什么

学生起点: sort 上 SFT 150 步, 留出集采样 pass@1 0.186、贪心 EM 0.562 (与 grpo 脚本同一个起点)。每臂 160 步, 每步 256 条学生 rollout。

**弱老师 (SFT 250 步)**, 留出集:

| | 采样 pass@1 | 贪心 EM | KL(学生‖老师) |
|---|---|---|---|
| 老师 | 0.547 | 0.836 | 0 |
| 学生起点 | 0.186 | 0.562 | 0.3115 |
| 只 RLVR | 0.486 | 0.617 | 0.1782 |
| 只 OPD | 0.494 | **0.789** | **0.0637** |
| 先 OPD 再 RLVR | **0.584** | 0.727 | 0.1206 |
| 联合 lr=3e-4 | 0.436 | 0.648 | 0.1332 |
| 联合 lr=1e-3 | 0.547 | 0.707 | 0.1088 |

- 先 OPD 再 RLVR 的 pass@1 最高, 而且超过了老师自己 (0.584 vs 0.547): 后 80 步的奖励来自 verifier, 不以老师为上限。
- 只 OPD 离老师最近 (KL 0.064), 贪心 EM 也最高, 但 pass@1 停在老师以下: 它学的是老师的分布, 包括老师采样时的错。
- 联合训练低于先后训练。lr=3e-4 时 (0.436) 还低于只 RLVR 和只 OPD; lr 提到 1e-3 后 (0.547) 追上了单项, 仍低于先后训练。
- 手动把各臂的种子从 1 换成 2、3 各跑一次 (学生和老师不变), pass@1 依次为: 只 RLVR 0.486 / 0.471 / 0.506, 只 OPD 0.494 / 0.496 / 0.500, 先 OPD 再 RLVR 0.584 / 0.564 / 0.605, 联合 lr=3e-4 0.436 / 0.457 / 0.469, 联合 lr=1e-3 0.547 / 0.559 / 0.521。先后训练三次都最高; 它和联合 lr=1e-3 的差距在种子 2 上只有 0.005, 三次平均 0.584 vs 0.542。

**强老师 (SFT 800 步)**, 只比两臂:

| | 采样 pass@1 | 贪心 EM | KL(学生‖老师) |
|---|---|---|---|
| 老师 | 0.977 | 0.992 | 0 |
| 学生起点 | 0.186 | 0.562 | 1.2746 |
| 只 OPD | **0.818** | **0.941** | **0.1360** |
| 先 OPD 再 RLVR | 0.678 | 0.836 | 0.3624 |

- 结论反过来了: 老师远强于学生时, 80 步的 OPD 还没把老师学完, 这时切到 RLVR 是把稠密信号换成了稀疏信号。什么时候切换要看 OPD 还有没有在涨, 不是固定一半。

**多教师 OPD** (MixTask: 分隔符 SEP 做 sort, CPY 做 copy), 各 100 步, 留出集采样 pass@1:

| | sort | copy |
|---|---|---|
| sort 老师 | 0.986 | 0.000 |
| copy 老师 | 0.000 | 0.994 |
| 学生起点 | 0.055 | 0.346 |
| 单老师 (sort) | 0.436 | **0.000** |
| 多教师路由 | **0.637** | **0.904** |

- 只用 sort 老师时, 它在 copy 样本上也按 sort 打分, 学生的 copy 能力从 0.346 被压到 0。
- 按分隔符路由后两个子任务都涨, 而且 sort 也比单老师高 (0.637 vs 0.436): copy 样本上的错误分布不再拖累共享参数。
- 第二个子任务最初试的是 reverse: 学生在混合数据上 SFT 150 步后 reverse 的 pass@1 是 0, 路由 OPD 100 步后仍不到 0.01。学生自己一条对的都采不出来时, 老师在这些前缀上的逐 token 分布也很难把它拉起来。这一组没有放进脚本。

断言:
1. 弱老师: 先 OPD 再 RLVR 的 pass@1 高于只 OPD、只 RLVR 和两个 lr 的联合。
2. 弱老师: 先 OPD 再 RLVR 的 pass@1 高于老师。
3. 弱老师: 只 OPD 的 pass@1 不超过老师, KL(学生‖老师) 是各臂里最小的。
4. 强老师: 只 OPD 的 pass@1 高于先 OPD 再 RLVR。
5. 多教师: 单老师的 copy pass@1 低于学生起点; 路由的 copy 比单老师高 0.5 以上, sort 也更高。

## 与真实系统的差距

- **老师和学生同结构**: 老师只是同一个 2 层 d=64 的小模型多训了几步 (弱老师 250 步, 强老师 800 步)。真实 OPD 的老师比学生大一个量级, 老师的覆盖范围和学生的容量差都比这里大。
- **单种子, 每臂一次**: pass@1 用 512 个留出 prompt 估, 标准误约 0.02。表里相差不到 0.04 的两个数分不出高下。
- **切换点固定在一半**: "Sequential Beats Joint" 建议看 OPD 的验证分数决定何时切到 RL。脚本只测了 "第 80 步切换" 一个点, 强老师那组说明这个点并不总是对的, 但没有扫切换点。
- **联合臂只扫了 lr**: λ 固定为 1, KL 项算在 GRPO 的 32 个 prompt × 8 条样本上, 而只 OPD 那一臂每步是 256 个不同的 prompt。lr 从 3e-4 提到 1e-3 就把联合臂从 0.436 拉到 0.547, 说明它的差距有一部分来自配置; 换 λ、换 KL 项的样本来源之后差距还剩多少, 这里没有测。
- **多教师只有两个领域, 老师按行全部前向**: `RoutedTeacher` 让两位老师都对整批前向再按行挑, 算力翻倍。真实系统按领域分批, 每条样本只调一位老师。MiMo-V2-Flash 的 MOPD 还在逐 token 的老师奖励之外叠加了可验证的结果奖励, 这里没有叠加。
- **奖励是 0/1 的规则判分, 回复最长 9 个 token**: 真实推理任务的回复是一长段推理, 老师在学生的长前缀上打分越往后越不可靠。

## 常见误区

- 把 OPD 当成 "更好的 RL": OPD 学的是老师的分布, 老师在采样时犯的错学生也会学; 想超过老师得靠 verifier 一类不以老师为上限的信号。
- 认为两种损失加在一起总比先后好: 两项梯度方向不一致时会互相拖累, 本例联合臂低于任一单项。
- 认为 "先 OPD 再 RLVR" 无条件更好: 老师远强于学生、OPD 还没学到头时就切到 RLVR, 是把稠密信号换成稀疏信号。
- 多领域学生只找一位最强的老师: 老师没见过的领域, 它给的逐 token 分布会把学生往错的方向拉。

## 自测题

1. 弱老师那组里, 为什么只 OPD 的学生 pass@1 没有超过老师, 先 OPD 再 RLVR 却超过了? — **答**: OPD 的目标是让学生的分布贴近老师, 老师自己的 pass@1 就是这条路的天花板; RLVR 的奖励来自 verifier, 学生采到比老师更好的回复也会被奖励。
2. 联合训练和先后训练用的是同样的两种信号, 为什么结果不同? — **答**: 联合训练每一步同时朝两个方向推: KL 项把学生拉向老师的分布 (包括老师的错), RL 项朝 verifier 锐化; 先后训练让两种信号各自在适合的阶段起作用。
3. 两位领域老师各只懂一个子任务, 为什么要按 prompt 路由, 而不是只用 sort 老师? — **答**: sort 老师没见过 copy 的分隔符, 它在 copy 样本上给的分布是 "按 sort 来写", 学生会被教坏; 路由让每条样本都由懂这个领域的老师打分。
