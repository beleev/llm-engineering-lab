# 在线偏好：更新后还符合谁的偏好

## 直觉

策略变了，采到的回答也会变。持续学习需要重新收集偏好，同时防止把“用户爱听”学成“事实可以错”。

## 核心原理

本例从当前策略采样回答对，按反馈选择 chosen/rejected，再实际执行单 token DPO 梯度。中途改变一个用户的长短偏好，比较离线数据与在线更新。

偏置裁判奖励错误但讨好的回答；核验裁判先判事实，再比较表达风格。报告正确率、风格满足率和迎合概率，不能只看裁判奖励。对拒答也要区分必要拒答与无谓回避。

每用户独立参数只是个性化的一种隔离基线，不代表共享模型已解决持续学习。共享适配器还需用户隔离、旧偏好回放、撤销记录与跨用户泄漏检查；反馈循环会有曝光偏差。

## 运行

```bash
python -m llm_finetune.run_finetune.online_preference.demo
```

需要 Python ≥ 3.10，依赖使用仓库的 numpy / torch；不需要模型 API。网页在现有章节中提供同一实验的执行记录回放。

## 怎样验证

固定随机种子和交互预算，比较偏好变化前后各用户指标。模型层迎合与有意欺骗不能只由一个错误答案判定，需要可核验的任务行为和多个条件。

## 与真实系统的差距

有限动作上的实际 DPO 梯度更新，评审器是公开规则，不是人工偏好或真实 LLM Judge。奖励规则与部署验收应独立审计。
