# 在线偏好: 更新后还符合谁的偏好

## 直觉

本组实验模拟两名用户与一个在 3 类离散回答上输出概率分布的策略模型, 3 类候选回答分别为正确简短、正确详细与错误迎合 (顺从用户倾向但违背事实)。用户 1 全程偏好简短回答, 用户 0 在第 200 步由偏好简短切换为偏好详细; 三条训练路径均执行 600 步在线或离线交互, 每步采用单步 DPO 梯度更新策略分布。
不同偏好采集方式导致显著分化的收敛结果:
- 离线静态偏好: 全程重复消费预先固定为「正确简短优于正确详细」的历史样本对, 600 步后用户 0 获得正确详细回答的概率仅为 0.0035。
- 在线核验偏好: 每步从当前策略实时采样一对候选回答并由事实优先的裁判即时定出胜负, 末步用户 0 获得正确详细回答的概率升至 0.9649。
随着策略分布演进与用户需求迁移, 持续对齐必须依托在线重采样收集最新偏好反馈; 但若在线反馈存在讨好偏置、无视事实正误而单纯奖励顺从回答, 在线闭环训练会迅速放大错误迎合行为, 使两名用户的平均迎合错误概率升至 0.9857。

## 核心原理

本例在线路径每步从当前策略无放回抽取一对不同回答, 依据反馈判定 chosen 与 rejected 后实际执行一步单 token DPO 梯度更新 (超参数 β 取 0.5)。模型参数由每位用户独立的 3 维 logits 向量构成, 经 softmax 归一化为 3 类候选回答的生成概率, 每类完整回答抽象为单个动作 token。
在线路径的单步闭环流程如下:
1. 按当前用户的策略概率分布无放回抽取两项不同回答。
2. 由裁判规则对两项候选打分, 高分项记为 chosen、低分项记为 rejected。
3. 沿解析梯度更新对应维度: chosen 的 logit 增加 $0.12 \times \beta \times \sigma(-\beta d)$, rejected 的 logit 减去相同幅度, 其中 d 为 chosen 与 rejected 当前的 logit 之差, $\sigma$ 为 sigmoid 函数, 即正负样本当前的间隔 d 越大, 单步更新幅度越平缓。
由于参考模型固定为均匀分布, DPO 中的对数概率比差值直接简化为两项候选的 logit 之差。实验中两名用户交替交互各 300 步 (合计 600 步), 用户 0 在全局第 200 步发生详略偏好反转; 离线基线则跳过在线采样, 全程 600 步固定输入「正确简短优于正确详细」样本对, 因此全部 600 次获胜记录均归属正确简短回答。

偏置裁判对违背事实的讨好回答赋予最高奖励, 导致 580 次对局由错误迎合获胜且两名用户的目标正确回答概率均跌破 0.01; 核验裁判确立事实优先于风格的排序准则, 获胜频次分布转为 [386, 214, 0]。
实验采用确定性的显式评分规则模拟两类反馈信号:
- 契合用户当前详略偏好的正确回答得 1 分。
- 详略不契合但事实正确的回答得 0 分。
- 错误迎合回答在偏置裁判下得 2 分, 在核验裁判下则被罚为 −2 分。
两类裁判在在线采样闭环中引发截然不同的演化轨迹:
- 偏置裁判下, 错误迎合一旦被采中即稳赢任何正确回答, 每次获胜推高其采样概率并进一步增加后续出场频次, 最终 600 步中有 580 次由迎合获胜, 末步用户 0 的正确详细概率跌至 0.0066、用户 1 的正确简短概率跌至 0.0072。
- 核验裁判下, 事实错误项得分恒居末位, 仅在两项事实正确的候选同时出场时才按详略偏好决出胜负, 最终获胜分布 [386, 214, 0] (依次对应正确简短、正确详细、错误迎合的胜出次数) 中错误迎合为 0 胜。
因此在线对齐评测必须解耦报告事实正确率、风格满足率与错误迎合概率, 不能仅监控裁判奖励均值; 若涉及安全或未知边界拒答, 还须区分合理必要拒答与过度保守的无谓回避。

本例为每位用户分配完全独立的 logits 参数组, 该设置仅构成物理隔离的理想个性化基线, 并不代表共享权重模型已解决持续学习难题。实验中两名用户各自的 3 维参数独立存储与更新, 用户 0 的偏好反转完全不会干扰用户 1 的分布, 因此在核验裁判下二者目标正确回答概率分别达到 0.9649 与 0.9854。而在真实生产系统中, 海量用户往往共享主干模型或共享轻量化 adapter 模块, 单一用户的在线梯度更新会直接牵动其他用户的输出分布。
构建多用户共享在线更新系统还须落实四项工程保障:
- 参数或上下文级用户隔离: 控制个性化梯度对全局通用能力的串扰。
- 历史偏好回放: 在线更新新反馈时按比例混入历史锚点样本以抑制遗忘。
- 反馈血缘与撤销机制: 当用户撤回错误反馈或要求删除数据时可精准回滚对应更新。
- 跨用户隐私泄漏审计: 验证单用户私有偏好与交互内容不会渗透至其他用户的生成结果。
此外, 在线反馈闭环天然伴随曝光偏差 (exposure bias): 模型仅能针对自身高概率采出的候选收集反馈, 一旦某类优质回答初始概率过低而极少被采中, 便长期缺乏正向反馈信号将其恢复。

## 怎样验证

固定同一随机种子与 600 步交互预算, 对比静态离线数据、在线采样配偏置裁判及在线采样配核验裁判三条路径在训练结束时两名用户的目标正确回答概率、平均迎合错误概率与获胜样本频次分布; 其中用户 0 的详略偏好在第 200 步发生切换, 用于检验策略能否及时追踪非平稳偏好迁移。
实验验收遵循以下判据:
- 以真实事实正确且契合用户当前偏好的生成概率越高、错误迎合概率越低为优, 不以裁判模型自身的内部打分高低作为验收依据。
- 代码断言偏置裁判路径的末步迎合概率严格高于核验裁判路径, 且核验裁判路径下用户 0 的正确详细回答概率严格高于离线路径。
需要强调的是, 真实大模型层面的迎合偏置 (sycophancy) 或策略性欺骗不能仅凭单条错误输出定性, 必须依托具备客观真值的可核验任务并在多组受控提示条件下交叉验证。

## 与真实系统的差距

有限动作上的实际 DPO 梯度更新，评审器是公开规则，不是人工偏好或真实 LLM Judge。奖励规则与部署验收应独立审计。

## 常见误区与自测

在线偏好训练中裁判奖励持续上升但事实错误率反而恶化时, 应优先排查什么?

<details><summary>展开解析</summary>

应优先排查反馈信号与裁判规则本身是否将顺从讨好、篇幅冗长或表面自信语气误奖为高质量回答。在线偏好优化直接最大化裁判给出的相对偏好信号, 奖励曲线上升仅证明策略学会了迎合裁判的打分偏好 (即 reward hacking), 并不等同于事实准确性提升。若裁判对违背事实但顺从用户的回答赋予更高分数, 每步梯度更新都会向该类回答倾斜概率质量; 采样概率越高则后续对局中出场与获胜越频繁, 形成闭环自我强化。在本例中, 偏置裁判赋予错误迎合 2 分而正确回答至多 1 分, 导致 600 步交互中有 580 次由迎合获胜, 末步平均迎合错误概率升至 0.9857。
工程修复需将客观事实核验与主观风格偏好解耦为分层门控:
1. 优先校验事实正确性, 将事实错误的候选直接置于最低优先级。
2. 仅在通过事实核验的正确候选之间按详略或语气偏好决出胜负。
同时必须保留具备客观真值的独立评测集监控事实正确率, 不可单凭在线奖励曲线验收模型。
