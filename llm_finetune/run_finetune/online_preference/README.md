# 在线偏好: 更新后还符合谁的偏好

## 直觉

这组实验模拟两个用户和一个只会从 3 种回答里挑一种的小模型, 3 种回答是正确简短、正确详细、错误迎合 (顺着用户说但事实是错的); 模型给每种回答一个概率, 这组概率叫策略。用户 1 一直偏好简短, 用户 0 在第 200 步改成偏好详细; 三种训练方式都更新 600 步, 每一步用 DPO (拿「A 比 B 好」的成对数据, 直接调高 A 的概率、调低 B 的训练方法) 改一次策略。
两种偏好来源的结果:
- 离线偏好是反复用一份事先采好的旧数据, 它只说「简短胜详细」, 训完用户 0 拿到详细正确回答的概率只有 0.0035。
- 在线偏好是每一步从当前策略重新采一对回答、当场判胜负, 配上先核验事实的裁判后, 这个概率是 0.9649。
策略变了, 采到的回答也会变, 持续学习要重新收集偏好; 但如果反馈有偏置, 只奖励讨好用户, 在线训练会把「用户爱听」学成「事实可以错」, 两个用户平均的迎合错误概率升到 0.9857。

## 核心原理

本例每步从当前策略采一对回答, 按反馈定 chosen/rejected, 再实际执行一步单 token DPO 梯度 (β = 0.5)。模型的全部参数是每个用户 3 个数 (logits), softmax 把它们换算成 3 种回答的概率, 数越大概率越高; 每个回答相当于一个 token, 所以叫单 token DPO。
在线路径每一步:
1. 按当前概率抽两种不同的回答。
2. 裁判打分, 分高的当 chosen (胜者)、分低的当 rejected (败者)。
3. 胜者的 logit 加一点、败者的减一点, 加减的量是 0.12 × β × σ(−β × d), d 是胜者与败者的 logit 差, σ 是 sigmoid 函数, 这个式子在说两者差距已经拉得越大, 这一步改得越少。
这里的参考模型是均匀分布, 所以 DPO 里的 log-ratio 差就等于两个 logit 之差。两个用户轮流交互, 各 300 步, 用户 0 在全局第 200 步改长短偏好; 离线路径不采样, 每一步都拿「正确简短胜正确详细」这一对来训练, 所以离线路径 600 次获胜全是「正确简短」。

偏置裁判给错误但讨好的回答最高奖励, 580 次获胜都是迎合, 两个用户的正确回答概率都掉到 0.01 以下。核验裁判先判事实再比风格, 获胜分布 [386, 214, 0]。
裁判是一条写死的公开打分规则:
- 符合用户当前长短偏好的正确回答得 1 分。
- 另一种正确回答得 0 分。
- 错误迎合在偏置裁判下得 2 分, 在核验裁判下得 −2 分。
两种裁判的结果:
- 偏置裁判下迎合只要被采到就赢, 每赢一次它的概率更高、下次更容易被采到, 结果 600 次里 580 次胜者是迎合, 用户 0 详细正确回答概率 0.0066, 用户 1 简短正确回答概率 0.0072。
- 核验裁判下错误回答永远垫底, 两个正确回答之间才按风格比, 获胜分布 [386, 214, 0] (依次是正确简短、正确详细、错误迎合当胜者的次数) 里迎合一次都没赢。
所以要报告正确率、风格满足率和迎合概率, 不能只看裁判奖励; 拒答也要分必要拒答 (确实不该答) 和无谓回避 (能答却不答)。

本例每个用户一组独立 logits, 这只是个性化的隔离基线, 不代表共享模型已经解决持续学习。两个用户的 3 个数分开存、分开更新, 用户 0 改口味碰不到用户 1 的参数, 所以核验裁判下两人能各自达到 0.9649 和 0.9854。真实系统里很多用户共用一个模型或一个适配器 (挂在基座上的少量可训练参数), 一个用户的更新会改到别人。
共享适配器还要做到:
- 用户隔离。
- 旧偏好回放 (训练新数据时混进一部分旧偏好, 防止忘掉)。
- 撤销记录 (用户收回反馈时能找到并撤掉它的影响)。
- 跨用户泄漏检查 (一个用户的偏好或数据不出现在别人的回答里)。
反馈循环还带着曝光偏差: 模型只会收到它自己采出来的回答的反馈, 很少被采到的回答几乎得不到反馈, 也就很难翻身。

## 怎样验证

三条路径 (固定离线数据、在线加偏置裁判、在线加核验裁判) 用同一个随机种子和同样 600 步交互预算, 比较训练结束时两个用户的正确回答概率、迎合错误概率和获胜样本分布 (每种回答当胜者的次数); 用户 0 的偏好在第 200 步改变, 它的读数检查的是策略能不能跟上变化后的偏好。
判定方法:
- 用户想要的正确回答概率越高、迎合错误概率越低越好, 裁判给的奖励本身不算数。
- 代码断言偏置裁判的迎合概率高于核验裁判, 且核验路径的用户 0 详细正确回答概率高于离线路径。
模型层的迎合和有意欺骗不能只由一个错误答案判定, 要有可核验的任务行为和多个条件。

## 与真实系统的差距

有限动作上的实际 DPO 梯度更新，评审器是公开规则，不是人工偏好或真实 LLM Judge。奖励规则与部署验收应独立审计。

## 常见误区与自测

在线偏好奖励上升却更常答错, 优先检查什么?

<details><summary>展开解析</summary>

先查反馈本身: 它可能把讨好、冗长或自信当成正确。在线训练优化的是裁判给的奖励, 奖励上升只说明模型越来越会拿裁判的高分, 不说明答得更对。如果裁判给错误但讨好的回答更高分, 每次更新都会把概率往这种回答上挪; 挪得越多它越常被采到、越常获胜, 形成自我强化。本例偏置裁判给错误迎合 2 分、正确回答最多 1 分, 结果 600 次里 580 次胜者是迎合, 迎合错误概率升到 0.9857。
修法是把事实核验和风格偏好拆开:
1. 先判对错, 错的直接垫底。
2. 再在正确回答之间比风格。
还要在独立样本上检查正确率, 不只看奖励曲线。
