# 模型合并 — Task Arithmetic / TIES / DARE / SLERP

```bash
python -m llm_finetune.run_finetune.merge.train_merge    # ~9 s
```

## 直觉
两个团队从同一个基座各微调了一个模型: 一个会 A, 一个会 B。想要一个两样都会的模型, 老办法是把两份数据合起来重训 (要数据、要算力), 或者部署两份权重。
合并的办法: 把 "微调改了什么" 看成一个向量 τ = θ_微调 − θ_基座, **不训练**, 直接在权重空间里把两个 τ 加回基座。几秒钟, 不需要任何数据。
加法会不会互相踩? 这就是 TIES / DARE 想修的 "干扰"。

## 核心数据结构与控制流
- 输入输出都是 `state_dict`, 不碰模型结构: [`methods/merge.py`](../../methods/merge.py)
  - `task_vectors` → τ_t;  `task_arithmetic` → θ₀ + λΣτ;  `ties_merge` → 修剪 / 选符号 / 不相交平均;  `dare` → 随机丢弃 + 重缩放;  `slerp` → 两个完整模型逐张量球面插值;  `sign_conflict` → 干扰度量
- 脚本 [`train_merge.py`](train_merge.py): `pretrained_base()` (会 copy) → 两次全参微调 (`EditTask`) → 各方法在验证集上挑 λ → 留出集打分 (`scores`)
- 两个任务都是 "copy, 但改写一段 token": **A** = 低段 3–8 各 +1, **B** = 高段 10–15 各 −1。每个任务的训练数据里, 另一段照抄。

## 核心公式
- 任务向量 `τ_t = θ_t − θ₀`;  Task Arithmetic `θ = θ₀ + λ·Σ_t τ_t` (λ = 1/T 就是简单平均)
- TIES: ① 每个 τ 只留 |·| 最大的 density 比例 ② `γ = sign(Σ_t τ̂_t)` ③ 每个坐标只对 "非零且与 γ 同号" 的任务取平均; `θ = θ₀ + λ·τ_m`
- DARE: `τ̃ = m ⊙ τ / (1−p)`, `m ~ Bernoulli(1−p)`, 期望不变; 之后照常做 Task Arithmetic
- SLERP: `sin((1−t)Ω)/sinΩ · θ_A + sin(tΩ)/sinΩ · θ_B`; t=0.5 时恰为线性平均 × `1/cos(Ω/2)`

## 运行后应该看到什么
全参微调 300 步、lr=1e-3; λ ∈ {0.5, 0.7, 1, 1.5} 按验证集 (训练分布的 prompt) 上的两段全对 EM 挑, 下表全是**留出集**:

| | λ | A 段准确率 | B 段准确率 | 两段全对 EM | 干扰 (相对单任务模型的平均掉点) |
|---|---|---|---|---|---|
| 基座 | – | 0.000 | 0.000 | 0.000 | – |
| 只微调 A | – | 1.000 | 0.000 | 0.004 | – |
| 只微调 B | – | 0.000 | 1.000 | 0.027 | – |
| 简单平均 | 0.5 | 0.423 | 0.616 | 0.039 | 0.480 |
| **Task Arithmetic** | 1 | **1.000** | **1.000** | **1.000** | **0.000** |
| TIES d=0.5 | 1.5 | 0.947 | 0.948 | 0.734 | 0.053 |
| DARE p=0.5 | 1 | 1.000 | 0.955 | 0.875 | 0.023 |
| DARE p=0.9 | 0.7 | 0.584 | 0.573 | 0.066 | 0.422 |
| SLERP t=0.5 | – | 0.510 | 0.739 | 0.090 | 0.376 |

`‖τ_A‖ 6.50, ‖τ_B‖ 6.43, cos(τ_A, τ_B) = +0.046`, 两者都非零的坐标里符号冲突 47.4% —— 几乎正交, 冲突却接近一半 (随机符号就是 50%)。
θ_A 与 θ_B 的夹角 Ω = 0.333 rad, SLERP 只比线性平均放大 1.014 倍。

**结论**: 两个单任务模型都做不了 "两段一起改写" (EM ≤ 0.027); 直接把两个 τ 加回基座 (λ=1) 就全对。
简单平均 = 每个 τ 只加一半, 两段都只改到一半。SLERP 在完整权重上插值, 两个模型共享 θ₀ 所以夹角小, 结果 ≈ 简单平均。
TIES、DARE p=0.5 **没有赢过**调好 λ 的 Task Arithmetic; DARE p=0.9 基本失效。另换两个种子 (1、2): Task Arithmetic EM 0.973 / 0.617, 仍是最高; TIES 0.695 / 0.211, DARE p=0.5 0.953 / 0.473。

## 诚实边界
- **能合并, 是因为任务这么设计**。A 的数据里高段照抄, 所以 τ_A 只被要求改 "低段怎么输出", 两个任务在函数上几乎不重叠 —— 这是 task arithmetic 的前提。调参时试过两种不满足前提的设置:
  - 同一输入要两种输出 (加任务标记 token 的 reverse vs sort): 所有方法合并后都没有明显好于基座。同一个输入不可能同时有两个正确答案, 哪种合并都救不了。
  - 按输入分段 (A 只见低段 prompt、B 只见高段 prompt, 都做 ±1 平移): 两个 τ 各自学成了**全局的** "+1" / "−1", 加起来互相抵消。LoRA r=4 时 3 个种子上 Task Arithmetic 的单任务 EM 从 0.01 到 0.68 不等。
- **TIES / DARE 的收益在玩具规模上看不到**。TIES 要修的是 "大量小幅度、冗余的坐标相互冲突"; 这里 τ 是约 10 万参数的全参更新, 修剪掉一半就伤到了真正有用的坐标。DARE 论文 "丢 90% 几乎无损" 依赖大模型任务向量的高度冗余, 这里丢 90% 两段全对 EM 掉到 0.066 (脚本对此设了断言)。
- **λ 要调**: 表里每个方法都在验证集上挑过 λ, 这才是公平比较。只看 λ=0.5 (简单平均) 会以为 "合并没用"。
- 只合并了 2 个任务。任务越多, τ 之间的冲突越多, TIES 这类方法的价值才可能显现, 这里没测。

## 常见误区
- "合并 = 平均权重"。平均是 λ=1/T 的特例, 任务数一多每个 τ 被稀释到 1/T。
- 以为 cos(τ_A, τ_B) ≈ 0 就没有冲突。本例 cos = 0.046, 符号冲突仍有 47%: 正交说的是整体, 冲突说的是逐坐标。
- 从不同基座 (或不同随机初始化) 出发的两个模型也拿来做 task arithmetic: τ 的定义就要求同一个 θ₀。

## 自测题
1. λ=0.5 的 Task Arithmetic 和两个模型取平均是什么关系? — 完全相同: θ₀ + 0.5(τ_A+τ_B) = (θ_A+θ_B)/2。
2. DARE 为什么要除以 (1−p)? — 让 E[τ̃] = τ; 不除的话等价于把 λ 缩小到 (1−p) 倍。
3. TIES 第 ③ 步如果改成对所有任务求平均 (不管符号), 会怎样? — 冲突坐标上两个任务互相抵消, 退化成修剪过的简单平均, 这正是 TIES 想避免的。
