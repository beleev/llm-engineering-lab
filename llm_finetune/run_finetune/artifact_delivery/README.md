# 模型交付: 新进程里还是同一个模型吗

## 直觉

本组实验将一个训练完毕的微型模型打包为标准交付产物, 随后在完全隔离的全新 Python 子进程中加载, 检验跨进程恢复出的实例是否仍与原模型等价。端到端一致性核验覆盖三项输出:
- 输入文本编码后的 token ID 序列。
- 前向传播输出的 logits 张量。
- Greedy 解码生成的完整序列。

三组对照实验结果如下:
- 完整 FP32 权重交付: 三项输出完全一致, logits 最大绝对误差为 0.0。
- int8 对称量化压缩再反量化还原: token 编码与 greedy 生成结果保持一致, logits 最大绝对误差为 0.008654。
- 词表错配注入: 对调词表中 a、b 两个 token 的顺序并同步更新文件 sha256 摘要后, 新进程依靠语义约定校验直接拒绝加载。

模型权重本身只是数值张量, 分词词表、对话模板与解码停止条件等上下文契约必须随权重一并封装交付, 并在加载入口强制核对。

## 核心原理

完整的模型交付包必须自包含全部结构、分词与解码契约, 使接收方无需任何外部口头说明即可在独立环境中复现同一模型行为。产物包需捆绑三层核心元数据:
- 模型架构配置: 定义网络层数、隐藏层维度与注意力头数, 用于实例化计算图以挂载参数权重。
- 输入编码契约: 包含完整词表、特殊控制标记 (如 bos 与 eos) 以及对话角色拼接模板, 确保相同文本映射为完全一致的 token 序列。
- 生成与血缘元数据: 记录默认解码参数 (最大生成长度、采样策略)、基座模型标识 (本例为 tiny-llama-seed21) 以及权重存储精度格式 (FP32 或 int8)。

此外还需按交付用途区分附加状态:
- 断点续训交付: 必须额外保存优化器动量状态与随机数生成器 (RNG) 状态。
- 在线推理交付: 必须通过跨进程回归测试证明加载端的输入解析与导出端严格对齐。

产物等价性验证必须在脱离训练内存状态的全新进程中执行端到端前向与解码比对。本实验的验证流水线共分四步:
1. 训练一个微型 LLaMA 架构模型 (词表容量为 8 个 token, 网络深度为 1 层) 共 25 步。
2. 将权重与配置序列化导出为磁盘交付包。
3. 通过 subprocess 拉起独立的 Python 子进程读取该交付包。
4. 在导出进程与新加载进程中分别对同一输入 ab 执行推理, 逐项核对:
   - 分词所得的 token ID 序列是否完全一致。
   - 输出 logits 的最大绝对偏差是否落在预设容差内。
   - Greedy 解码生成的 token 序列是否完全一致。

int8 对照组在导出时按各权重张量的最大绝对值线性缩放映射为 -127 至 127 区间的整数, 加载时再乘回缩放因子反量化为浮点数, 实测 logits 最大误差 0.008654 反映了该次伪量化往返截断误差 (预设验收容差阈值为 0.15)。实验边界: 反量化后的矩阵运算仍在浮点张量上执行, 未调用底层整数算子核, 因此本实验不能用于推断 int8 推理加速比。

单文件哈希摘要仅能校验存储传输过程中的比特完整性, 无法在摘要本身被同步重算时认证语义配置未被篡改。本实验构造了词表顺序对调、对话模板结尾修改与基座名称替换三类 package.json 错配, 并同步刷新了交付清单 manifest 中的文件哈希值, 使单纯的摘要校验全部放行。真正拦截上述错配的是可信 manifest 中独立持久化的语义约定副本: 加载器逐字段比对 package.json 与约定副本, 一旦失配立即抛出「配置与交付约定不一致」异常并中止加载, 其安全前提是 manifest 本身经由可信控制面下发。生产级模型交付还需补齐两项约束:
- 增量 adapter 交付必须强绑定所依赖基座模型权重的加密摘要, 防止挂载至错误版本基座。
- 跨推理引擎迁移时的数值误差门限必须基于代表性校准集实测标定, 不能凭主观经验任意设定。

## 与真实系统的差距

拒绝时误差显示 0 代表未运行推理；int8 是反量化后的误差实验，没有整数算子加速。manifest 需由可信渠道提供；签名、真实 adapter 基座指纹与跨引擎容差属于部署扩展。

## 怎样验证

固定同一个训练完毕的微型模型与同一测试输入 ab, 对比五种交付工况: 完整 FP32 交付、int8 压缩反量化交付, 以及人为构造的词表对调、模板篡改、基座标识错配三种异常包。验收判定标准如下:
- 合规交付组 (FP32 与 int8): 新进程加载后的输入 token 序列及 greedy 解码结果必须与原进程完全一致, 且 logits 最大绝对误差满足容差门限 (FP32 小于百万分之一, int8 小于 0.15)。
- 契约错配组 (词表、模板、基座异常): 必须在加载阶段显式抛出校验异常并拒绝上线, 严禁静默加载成功后输出偏离预期的错误结果。

边界测试见 [test_engineering_completion.py](../../../tests/test_engineering_completion.py)。

## 常见误区与自测

同一份模型权重对调了词表 token 顺序, 并同步刷新了包内文件摘要, 能否直接上线服务?

<details><summary>展开解析</summary>

不能直接上线, 核心原因有两点:
- 文件摘要不提供来源认证: sha256 哈希仅检查当前字节与登记指纹是否匹配, 可拦截意外损坏或单文件替换; 若修改配置方同步重算并覆写了清单中的文件指纹, 哈希校验便会直接放行, 无法证明配置仍符合训练时的原始契约。
- 词表顺序直接决定输入语义映射: 权重矩阵的 embedding 行索引与词表位置严格绑定, 一旦对调 a 与 b 的编号顺序, 同一字符 a 会被映射至另一行嵌入向量, 导致前向计算与生成结果彻底改变。

本实验中对调 a、b 并重算文件哈希后, 正是由可信 manifest 中独立保存的语义约定副本检出失配并拒绝加载。真实生产交付还需将 adapter 绑定至基座权重摘要, 并使用校准输入实测标定跨推理引擎的数值容差门限。

</details>
