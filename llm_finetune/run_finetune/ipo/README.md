# IPO: 偏好间隔为何有有限目标

## 直觉

这组实验比较两种偏好训练方法:
- DPO (direct preference optimization, 直接用「A 比 B 好」的成对标签训练模型, 不另训奖励模型)。
- IPO (identity preference optimization, 把 DPO 的损失换成平方形式的改版)。
实验设置:
- 数据是 4 对单 token 偏好: 每对里的回答只有 1 个 token, 标签指定其中一个是 chosen (更好的)、另一个是 rejected (更差的)。
- 参考模型是一个冻结不动的均匀分布。
- 两种方法都用 SGD 训练 400 步。
读数是 log-ratio 差 h (也叫 margin): 训练中的模型给 chosen 和 rejected 的对数概率之差, 再减去参考模型的同一个差, h 越大, 模型比参考模型越偏向 chosen。
400 步后:
- DPO 把平均 h 推到 4.35871 而且还在涨。
- IPO 停在 1.0, 正好等于 1/(2β) (β 是两种方法都有的超参数, 本例 β = 0.5)。
成对标签只说 A 比 B 好, 没要求把 B 的概率压到零; IPO 把一个有限的相对概率间隔当成优化目标, 到了就停。

## 核心原理

IPO 的损失在 h 等于 1/(2β) 时最小, 超过这个值也会被拉回; DPO 的 logistic 目标对可分偏好会一直推间隔增大。h 的定义是 h = [log π(chosen) − log π(rejected)] − [log π_ref(chosen) − log π_ref(rejected)], 前一半是训练中的策略模型 π 给两个回答的对数概率之差, 后一半是冻结参考模型 π_ref 的同一个差; 本例参考模型是均匀分布, 后一半等于 0。
两种损失的形状不同:
- IPO 最小化 (h−1/(2β))², 这个式子在说: h 离目标值 1/(2β) 越远损失越大, 偏小偏大都罚, 所以 h 超过目标时梯度会把它往回拉。
- DPO 最小化 −log σ(βh) (σ 是把任意实数压到 0 到 1 之间的 sigmoid 函数), 这个式子在说: h 越大损失越小, 但永远降不到 0; 本例每一对都有自己独立的参数, 四对的胜负都能被完全照办 (这叫可分偏好), 所以梯度一直推 h 增大。
结果是 β = 0.5 时 IPO 的 h 停在 1.0, 意思是相对参考模型, chosen 与 rejected 的概率比被拉开到 e 倍 (约 2.7 倍); DPO 400 步后到 4.35871, 还没有停。

本实现对回答有效 token 的 log probability 取均值, 忽略 padding; 这改变了长度的缩放方式, 必须在配置里写明。一个多 token 回答的对数概率有两种算法:
- 求和: 把每个 token 的对数概率加起来。
- 均值: 加起来再除以 token 数。
padding 是为了把一批回答补到同样长度而填的空位, 不是回答内容, 计算时被排除在外。每个 token 的对数概率都不大于 0, 求和时回答越长总数越负, h 会跟着回答长度变; 取均值后长度的影响被除掉了。IPO 的目标值 1/(2β) 是对 h 定的, h 的算法一换, 同一个 β 对应的间隔就不是同一回事, 所以求和与均值不能混用。本例每个回答只有 1 个 token, 均值和求和算出来一样, 这条规定是给多 token 回答准备的。

参考模型冻结、标签成对、prompt 不计入回答 loss; β 控制的是目标间隔, 不是学习率。
三条约定的意思:
- 参考模型冻结, 是说训练时它的参数不动, 只用来算 h 的后一半, 给策略模型一个固定的比较基准。
- 标签成对, 是说每条数据都是同一个问题下的一个 chosen 回答和一个 rejected 回答。
- prompt (问题本身) 不计入回答 loss, 是说只算回答部分 token 的对数概率, 代码把问题部分 token 的标签设成 -100 排除掉。
在 IPO 里 β 决定 h 停在多大 (1/(2β)), β 越小目标间隔越大; 每一步走多远则由优化器的学习率决定 (本例 SGD 学习率 0.2)。
这个实验没有覆盖下面三种情况, 仍要独立验证:
- 偏好矛盾 (同一对回答在不同标注里胜负相反)。
- 标签噪声 (标错的对)。
- 分布外回答 (训练时没见过的回答)。

## 怎样验证

固定同一组 4 对单 token 偏好、同一个冻结的均匀参考分布和 400 步训练预算, 分别训练 DPO 与 IPO, 比较 loss 和 log-ratio margin (上面说的 h), 看 margin 是否收敛到 1/(2β), 而不是只看训练集准确率。代码断言 IPO 的 margin 与 1 相差不到 0.001, 且 DPO 的 margin 大于 IPO 的。
只看准确率不够: 本例两种方法训完 h 都大于 0, 每一对都是 chosen 的概率更高, 准确率分不出两者, 区别只在 h 停在哪里; 长文本上还要控制回答长度与参考模型概率, 因为两者都会改变 h 的大小。

## 与真实系统的差距

四个独立的条件 logits，验证 loss 的梯度与平衡点，不代表真实偏好泛化，也不说明 IPO 总比 DPO 好。

## 常见误区与自测

IPO 间隔超过目标以后, 平方损失会怎样?

<details><summary>展开解析</summary>

会把它拉回来。平方目标两侧都有惩罚, h 超过 1/(2β) 后梯度反向。
IPO 的损失是 (h−1/(2β))², 对 h 求导得 2(h−1/(2β)), 这个式子在说梯度的方向取决于 h 落在目标值的哪一边:
- h 小于 1/(2β) 时导数为负, 梯度下降把 h 往上推。
- h 大于 1/(2β) 时导数为正, 梯度下降把 h 往下拉。
- 正好相等时导数为 0, h 不再变。
DPO 的损失 −log σ(βh) 的导数始终为负, 只是 h 越大越接近 0, 所以它只会继续把 h 推大。本例 400 步后 IPO 的 margin 停在 1.0, DPO 的到 4.35871。

</details>
