# IPO：偏好间隔为何有有限目标

## 直觉

成对标签说 A 比 B 好，并没有要求把 B 的概率压到零。IPO 用有限的相对概率间隔作为优化目标。

## 核心原理

定义 h 为 chosen/rejected 的策略对数概率差减去参考模型的相同差。IPO 最小化 (h−1/(2β))²；在这个目标下，超过目标间隔也会被拉回。DPO 的 logistic 目标对可分偏好仍会推动间隔增大。

本实现对回答有效 token 的 log probability 取均值，并且忽略 padding。这样改变了长度的缩放方式，必须在配置中说明；不能混用求和与均值还沿用同一个 β 解释。

参考模型冻结、标签成对、prompt 不计入回答 loss。β 控制目标间隔而非学习率；偏好矛盾、噪声和分布外回答仍需独立验证。

## 运行

```bash
python -m llm_finetune.run_finetune.ipo.demo
```

需要 Python ≥ 3.10，依赖使用仓库的 numpy / torch；不需要模型 API。网页在现有章节中提供同一实验的执行记录回放。

## 怎样验证

同一组四个单 token 偏好分别训练 DPO 与 IPO，比较 loss 和 log-ratio margin，而不是只检查训练集准确率。长文本上还应控制回答长度与参考模型概率。

## 与真实系统的差距

四个独立的条件 logits，验证 loss 的梯度与平衡点，不代表真实偏好泛化，也不说明 IPO 总比 DPO 好。

## 常见误区与自测

IPO 间隔超过目标以后，平方损失会怎样？

<details><summary>展开解析</summary>

平方目标两侧都有惩罚；h 超过 1/(2β) 后，梯度方向会将它拉回。

</details>
