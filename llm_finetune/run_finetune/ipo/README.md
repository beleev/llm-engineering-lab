# IPO: 偏好间隔为何有有限目标

## 直觉

同样 4 对单 token 偏好、同样 400 步, DPO 把平均 log-ratio 差推到 4.35871 还在涨, IPO 停在 1.0, 正好是 1/(2β) (β = 0.5)。成对标签只说 A 比 B 好, 没要求把 B 的概率压到零; IPO 把有限的相对概率间隔当成优化目标。

## 核心原理

定义 h 为 chosen/rejected 的策略对数概率差减去参考模型的相同差。IPO 最小化 (h−1/(2β))², 超过目标间隔也会被拉回, 本例 β = 0.5 时 h 停在 1.0。DPO 的 logistic 目标对可分偏好一直推间隔增大, 400 步后到 4.35871。

本实现对回答有效 token 的 log probability 取均值, 忽略 padding。这改变了长度的缩放方式, 必须在配置里写明; 求和与均值混用, 同一个 β 的含义就不一样了。

参考模型冻结、标签成对、prompt 不计入回答 loss。β 控制的是目标间隔, 不是学习率; 偏好矛盾、标签噪声和分布外回答仍要独立验证。

## 怎样验证

同一组 4 对单 token 偏好、同一个均匀冻结参考分布和 400 步预算, 分别训练 DPO 与 IPO, 比较 loss 和 log-ratio margin 是否收敛到 1/(2β), 而不是只看训练集准确率; 长文本上还要控制回答长度与参考模型概率。

## 与真实系统的差距

四个独立的条件 logits，验证 loss 的梯度与平衡点，不代表真实偏好泛化，也不说明 IPO 总比 DPO 好。

## 常见误区与自测

IPO 间隔超过目标以后, 平方损失会怎样?

<details><summary>展开解析</summary>

会把它拉回来。平方目标两侧都有惩罚, h 超过 1/(2β) 后梯度反向; 本例 400 步后 IPO 的 margin 停在 1.0, DPO 的到 4.35871。
