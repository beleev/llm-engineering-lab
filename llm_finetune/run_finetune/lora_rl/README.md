# LoRA 做 RL: 策略梯度带回的信息很少, 但要放开对的那几百个参数

[llm_finetune 目录](../../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/finetune/lora)

## 直觉

[lora](../lora/README.md) 量到的 "同步数下全参优于 LoRA" (EM 0.809 vs 0.352) 是 SFT 上的结论。RL 一侧的情况不同: Thinking Machines 的 "LoRA Without Regret" (John Schulman 等, 2025-09-29) 报告, 用策略梯度做 RL 时秩 1 的 LoRA 就能追平全参。理由是一个信息量的账: SFT 的每条样本逐 token 监督, 带回 O(token 数) bit; 策略梯度的每个 episode 只靠一个优势值学习, 只带回 O(1) bit。RL 要吸收的信息少, 低秩适配器就装得下。

本脚本在同一个 GRPO 任务上比全参、LoRA r=1 / r=8, 结果照实写:
- 标准 LoRA (norm 和 embedding 冻结) 在这个规模上没有追平全参: 60 步后采样 pass@1 全参 0.324, r=1 0.193, r=8 0.221。
- 差距不在秩。线性层满秩可训、norm 冻结的对照也只有 0.223; 给 r=1 再放开 320 个 RMSNorm 增益就到 0.301, 只训这 320 个增益到 0.502。
- 所有 RL 臂的贪心 EM 都没有涨 (起点 0.562)。60 步 RL 的收益是把分布变尖, 这件事几百个参数就够, 但得是控制 logits 尺度的那几个。
- SFT 对照里贪心 EM 跟着线性层的可训容量走: 全参 0.684, 只训 norm 0.602。

## 核心原理

### 信息量的账

LoRA Without Regret 的论证分三步 (原文是数量级估计, 不是定理):
1. SFT 每条样本对每个 token 都给出目标, 带回的信息随 token 数增长。
2. 策略梯度的学习信号是每个 episode 一个优势值。奖励是 0/1 时, 一个 episode 至多带回 1 bit。原文估计, episode 有几千个 token 时, RL 每个训练 token 吸收的信息比 SFT 少约 1000 倍。
3. 适配器能存的信息按每个参数约 2 bit 估 (原文引用 Allen-Zhu & Li, 这是长训练极限下的存储量)。原文的例子: MATH 上 1 万题各采 32 次, 约 32 万 bit; Llama-3.1-8B 秩 1 的 LoRA 已有约 300 万参数。

这个账只说明容量够不够, 不说明学得多快, 也不说明哪些参数该放开。本脚本量到的正是后一件事。

### 本库这个小模型里, "变尖" 由谁控制

LLaMA 在 lm_head 之前有一层 RMSNorm (ln_f): 不管前面的残差流整体放大多少倍, 进 lm_head 之前都被归一化回去。logits 的整体尺度因此只由 ln_f 的增益和 (与 lm_head 共享的) embedding 决定。

- 标准 LoRA 只改线性层, 冻结 norm 和 embedding, 它只能靠改隐状态的方向去拉大 logit 差距, 60 步里走得很慢。
- 线性层全参可训但 norm 冻结时同样慢, 所以瓶颈不是秩。
- 放开 RMSNorm 增益 (每层 norm1、norm2 加 ln_f, 共 5 × 64 = 320 个) 之后, 模型可以直接调大 logits 的尺度, 等价于降低采样温度。答对概率本来就最高的题, 采样一次答对的概率随之上升。

### LoRA 的参数化

`y = W x + (α/r)·B A x`, A 用 Kaiming uniform, B 全零。α 固定 16, 缩放 α/r 随秩变 (原论文与博客都用这种 1/r 参数化; 博客的实验取 α = 32)。LoRA 注入全部 7 种线性层, 包括 MLP 的 w_gate / w_up / w_down: 博客报告只加在注意力上明显不如只加在 MLP 上。

```bash
python -m llm_finetune.run_finetune.lora_rl.train_lora_rl    # 单线程 CPU 约 108 s
```

## 运行后应该看到什么

起点与 [grpo](../grpo/README.md) 相同 (sort 任务 SFT 150 步, 种子 0)。RL 臂: GRPO 32 prompt × G=8, 60 步。SFT 臂: 同一起点, 每步 64 条, 60 步。每种配置扫 2 个 lr, RL 按采样 pass@1、SFT 按贪心 EM 取最好的一臂, 全部是留出集指标:

```
---- 每种配置取 lr 网格里最好的一臂 (RL 按 pass@1, SFT 按贪心 EM) ----
                     可训参数  RL pass@1    RL 贪心 EM    SFT 贪心 EM
SFT 起点              99,648      0.186       0.562        0.562
全参                  99,648      0.324       0.535        0.684
只训线性层               98,304      0.223       0.504        0.672
LoRA r=1             2,432      0.193       0.523        0.629
LoRA r=8            19,456      0.221       0.535        0.637
LoRA r=1 + norm      2,752      0.301       0.496        0.625
只训 norm                320      0.502       0.574        0.602
```

各臂的 lr: RL 全参 3e-4, 只训线性层 3e-4, LoRA r=1 1e-3 (3e-3 同为 0.193), r=8 1e-3, r=1 + norm 3e-3, 只训 norm 3e-2; SFT 全参 3e-3, 只训线性层 3e-3, LoRA r=1 / r=8 / r=1 + norm 1e-2, 只训 norm 1e-1。完整的 24 臂明细脚本会逐行打印。

**怎么读这张表**:
- RL 一列: 标准 LoRA 的 r=1 和 r=8 只比起点高 0.007 和 0.035, 全参高 0.138。把 norm 加回去, r=1 追到全参 0.023 以内; 只训 320 个 norm 增益反而最高。
- RL 贪心 EM 一列: 没有一臂比起点高 0.02 以上。60 步 GRPO 改变的是采样分布的尖锐程度, 不是 argmax 的对错。这与 [grpo](../grpo/README.md) 的结论一致。
- SFT 一列: 贪心 EM 的涨幅按线性层的可训容量排序 (全参 +0.122, 只训线性层 +0.110, r=8 +0.075, r=1 +0.067), 只训 norm 只涨 0.040。学会新的映射要靠线性层的容量, norm 增益做不到。
- lr: RL 上 LoRA 最好的 lr (1e-3 到 3e-3) 是全参 (3e-4) 的 3 到 10 倍。博客报告的最优倍数约 10 倍, 100 步以内的短训练约 15 倍。

断言 (都通过):
1. LoRA r=1 训练后, 冻结的基座权重逐位不变 (GRPOTrainer 的 AdamW 跳过 grad 为 None 的参数)。
2. RL 全参的 pass@1 比起点高 0.04 以上。
3. RL 标准 LoRA r=1 比全参低 0.05 以上; 只训线性层也比全参低 0.05 以上。
4. RL LoRA r=1 + norm 追到全参 0.05 以内; 只训 norm 比起点高 0.1 以上。
5. RL 各臂的贪心 EM 都没有比起点高 0.02 以上。
6. SFT 全参的贪心 EM 涨 0.1 以上, 只训 norm 涨不到 0.05; 全参比 LoRA r=1 高 0.04 以上。

## 与真实系统的差距

- **模型和训练都太小, 不能用来否定博客的结论**: 2 层、d_model=64 的模型, 60 步 GRPO, 单种子。博客在 Llama-3.1-8B 上用 MATH / GSM8K 训练, 量的是完整的学习曲线。本脚本只说明在这个规模上, 标准 LoRA 追不上全参的原因是冻结了 norm, 不是秩不够。
- **RL 的收益几乎全是变尖**: 起点已经 "半会" sort, 60 步 RL 只提高了采样 pass@1。真实 RLVR 在长推理上的收益更复杂, 那里是否也主要靠少数尺度参数, 这个脚本测不出来。
- **评估噪声**: pass@1 用 512 道留出题, 贪心 EM 用 256 道, 单种子评估噪声约 ±0.03。r=1 + norm 与全参的差距 0.023 落在噪声内, 表格之间更小的差别不要读成谁更强。
- **lr 网格很粗**: 每种配置只扫 2 个值。只训 norm 的 RL 最好值落在网格上沿 (3e-2), 再调大可能更高, 但不影响 "几百个参数就够" 的结论。
- **SFT 对照的数据量很小**: 60 步 × 64 条 = 3,840 条样本。博客说的 "数据量超过 LoRA 容量时 LoRA 落后全参" 是大数据集上的结论, 这里看到的 r=1 落后 0.055 (EM) 更可能是 60 步里学得慢, 不能证明容量不够。
- **信息量的账没有在脚本里实测**: 每个 episode 的奖励熵、每个参数能存多少 bit 都是引用的估计, 实验台里的条形图按这些估计算。

## 常见误区

- "RL 用秩 1 的 LoRA 就够, 所以怎么注入都行"。本脚本里秩不是瓶颈, 冻结哪些参数才是: 同样 2,432 个 LoRA 参数, 加上 320 个 norm 增益后 pass@1 从 0.193 升到 0.301。博客也强调要加到包括 MLP 在内的所有层。
- 用 RL 的结论去推 SFT: SFT 每条样本带回的信息多得多, 大数据集上 LoRA 会受容量限制。本库 [lora](../lora/README.md) 的 SFT 对照里全参 EM 0.809, LoRA r=8 只有 0.352。
- 用贪心 EM 判断 RL 有没有效果: 这里所有 RL 臂的贪心 EM 都没涨, 但采样 pass@1 涨了 0.14 到 0.32。
- 沿用全参的 lr 训 LoRA: B 从 0 起步, 有效步长小, 本脚本里 LoRA 最好的 lr 是全参的 3 到 10 倍。

## 自测题

1. 一个 GRPO episode 的奖励是 0/1, 它最多带回多少信息? 同样一条 7 个 token 的 SFT 样本呢? — **答**: 至多 1 bit (二值奖励的熵不超过 1 bit, 组内奖励全相同时优势为 0, 连这 1 bit 也没有)。SFT 样本对 7 个位置都给出目标, 信息随 token 数增长。
2. 为什么 "只训线性层" (98,304 个参数, 满秩) 在 RL 上也追不上全参? — **答**: 这个模型在 lm_head 之前有 RMSNorm, logits 的整体尺度由 norm 增益和 embedding 决定。60 步 RL 的收益是把分布变尖, 冻结了 norm 和 embedding 就只能靠改方向慢慢拉大差距, 与秩无关。
3. 只训 320 个 norm 增益, RL 的 pass@1 能到 0.502, 为什么 SFT 的贪心 EM 只涨 0.040? — **答**: 变尖不改变 argmax, 只让本来就最可能的答案更常被采到; SFT 要的是把错的 argmax 改对, 这需要改线性层里的映射, 几百个尺度参数做不到。
