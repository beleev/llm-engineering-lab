# 推理模型的训练面: 长 CoT 蒸馏、思考模式开关与思考预算

[llm_finetune 目录](../../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/finetune/reasoning)

## 直觉

推理模型在回答前先写一段思考。训练这类模型时有三件事要定:

- **小模型从哪学会思考**: DeepSeek-R1 (arXiv 2501.12948) 用 R1 整理的 800k 条样本对 Qwen 和 Llama 小模型做 SFT, 把大模型的长推理轨迹直接蒸馏进去。R1-Distill-Qwen-7B 在 AIME 2024 上 pass@1 55.5; 在 Qwen-32B 上, 蒸馏版 72.6 高于直接做大规模 RL 的 47.0。
- **简单问题要不要也想半天**: Qwen3 (arXiv 2505.09388) 在推理 RL 之后的第 3 阶段继续 SFT, 把思考与非思考两种格式混在一起训, 用户在消息里写 /think 或 /no_think 切换; 非思考模式的样本保留一个空的思考块。
- **想多久**: s1 (arXiv 2501.19393) 在推理时做 budget forcing, 到预算就追加 end-of-thinking 分隔符强制结束, 想延长就压住分隔符再追加 "Wait"。L1 (arXiv 2503.04697) 用 RL 训练模型听从 prompt 里的 "Think for N tokens.", 奖励是答对减去 α 乘以长度偏差。

本脚本在一个 K=4 步的模 10 算术链上把这三件事各做一遍, 结论按实测写。

## 核心原理

### 任务与格式

题目是 [prm](../prm/README.md) 用的同一种算术链: 起始数字 a0, 再依次做 4 次 +, −, × 一个数, 结果都模 10。vocab 24, 序列最长 26 个 token:

```
prompt:  a0 op1 k1 … op4 k4 MODE SEP          MODE ∈ {/think, /no_think, B0 … B4}
思考:    op1 k1 v1 … op4 k4 v4 </think> ans EOS     每步一行 "op k 结果", 老师 (程序) 写的完整轨迹
非思考:  </think> ans EOS                          空的思考块
预算 b:  前 b 步 </think> ans EOS                  剩下 4−b 步要在回答那一次前向里默算
```

ans = v4。留出集是 (a0 + Σk) ≡ 0 (mod 5) 的题, 与训练集不相交。

### 五个模型

| 模型 | 训练数据 | 步数 |
|---|---|---|
| 只答案 | 只有非思考格式 | 从头 1500 步 |
| 长轨迹 | 只有思考格式 (完整轨迹) | 从头 1500 步 |
| 融合 | 两种格式各一半, 靠 /think 与 /no_think 区分 | 在长轨迹模型上继续 500 步 |
| 预算 token | b 从 0…4 均匀取, prompt 写 B_b | 在长轨迹模型上继续 500 步 |
| 强制截断 | 不训练: 拿长轨迹模型, 写完 b 步硬插 </think> | — |

结构都是 `common.make_model` 的 2 层 LLaMA (d_model=64), batch 64, lr=3e-3。指标在留出集 512 题上用贪心解码: 正确率 = </think> 后面那个 token 等于 v4; 输出 token 数 = 到 EOS (含) 为止。

## 运行

```bash
python -m llm_finetune.run_finetune.reasoning.train_reasoning    # 单线程约 55 s
```

## 运行后应该看到什么

```
---- 1. 只答案 SFT vs 长轨迹 SFT ----
                   正确率    输出 token
只答案               0.158         3.0
长轨迹               0.996        15.0

---- 2. 一个模型混训 /think 与 /no_think ----
                   正确率    输出 token
/think            1.000        15.0
/no_think         0.156         3.0

---- 3. 长度控制: 预算 b 步 (输出 3b+3 个 token) ----
b       预算 token 正确率    输出 token         强制截断正确率    输出 token
0              0.160         3.0           0.092         2.9
1              0.131         6.0           0.072         5.8
2              0.145         9.0           0.105         9.0
3              0.166        12.0           0.113        12.0
4              0.998        15.0           0.996        15.0
```

怎么读:

- **长轨迹把正确率从 0.158 提到 0.996, 输出从 3 个 token 变成 15 个**: 只答案的模型要在一次前向里算完 4 次模 10 运算, 2 层模型做不到, 只比瞎猜 (0.1) 高一点; 长轨迹每写一行就多一次前向, 每次只算一步。
- **一个模型两种模式**: 融合模型 /think 下 1.000, /no_think 下 0.156 且恰好输出 3 个 token, 与两个单独训练的模型几乎相同。开关决定花多少 token, 也就决定了能算多少步。
- **预算 token 学会了按预算写**: 每一档的平均长度都恰好是 3b+3。
- **正确率与长度的取舍是一个台阶**: b=0…3 的正确率都在 0.13–0.17, 只有 b=4 跳到 0.998。少写一步, 那一步就要默算, 而这个模型连一步都默算不了。把混训步数从 500 加到 3000, b=3 也只到 0.178, 不是训练不够。
- **强制截断比预算 token 更差**: s1 式硬插 </think> 时, 长轨迹模型从没学过 "写一半就作答", b<4 时只有 0.07–0.11, 等于瞎猜; 预算 token 模型至少学会了只答案模型那点先验。

断言 (每条都在脚本末尾):

1. 长轨迹 SFT 的正确率比只答案高 0.3 以上, 输出 token 多 4 倍以上。
2. 融合模型 /think 与单独的长轨迹模型相差不到 0.1; /no_think 平均恰好 3 个 token。
3. 融合模型 /think 比 /no_think 高 0.3 以上。
4. 预算 token 模型每档的平均长度等于 3b+3; b=4 比 b=0 高 0.3 以上。
5. 预算 token 模型 b=1…3 都不比 b=0 高出 0.05 (台阶)。
6. 强制截断 b=4 等于长轨迹模型本身; b<4 时正确率 < 0.15, 也低于同一档的预算 token 模型。

## 与真实系统的差距

- **老师是程序, 轨迹没有噪声**: R1 的蒸馏数据来自大模型采样, 要做拒绝采样过滤错误答案, 轨迹里有反思、回溯和重复检查。这里的轨迹每一步都必要且正确, 所以 "少写一步就丢一步计算"。真实长 CoT 里有冗余, L1 这类方法能把长度压下来而只掉少量分数, 原因正在于此。
- **长度控制用 SFT 学, 不是 RL**: L1 的奖励是 𝟙(答对) − α·|n_gold − n_y| (L1-Exact, α=0.0003), 由模型自己探索怎么在预算内答对。这里直接拿老师截断后的轨迹做 SFT, 模型没有机会发现更短的解法。
- **s1 的 "Wait" 延长没有做**: 这里的链长固定, 写满就是全部计算, 延长无事可做。
- **Qwen3 的思考预算**是在思考达到阈值时插入一句 "根据已有思考直接作答" 的提示再接 </think>, 报告说这个能力不是专门训练的。本例的强制截断对应它, 小模型上效果接近瞎猜。
- **单种子, 2 层模型, K=4**: 台阶形状是这个容量下的结果。更大的模型能默算几步, 台阶会左移。

## 常见误区

- **思考 token 只是 "把答案说得更详细"**: 本例只答案 0.158、长轨迹 0.996, 同一个模型容量, 差别全在写出来的中间步骤。每个思考 token 都是一次额外的前向计算。
- **非思考模式等于把思考截掉**: 融合模型 /no_think 学过 "不写直接答", 正确率 0.156; 长轨迹模型被强制截到 0 步只有 0.092。没学过的截断比学过的空思考块更差。
- **预算给多少, 正确率就按比例给多少**: 本例是台阶不是斜坡。能不能省长度, 取决于被省掉的步骤是不是冗余的, 以及模型默算能力有多强。

## 自测题

1. 为什么只答案 SFT 的模型正确率只有 0.158, 而长轨迹 SFT 是 0.996? — **答**: 只答案要在一次前向里算完 4 步模 10 运算, 2 层模型做不到; 长轨迹每写一步就多一次前向, 每次只需要算一步。
2. Qwen3 的非思考模式样本长什么样? 这样做有什么好处? — **答**: 保留一个空的思考块再作答。两种模式的输出格式相同, 同一个模型靠 /think 与 /no_think 切换, 部署只需要一份权重。
3. 本例把预算从 4 步降到 3 步, 正确率从 0.998 掉到 0.166。为什么真实推理模型压缩思考长度时不会掉这么多? — **答**: 真实长 CoT 里有大量冗余的检查和重复, 被压掉的多是冗余; 大模型一次前向也能默算更多。本例的轨迹每一步都必要, 而 2 层模型一步也默算不了。
