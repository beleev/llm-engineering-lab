# DoRA — 权重分解的 LoRA

```bash
python -m llm_finetune.run_finetune.dora.train_dora    # ~25 s
```

## 直觉
把每一行权重看成 "长度 × 方向"。全参微调时两者常常独立变化, 而 LoRA 的 ΔW = BA 只能让它们按比例一起动。
DoRA 让 LoRA 只负责方向, 长度单独用一个 d_out 维向量 m 来学。

## 核心公式
`W' = m ⊙ (W + (α/r)BA) / ‖W + (α/r)BA‖_row`，m 初始化为 ‖W‖_row ⇒ 第 0 步 W' = W。
反传时分母 `.detach()` (论文 §4.3): 省一整份 [d_out, d_in] 的梯度显存。

## 运行后应该看到什么
同一基座 (copy → sort)、r=8、lr=1e-2、300 步, 3 个种子:

| | 可训参数 | 末步 loss (3 seeds) | 留出集 EM (3 seeds) |
|---|---|---|---|
| LoRA | 19,456 | 0.384 / 0.367 / 0.356 (均 0.369) | 0.352 / 0.406 / 0.387 (均 0.382) |
| DoRA | 20,736 (+1,280 = Σ d_out) | 0.273 / 0.301 / 0.313 (均 **0.296**) | 0.570 / 0.523 / 0.473 (均 **0.522**) |

训练后 `layers.0.attn.w_q` 的 m 相对初值平均变了 59.7% —— 这个任务确实需要改 "长度"。
诚实说明: 这是玩具规模; 调参时 r=2 的 3 个种子里有 1 个是 LoRA 赢。断言只要求 3 个种子的平均 loss DoRA < LoRA。

## 常见误区
- 以为 DoRA 和 LoRA 一样能拆成两次小 matmul: 归一化作用在整行 W+ΔW 上, 每步都要显式构造 [d_out, d_in] 的矩阵, 训练更慢。
- m 初始化成 1: 第 0 步输出就变了。必须是 ‖W‖_row。
- 忘了 detach 分母: 结果接近, 但显存多一份全尺寸梯度。

## 自测题
1. DoRA 比 LoRA 每层多多少参数? — d_out 个。
2. 如果训练中 m 完全不动, DoRA 等价于 LoRA 吗? — 不等价: 方向仍被归一化, W' 的每行长度被钉死在 ‖W₀‖, 而 LoRA 的行长度会随 BA 变化。
3. 合并后推理开销? — 零, 合并结果是一个普通 Linear。
