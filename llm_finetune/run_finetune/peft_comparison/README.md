# PEFT: Prompt、Prefix、Adapter 与 LoRA

## 直觉

PEFT (parameter-efficient fine-tuning, 参数高效微调) 冻结基座模型原有的全部参数, 只训练少量新加的参数。这组实验在同一个冻结基座上比较四种放新参数的位置:
- soft prompt 在输入序列前面拼几个可学习的向量。
- KV prefix 直接往注意力层的 K 和 V (注意力用来匹配和取内容的两组向量) 前面拼可学习的向量。
- Adapter 在注意力输出后面串一个小网络。
- LoRA 给 V 的投影矩阵加一个低秩增量 (两个小矩阵相乘得到的改动)。
基座只有一层注意力, 每条样本是 3 个 8 维的 token, 目标值是最后一个 token 前两维之和, 四种方法都用同样 32 条样本训练 160 步。
训练结果:
- Soft prompt 只有 16 个可训练参数, MSE (预测值与目标之差的平方取平均, 越小越准) 从 1.5684 降到 1.0521。
- prefix、Adapter、LoRA 各 32 个参数, 分别降到 0.7128、0.5444、0.7207。
冻结基座不等于只能改提示词: 四种方法把可训练参数放在不同位置, 梯度传到它们的路径不同, 部署时多付的代价也不同。

## 核心原理

Prompt Tuning 学 2 个输入 embedding (模型输入端的向量), 它们还要经过冻结的 Q/K/V 投影; Prefix Tuning 直接提供这一层的 K/V 前缀, 真实多层模型要逐层注入。
注意力层里, 每个输入向量分别乘三个矩阵, 得到 q (query, 拿去和别的 token 匹配)、k (key, 被拿来匹配)、v (value, 匹配上以后交出的内容), 这三次矩阵乘法叫 Q/K/V 投影, 本例三个矩阵都是冻结的。
两条路径:
- Prompt Tuning (soft prompt) 在输入序列前面拼 2 个可学习的 8 维向量, 共 16 个参数; 它们和真实 token 一样要先乘冻结的投影矩阵才变成 k 和 v, 所以能变出什么样的 k、v 受冻结矩阵限制。
- Prefix Tuning 跳过投影, 直接学 2 个 k 向量和 2 个 v 向量, 共 32 个参数, 拼到这一层的 K、V 前面; 真实模型有很多层, 每一层都要各注入一份。
本例在同一个单层基座上比较这两条路径, 只读最后一个位置的输出, 这个位置能看见前面全部 token 和拼进来的向量。

瓶颈 Adapter 把注意力输出 h 先降维、过非线性、再升维, 结果放进输出残差; LoRA 给 V 投影加低秩分支 ΔW=AB, 在适用的线性层可以合并回权重。
Adapter 的做法, 在注意力算出 8 维输出 h 后:
1. 先乘一个 8 × 2 的矩阵压到 2 维 (中间窄, 所以叫瓶颈)。
2. 过 ReLU (把负数变成 0 的非线性函数)。
3. 再乘一个 2 × 8 的矩阵升回 8 维。
4. 加回到 h 上。
这种「原值加改动量」的连法叫残差。
LoRA (low-rank adaptation, 低秩适配) 的做法: V 投影原本是冻结的 8 × 8 矩阵 W, LoRA 另学一个 8 × 2 的 A 和一个 2 × 8 的 B, 相乘得到 8 × 8 的增量 ΔW, 它的秩最多是 2, 所以叫低秩, 实际用的投影是 W + ΔW。两种方法的 B 都从全 0 开始, 训练前新分支的输出为 0, 所以 Adapter 和 LoRA 的初始 MSE 都是基座本身的 1.5489。
部署代价不同:
- 前缀占上下文/缓存, 每个请求都要带着它, 它的 K/V 也要存进推理时的 KV 缓存。
- Adapter 中间有 ReLU, 不能并进原有矩阵, 推理时多一个算子。
- LoRA 训完可以把 ΔW 直接加进 W, 合并后不一定多出线性算子。

多个 LoRA 可以按权重求和, 但组合效果不保证可加; 基座、秩与目标层都要核对一致。按权重求和, 是说把几个任务各自训出的增量 ΔW 乘上系数后一起加进同一个 W。每个增量训练时只见过自己, 放在一起后会互相影响, 合起来的效果不一定等于各自效果相加。ΔW 是针对某个基座的某一层学出来的, 换了基座或挂到别的层上, 同样的数值意思就变了, 所以相加前要核对基座、秩和目标层。Prompt/Prefix 通常不能直接当 ΔW 相加: 它们不是权重的改动量, 而是额外拼进序列的几个位置。持续个性化 (为每个用户不断训练自己的适配器, 适配器指 Adapter、LoRA 这类挂在基座上的小模块) 要比较单用户、共享和组合适配器三种做法的串扰 (一个用户的训练影响到别的用户) 与遗忘 (新的训练让旧能力退步)。

## 怎样验证

四种模式用同一个冻结基座、同样 32 条样本和 160 步 (Adam 优化器, 学习率 0.035), 报告可训练参数数、训练前后 MSE, 并断言基座权重没变; 参数量没有配平 (16 对 32), 结果只验证每条路径学得动, 不作为方法排名。
「断言基座权重没变」是训练结束后检查 Q/K/V 投影矩阵和训练前逐个相等, 表里的「冻结基座未变 true」就是这项检查的结果; 代码还断言每种方法训练后的 MSE 都低于训练前。soft prompt 只有 16 个参数, 其余三种是 32 个, 而且 MSE 就在这 32 条训练样本上算, 没有留出测试集, 所以 MSE 的高低只说明梯度确实流到了新参数, 不能拿来排谁更好。

## 与真实系统的差距

固定 32 条合成样本验证参数路径与梯度。没有留出泛化结论；Prompt Tuning 与提示词写作不是一回事。

## 常见误区与自测

本例 Prefix 与 Soft Prompt 最关键的区别是什么?

<details><summary>展开解析</summary>

Soft Prompt 学的是输入向量, 要经过冻结的 Q/K/V 投影才变成 K/V; Prefix 直接学这一层里的 K/V 状态。
具体路径:
- soft prompt 的 2 个向量拼在输入序列最前面, 进入注意力层后和真实 token 一样, 先乘冻结的 K 投影矩阵得到 k, 乘冻结的 V 投影矩阵得到 v; 训练能改的只是投影之前的输入, 最后得到的 k、v 受冻结矩阵限制。
- Prefix 不走这一步, 它的 2 个 k 和 2 个 v 就是可训练参数, 直接拼在这一层 K、V 序列的前面。
两者的参数量也因此不同: soft prompt 是 2 × 8 = 16 个, prefix 的 k、v 各 2 × 8 个, 共 32 个。本例只有一层, 多层实现还要说明每层的注入位置, 因为 prefix 要给每一层各提供一份 K/V。

</details>
