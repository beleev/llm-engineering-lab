# KTO — 只有 👍 / 👎, 没有成对偏好

```bash
python -m llm_finetune.run_finetune.kto.train_kto      # ~21 s
```

## 直觉
DPO 的数据单位是 "同一个 prompt 下的两条回复 + 谁更好"。线上日志里更常见的是单条回复的 👍 / 👎, 而且好坏数量严重不均。

KTO 给每条样本一个 "参考点" z0: 好回复的隐式奖励要高过它, 坏回复要低过它。参考点代替了 DPO 里 "对面那条", 于是单条样本也能训。

## 核心数据结构与控制流
- `methods/kto.py:UnpairedDataGenerator` — 把偏好对拆开: 每个 prompt 只给一条回复, 以 `desirable_frac` 的概率是正确回复, 否则是损坏回复。另附一份错配的 (x_i, y_{i+1}) 用来估 z0。
- `methods/kto.py:KTOForward` — 继承 `PairwiseForward`, 两路前向 (本条样本 / 错配样本) + 冻结 ref, 只改了输出的名字。
- `methods/kto.py:KTOLoss` — 普通 `LossComputer`, 通用 `Trainer` 一行不改。

## 核心公式
`r(x,y) = log π_θ(y|x) − log π_ref(y|x)`
`z0 = max(0, mean_{错配 (x,y')} r(x,y'))`, 不回传梯度
`v = λ_D·σ(β(r − z0))` (好)，`v = λ_U·σ(β(z0 − r))` (坏)，`L = E[λ_y − v]`
类别不均时: 论文建议 `λ_D·n_D / (λ_U·n_U) ∈ [1, 4/3]`。

## 运行后应该看到什么
设置:
- 起点 = SFT 100 步 (与 `dpo` 相同); β=0.5, lr=3e-4, 200 步。
- 每步 policy 与 ref 各前向 128 条序列 (DPO: 64 对; KTO: 64 条样本 + 64 条错配样本)。
- 全部指标在**留出**偏好对上。

| 留出集 | 偏好准确率 | log π(chosen) | log π(rejected) | 差值 | 贪心 EM |
|---|---|---|---|---|---|
| SFT 起点 | 0.965 | −4.03 | −10.55 | 6.52 | 0.332 |
| DPO 成对 | **0.996** | −4.25 ↓ | −15.60 | **11.35** | 0.121 ↓ |
| KTO 拆开, 好:坏 = 1:1 | 0.992 | **−3.73 ↑** | −14.03 | 10.31 | **0.324** |
| KTO 好:坏 = 1:9, λ_U = 1/9 | 0.988 | −4.12 | −13.86 | 9.74 | 0.254 |
| KTO 好:坏 = 1:9, 不调 λ | 0.492 | **−30.02** | −30.75 | 0.73 | **0.000** |

表里的 DPO 行是本脚本里同条件重跑的对照。单独跑 `train_dpo` 得到的是 −4.18 / −15.36 / EM 0.137（见 `../dpo/readme.md`）：两次独立运行，数字有差异，结论一致。

**如实解读**:
- **不成对也能学到偏好方向**: KTO 准确率 0.965 → 0.992, 差值 6.5 → 10.3。
- **同样前向预算下 DPO 略强** (0.996 / 11.35): 它每步看到 64 对 = 128 条有标签的回复, KTO 只有 64 条。
- **KTO 没有 DPO 的 likelihood displacement**: 好样本有自己的一项, 直接把 r 往上推。chosen 的 log-prob 从 −4.03 升到 −3.73, 贪心 EM 基本不掉 (0.324)。DPO 这两项都掉了 (−4.25, 0.121)。
- **好坏 1:9 时 λ 必须跟着调**: 按论文把 λ_D·n_D / (λ_U·n_U) 调到 1, 准确率 0.988。不调的话, 坏样本的梯度压倒一切, 模型把**所有**回复一起往下压 (chosen −30)。偏好方向丢了, 生成全崩 (EM 0)。
- **KTO 能吃 DPO 吃不了的数据**: 这份 1:9 的数据每个 prompt 只出现一条回复, DPO 一对也凑不出来。

## 诚实边界
- 本脚本里 z0 **始终为 0**。错配样本上的平均 log π/π_ref 从 0 降到 −2.5 (policy 把 "答非所问" 的回复压得比 ref 还低), 被 clamp 到 0。所以这里的 KTO 实际上是 "好样本 σ(βr)、坏样本 σ(−βr)", 参考点那一项没发挥作用。
- "好" = 完全正确的排序, "坏" = 改错 / 漏掉一个 token 的排序。好坏在这里界限分明, 真实的 👍 / 👎 噪声大得多。
- 前向预算相同, 但 KTO 有一半前向花在估 z0 上。若按 "同样多的有标签回复" 比, 结论可能不同, 这里没有测。

## 常见误区
- 用本条样本自己估 z0: 那样 z0 就随 r 一起动, 参考点失去意义。必须用错配的 (x, y'), 并 detach。
- 数据极不均衡时不调 λ: 上表最后一行。
- 以为 KTO 就是 "DPO 去掉配对":
  - DPO 只看差值, 两边可以一起降。
  - KTO 对好、坏样本各有一项, 好样本的 log-prob 被直接往上推。

## 自测题
1. KTO 需要什么样的数据? DPO 呢? — KTO: 单条回复 + 好 / 坏标签; DPO: 同一 prompt 下的一对回复 + 谁更好。
2. 好:坏 = 1:9, 按论文建议 λ_U 应该取多少 (λ_D = 1)? — 让 λ_D·n_D ≈ λ_U·n_U: λ_U ≈ 1/9。
3. 为什么 KTO 的 chosen log-prob 没像 DPO 那样下降? — KTO 对好样本单独有 σ(β(r − z0)) 一项, 要求 r 高过参考点; DPO 只要求 chosen 与 rejected 的差值变大。
