# 推理图：链、树、合并与逐步核验

## 直觉

多写几步不一定更会推理。搜索改善的是候选空间和验证机会，前提是状态和验证器定义正确。

## 核心原理

CoT 提示请求模型输出中间步骤；CoT 监督训练改变参数分布；RL 依据奖励更新策略。三者不能仅因为输出都有解释就混为一谈。

树保留不同路径，图合并等价状态；本例从 1 用加一/翻倍到 15，比较贪心与广度搜索。合并键必须包含影响未来的完整状态；有预算、权限或历史约束时，仅按当前数值合并可能错误。

最终答案对不代表过程对，独立验证器逐边检查。本例构造正确终点但非法中间跳跃的路径，揭示 outcome-only 的 overcredit。外部解释可验证也不证明它忠实描述模型内部因果。

测试时预算应包含生成、评分器前向、工具、重试和等待。相同生成 token 不等于相同总成本；比较 pass@k、成功成本、尾延迟和验证器漏判。

## 怎样验证

三个策略使用同一初态、目标和动作集合；统计展开数并拒绝伪造路径。迁移到 LLM 后还需审计步骤粒度、验证器相关错误与未见任务泛化。

## 与真实系统的差距

有限整数状态搜索，不是完整 ToT/GoT 论文复现。检验文本步骤只检验外部一致性，内部因果忠实性需激活干预等独立证据。
