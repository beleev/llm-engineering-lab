# M40 — Attention–FFN 分离部署: 注意力和专家按各自的瓶颈分开扩缩

[llm_infer 目录](../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/infer/moe-serving)

## 直觉

P/D 分离 (m15) 把 prefill 和 decode 拆到不同实例。AFD (Attention–FFN disaggregation) 再拆一次, 把 decode 的每一层拆成注意力和专家 FFN 两半, 放到两组卡上。拆的理由是两半的瓶颈不一样:
- **注意力**: 每步要把 batch × 上下文的 KV 读一遍, 受显存带宽限制, 耗时随 batch × 上下文增长。
- **专家 FFN**: 每步要把专家权重读一遍。MoE 每个 token 只激活少数专家, 分到每个专家的 token 很少, batch 不够大时它同样是读权重受限, 算力闲着; 汇聚的 token 够多才变成算力受限。

拆开以后, 注意力卡的显存全给 KV, FFN 卡只放专家, 很多张注意力卡的 token 汇到少数 FFN 卡上, 两边按各自的瓶颈独立扩缩。代价是每一层都要过两次网络 (注意力 → FFN → 注意力), 所以要把一个 batch 切成几个 micro-batch 轮流在两边跑 (ping-pong), 一个在 FFN 上算时, 另一个在注意力上算, 第三个在网络上传, 通信被藏在计算后面。

## 核心原理

### 核心数据结构或公式

每层、每个 micro-batch 的代价模型 (`afd.py`, 全部是估算):
```
t_a = (W_attn + b·S·kv_bytes) / BW                     注意力卡: 读注意力权重 + 读 b 条序列各 S 个 token 的 KV
t_f = max(E/n_f · P_e / BW,  2·P_e·N·k/n_f / FLOPS)    FFN 卡: 读本卡专家权重 vs 算, 取慢的; N = 这一份的 token 总数
t_c = max(b·k, N·k/n_f) · D · 2 bytes / NET            一个方向的 all-to-all, 取注意力卡发送和 FFN 卡接收中慢的
T   = max(t_a + t_f + 2·t_c,  m·t_a,  m·t_f,  m·t_c)    一层的周期: 一个 micro-batch 走一圈, 或各部件的忙碌时间
TPOT ≈ 层数 · T;   每卡吞吐 = 全局 batch / TPOT / (n_a + n_f)
```
- **最优 A:F 比**: 注意力卡显存塞满后 t_a 固定; 加注意力卡会让 FFN 收到的 token 变多, t_f 从"读权重"段进入"算"段后开始上升。t_f < t_a 时加注意力卡只摊薄 FFN 卡, 每卡吞吐上升; t_f > t_a 后 FFN 成了瓶颈, 每卡吞吐下降。最优点在 t_a ≈ t_f (MegaScale-Infer 按这个条件定注意力节点数)。
- **micro-batch 数**: t_a ≈ t_f 时, 通信完全藏住需要 m·t_f ≥ 2·(t_f + t_c), 即 m ≥ 2·(1 + t_c/t_f) (MegaScale-Infer 的条件; 通信快于 t_f/2 时至少 3 个)。m 太大时每份太小, 每一份都要把专家权重和注意力权重再读一遍。
- **同卡部署 (对照)**: n 张卡, 每卡放 1/n 的专家和全部注意力权重, 双 micro-batch 重叠 (DeepSeek 式), 一层取"算"和"all-to-all"中慢的。
- **两个假想模型**: 细粒度专家 (256 选 8, 每专家 44M 参数, 仿 DeepSeek-V3) 和粗粒度专家 (48 选 3, 每专家 110M, 仿 Step-3); 注意力统一写成 GQA 式 KV, 每 token 每层 2 KB。

## 与真实系统的差距

- 全部是代价模型的估算, 硬件 (显存带宽 3.35 TB/s、FP8 1.98 PFLOPS、72 GB 可用显存) 和模型参数都是假设, 没有任何实测。
- 没算专家负载不均 (m21)、shared expert、dense 层、router、LM head 和 prefill; 假设所有专家都被激活且负载均衡。2602.09721 指出 AFD 对注意力侧的 DP 负载不均比大 EP 更敏感, 而且注意力实例数是离散的, 这些这里都没体现。
- 通信只算了带宽, 没算延迟、按节点去重和 NVLink / RDMA 分层; 同卡部署的 all-to-all 假设能被双 micro-batch 完全重叠, 对它偏乐观。
- 没有异构硬件。MegaScale-Infer 的一大收益来自注意力用 H20、专家用 L40S, 按单位成本算吞吐 (论文报告比 TensorRT-LLM 高 1.86 倍); 同构硬件下的单 GPU decode 吞吐最高比 TensorRT-LLM 高 1.90 倍。Step-3 在 Hopper 上 2A2F (32 卡)、4K 上下文、50 ms TPOT 下报告每卡 4,039 token/s, 同设置下 DeepSeek-V3 是 2,324; 对照组和模型都不同, 不能和这里的数字直接比。
- MegaScale-Infer 的 M2N 通信库、Step-3 的 StepMesh 都是为 AFD 专门写的, 普通 NCCL all-to-all 在小消息下延迟高得多。
- [4] 搜索 AFD 配置时注意力卡数限制在 256 以内; 32K 上下文时每张注意力卡只装 16 条序列, 最优点落在这个边界上, 放开限制每卡吞吐还会略升。

## 常见误区

- "AFD 总比同卡部署快" —— 取决于对照组。对小规模同卡部署快很多, 对调好的大 EP 在这个模型里不快 ([4])。
- "注意力卡和 FFN 卡一样多就行" —— 最优比例由 t_a ≈ t_f 决定, 这里是 184:16; 上下文翻倍时最优比例也翻倍, 扩上下文只加注意力卡。
- "micro-batch 越多越能藏通信" —— 3 个就藏住了, 再多每份都要重读权重, m=6 比 m=3 低 26%。
- "网络慢一点只是多等一会" —— FFN 卡的接收量随 A:F 比线性增长, 网络慢时它先到顶, 最优比例从 184 压到 48, 每卡吞吐从 4108 降到 3349。

## 自测题

1. 为什么在 t_f < t_a 的区间里, 增加注意力卡会提高每卡吞吐?
   **答**: 这时 FFN 卡还在"读权重"段, 多接一些 token 几乎不增加 t_f, 周期仍由 t_a 决定; 全局 batch 随注意力卡线性增加, 而 FFN 卡数不变, 被摊薄的 FFN 卡占比下降。
2. t_a = t_f = 160 µs、t_c = 46 µs 时至少要几个 micro-batch?
   **答**: m ≥ 2·(1 + 46/160) = 2.6, 至少 3 个。2 个时一个 micro-batch 走一圈要 160 + 160 + 2×46 = 412 µs, 两边各只忙 320 µs, 剩下的是气泡。
3. 对一个已经部署在 256 卡大 EP 上的细粒度 MoE, 什么条件下 AFD 才可能值得?
   **答**: 这个代价模型给不出收益。真实系统里要靠模型没算的东西: 注意力和专家用不同硬件降低单位成本、大 EP 的负载不均和通信开销、上下文变长时只扩注意力实例的灵活性。FastAFD 的结论是它是资源配置的选择, 不是架构上的胜利。
