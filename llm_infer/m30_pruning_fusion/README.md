# 剪枝与融合：零值不等于少做计算

## 直觉

权重变成零，稠密矩阵乘仍可能照算。想加速，要让执行器真的跳过这些工作。

## 核心原理

非结构化剪枝把小权重置零；若仍走 dense GEMM，算子形状与 MAC 数不变。结构化剪枝删除通道，改变矩阵形状，才能在普通 dense 实现中减少运算。

本例构造低贡献通道，对比掩码输出与压缩矩阵输出的一致性，并报告相对 dense 的误差。硬件稀疏格式还要求模式、索引和内核支持，低密度也可能被索引开销抵消。

融合把 bias、激活、残差等中间结果留在寄存器或片上存储，减少读写；编译器还需处理形状、布局与数值约束。CUDA Graph 主要复用提交调度，不自动等于算子融合。

压缩验收不能只测平均困惑度：分别测低频实体、长推理、多语言、安全边界、校准和拒答。相同吞吐下质量变差，应报告质量—延迟 Pareto 取舍。

## 与真实系统的差距

numpy 的通道裁剪与理论流量。没有稀疏 GPU kernel 或融合 kernel 的实测加速；模型压缩还需看长尾、推理、安全切片。

## 常见误区与自测

把 90% 权重置零后，dense GEMM 会自动快十倍吗？
