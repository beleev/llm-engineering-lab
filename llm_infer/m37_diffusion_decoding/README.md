# m37 — 扩散语言模型的解码: 一步揭开几个位置, 以及没有精确 KV cache 怎么办

[llm_infer 目录](../README.md) · [交互实验](https://beleev.github.io/llm-engineering-lab/#/infer/diffusion-decoding)

## 直觉

掩码扩散语言模型 (LLaDA 一类) 生成回答时, 先把回答的每个位置都填成 [MASK], 每一步让模型给所有遮住的位置各出一个分布, 再挑一部分位置揭开 (unmask), 直到全部揭开。自回归模型一步只出 1 个 token, 扩散模型一步可以揭开好几个, 这是它能快的原因。LLaDA 论文的默认设置是一步揭开 1 个, 步数等于回答长度, 速度上并不占优。

一步多揭开几个会遇到两个问题:
- 同一步揭开的位置各自从自己的边缘分布里取值。两个位置强相关时 (Fast-dLLM 论文举的例子是两个词的扑克牌型, "high card" 和 "full house"), 各取各的最大值可能拼出 "high house"。
- 扩散模型的注意力是双向的, 任何一个位置被揭开, 所有位置在第 2 层及以后的 K/V 都会变, 没有自回归那种「算一次永远有效」的 KV cache。

对应的做法:
- 按置信度阈值揭开 (Fast-dLLM): 置信度 (最大概率) 超过 τ 的位置全部揭开, 一个都没有就只揭开最高的那个。独立、有把握的位置一步揭开一大片, 相关、没把握的位置自动退回一次一个。
- 近似缓存: 每隔几步完整算一遍, 中间的步只重算当前块, 块外的位置用旧的 K/V (Fast-dLLM 的 DualCache, dKV-Cache)。
- 块扩散: 块之间改成因果、块内仍然双向, 写完的块 K/V 不再变, 缓存是精确的 (BD3-LM)。

## 核心原理

### 核心数据结构或公式

```
Oracle (合成的「完美模型」)     序列 = 互相独立的组; 组内是一张短语表 (每条短语一个概率)
  marginals(x)                  对每个遮住的位置, 在「和已揭开位置一致的短语」上重新归一, 给出精确的条件边缘分布
  三种组:
    独立位置                    1 个 token, 最大概率 0.92–0.995
    共用 token 的短语            短语 0 自成一套, 短语 1/2 只在一个位置不同 → 各位置最大值拼出表里没有的组合
    「三角」短语                 (a,b,x) (a,y,c) (z,b,c) 各约 1/3 → 每个位置最大概率约 2/3, (a,b,c) 不在表里

decode(fixed, k)                每步揭开置信度最高的 k 个, 步数 = ⌈L / k⌉
decode(threshold, τ)            每步揭开所有置信度 > τ 的位置; 一个都没有时只揭开最高的 1 个
                                Fast-dLLM 定理 1: n 个位置的置信度都 > 1 − ε 且 (n+1)ε ≤ 1 时,
                                同一步贪心揭开与逐个贪心揭开结果相同

BiLM (随机权重, 3 层单头)        全双向 (LLaDA) 或块间因果 + 块内双向 (块扩散)
dual_cache_error(refresh=r)     每 r 步完整前向并缓存全部 K/V; 其余步只算当前块, 前缀和后缀用缓存里的旧 K/V
block_cache_error               块因果掩码下, 写完的块 K/V 与后面的块无关, 缓存一次即可
```

读代码时盯住两处:
1. decode 里 threshold 分支那一行 `order[:max(1, int((conf > tau).sum()))]`: 过阈值的全揭开, 都不过就只揭开 1 个。
2. BiLM.run 里 `K[idx], V[idx] = k, v`: 只有当前块的 K/V 是新算的, 其余位置是缓存里的。

断言:
- [1] 全部独立的位置, 任何 k 都不拼错; k=1 不拼错; 混合负载上 k 越大拼错率越高, k=32 时超过 30%。
- [2] τ=0.7 和 τ=0.9 在三种负载上都不拼错; τ=0.9 在独立负载上每步至少揭开 8 个, 在全部相关的负载上每步不超过 2 个; τ=0.5 在全部相关的负载上拼错率超过 10%; 混合负载上 τ=0.7 的步数比固定 k=2 少、而且不拼错; 独立负载上 τ=0.7 的步数不到固定 k=2 的 1/4。
- [3] 每步都刷新时与完整前向一致 (误差 < 1e-5); 刷新间隔越大误差越大; 间隔 32 的决策不一致率高于间隔 2。
- [4] 块扩散的缓存与每步完整前向的最大差 < 1e-5。

几个数字怎么读:
- [1][2] 的拼错率是「多 token 短语里拼出表里没有的组合」的比例。Oracle 给的是精确条件分布, 所以拼错全部来自同一步揭开了相关位置, 不来自模型没学好。
- [2] τ=0.5 拼错, 是因为「三角」短语每个位置的置信度约 2/3, 三个一起过阈值、同一步揭开, 而 (a,b,c) 不在表里。按 Fast-dLLM 的定理, 同一步揭开 3 个位置要 ε ≤ 1/4, 即置信度 ≥ 0.75。τ=0.7 时三角短语的三个位置不会同时过阈值 (三个置信度加起来是 2), 所以也不拼错。
- [3] 的决策不一致率是在随机权重模型上测的。随机模型的输出分布很平, logits 差一点 argmax 就会变, 所以 18.8% 这类数字不能当成真实模型的精度损失; 能读的是误差随刷新间隔单调变大。Fast-dLLM 在 LLaDA 上报告 DualCache 加并行解码的准确率和基线接近 (GSM8K 76.0 对 77.3)。

## 与真实系统的差距

- Oracle 是合成的分布, 不是训练出来的模型。真实模型的置信度会受训练质量影响, 独立位置未必都有 0.92 以上的把握, 阈值策略的并行度会比 [2] 的独立负载低。LLaDA2.0 的默认解码设置是阈值 0.95、块长 32; SGLang 的扩散模型支持里有 LowConfidence 和 JointThreshold 两种解码算法 (--dllm-algorithm), 默认块长 32。
- LLaDA 论文在 Base 模型、长度 256 上比较两种揭开策略: 随机揭开 GSM8K 21.3、HumanEval 11.6, 按置信度揭开 70.0、32.9。这里只实现了按置信度揭开。
- Fast-dLLM 的 DualCache 在每个块写完时刷新, 对应 [3] 里的 r=8。论文在 LLaDA、GSM8K 8-shot、生成长度 1024 上报告吞吐最多提高 27.6 倍 (0.7 → 19.3 tok/s), 单独用并行解码最多 13.3 倍。dKV-Cache 的做法是 token 揭开后晚一步再缓存它的 K/V (揭开那一步 K/V 变化最大), 并每隔几步刷新 (LLaDA 上 8 步, Dream 上 4 步), 摘要报告 2–10 倍加速。这里两种都没有实现, 只实现了「每 r 步全刷新」这一个旋钮。
- 块扩散 (BD3-LM, ICLR 2025) 用块间因果换来精确缓存和可变长度生成, 代价是块与块之间回到自回归。模型侧怎么训练块扩散见模型阶段的块扩散一章。
- 商用速度数字都是厂商口径, 这里没有复现: Mercury 的技术报告引用 Artificial Analysis 的独立评测, Mercury Coder Mini / Small 在 H100 上 1109 / 737 tok/s; LLaDA2.0 技术报告里 LLaDA2.0-flash-CAP 535 TPS, 普通 LLaDA2.0-flash 383 TPS, 自回归基线 256 和 237 TPS (扩散模型跑在 dInfer 上、自回归基线跑在 SGLang 上, 没有写硬件); LLaDA2.1 在定制的 SGLang 和 FP8 量化下报告 HumanEval+ 上 892 TPS。

## 常见误区

- 「扩散模型一步就能出整段回答」: 能出, 但相关位置会拼错 ([1]: k=32 时混合负载 49.0% 的短语拼错)。步数和质量是一对取舍。
- 「阈值越低越快, 只要过半就安全」: 两个位置都过半时它们的最大值组合一定在支撑集里, 三个及以上就不一定 ([2]: τ=0.5 在全部相关负载上拼错 46.0%)。
- 「固定每步揭开 k 个和阈值策略差不多」: 固定 k 不看内容, 独立的位置也一样慢、相关的位置照样一起揭开; 阈值策略在独立负载上 1 步, 在全部相关负载上 22.6 步, 都不拼错。
- 「扩散模型不能用 KV cache」: 不能用精确的, 可以用近似的 (隔几步刷新), 误差随刷新间隔增大 ([3]); 块扩散把块间改成因果, 就又能用精确缓存 ([4])。

## 自测题

1. 一个两词短语只有三种写法: "high card" 0.40、"full house" 0.35、"low house" 0.25。同一步揭开这两个位置、各取最大值, 会得到什么? 逐个揭开呢?
   **答**: 第一个位置 "high" 0.40 最大, 第二个位置 "house" 0.60 最大, 同一步揭开得到 "high house", 不在表里。逐个揭开时先揭开置信度高的第二个位置得到 "house", 再在 "full house" 和 "low house" 里重新归一, 第一个位置取 "full", 得到合法的 "full house"。
2. 阈值取 0.7 时, 「三角」短语的三个位置为什么不会在同一步被揭开?
   **答**: 三个位置的最大概率分别是  + w_1$、 + w_2$、 + w_2$, 加起来等于 2, 平均 2/3, 不可能三个都超过 0.7。最多两个同时过阈值, 而两个位置都过半时它们的组合一定在表里。
3. 为什么块扩散的缓存是精确的, 全双向的 DualCache 只能是近似的?
   **答**: 块因果掩码下, 前面块的位置看不见后面的块, 后面的块怎么变都不影响前面块的 K/V; 全双向时每个位置都看得见当前块, 当前块一揭开, 块外所有位置在第 2 层以后的 K/V 都变了, 缓存里存的是旧值。
