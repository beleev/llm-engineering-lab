# 端侧预算: 能放下、能跑快、能持续吗

## 直觉

1B 参数模型按 FP16 算权重 1907.35 MiB, 加 192 MiB KV 和 256 MiB 运行时共 2355.35 MiB, 2 GiB 装不下; 改 INT4 后权重 476.84 MiB, 总 924.84 MiB 装得下, 但带宽减半的热降频让每 token 从 28.053 ms 变成 56.106 ms。手机上能加载模型只是第一关: 上下文缓存、功率和持续运行后的降频都可能成为瓶颈。

## 核心原理

总内存包括权重、KV cache、工作区和运行时。量化权重不自动量化 KV: 本例 INT4 后权重只剩 476.84 MiB, 4096 上下文的 16 位 KV 仍是 192 MiB; 长上下文下, 缓存会吞掉原本省下的内存。

简化 roofline 取 max(运算量/算力, 搬运量/带宽): 1 TFLOP/s 下 1B 参数算一个 token 只要 2 ms, 25 GB/s 搬 FP16 权重加 KV 要 88.053 ms, decode 卡在带宽上。再用功率×时间估每 token 能量 (6 W 下 0.52832 J); 热降频把持续带宽砍半, 冷启动峰值不能代表十分钟后的速度。

联合设计从目标质量和设备约束出发, 选模型宽深、量化格式、编译器布局与内核; 理论压缩要有算子支持才兑现。电池寿命还取决于整机其他负载和电源效率。

Green AI 要报告每成功任务能耗、硬件利用率、重试和生命周期假设。低功率设备跑得更久, 总能量不一定更低: 本例热降频下每 token 从 0.16832 J 升到 0.33664 J; 没有设备实测就不能给碳排或续航承诺。

## 怎样验证

全部参数都是公开假设 (1B 参数、2 GiB 内存、25 GB/s 带宽、1 TFLOP/s 算力、6 W 功耗), 切换 FP16 / INT4 / 热降频三种情形, 比较总内存能否装入 2 GiB、每 token 毫秒和焦耳; 真实选型还要实测量化质量、温度、功率曲线和电池。

## 与真实系统的差距

预算模型，不是手机或芯片跑分，不提供特定设备续航承诺。真实能耗需扣除/报告空闲基线并说明测量边界。

## 常见误区与自测

权重从 FP16 改 INT4, 峰值内存一定降为四分之一吗?

<details><summary>展开解析</summary>

不一定。只有权重按位宽缩小 (1907.35 → 476.84 MiB), KV 192 MiB、运行时 256 MiB 原样留着; 总内存从 2355.35 降到 924.84 MiB, 远不到四分之一。

</details>
