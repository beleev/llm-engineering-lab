# 缓存身份: 相同 token 不一定能复用

同样 4 个 token, 先由可信身份 A 写入缓存。跨租户共用时 B 直接命中 A 的 KV (合成代价 1); 隔离命名空间后 B 未命中, 条目变 2 (代价 5); 换模型或 adapter 版本都未命中; 忽略版本那组命中了, 返回值却和当前约定对不上; B 伪造租户声明 A 被网关直接拒绝。KV 的身份不只是 token, 还包括解释这些 token 的模型和输入约定, 命中更快也可能泄露别的租户用过什么前缀。

## 怎么跑

```bash
python -m llm_infer.m34_cache_identity.demo
```

## 先看这几件事

- 缓存键绑定授权共享域、不可变的模型标识、adapter 标识和 token 前缀, 多模态还要绑定内容摘要。只有 token 相同证明不了 KV 相同: 忽略版本那组命中了, 返回值却和当前模型约定重算的指纹不一致。
- 共享域由可信身份网关从凭据推出 (本例用 HMAC 生成命名空间), 客户端声明的租户或 salt 不能覆盖鉴权结果: B 声明自己是 A 直接被拒。同域可复用 (A 再来命中), 跨域要有明确的命名空间隔离。
- salt 只减少特定的缓存侧信道风险, 不提供服务进程、网络或显存隔离。命中 1 / 未命中 5 是合成代价, 只用来展示泄露渠道, 不能报告成真实的攻击成功率。

## 怎样验证

固定同一串 token, 先由可信身份 A 写入 v1 模型 / adapter 的 KV, 再分别改租户、模型版本、adapter 版本或客户端的租户声明, 比较七种情形; 判定看是否命中、返回值是否和当前约定重算的指纹一致、越权是否被拒, 以及是否出现跨隔离域复用。

### 跨租户共用

| 指标 | 实际结果 |
| --- | --- |
| 缓存命中 | true |
| 返回值匹配模型约定 | true |
| 身份越权被拒绝 | false |
| 跨隔离域复用 | true |
| 缓存条目 | 1 |
| 合成命中代价 | 1 |

命中 1 / 未命中 5 是合成代价，不是测量时延或攻击成功率。salt 只隔离缓存键，不隔离服务进程、网络和显存；多模态还要绑定内容摘要。
