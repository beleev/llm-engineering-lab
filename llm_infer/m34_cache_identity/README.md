# 缓存身份: 相同 token 不一定能复用

推理服务会把处理过的 token 前缀的中间结果 (KV cache) 存起来, 下次遇到同样的前缀就直接复用, 省掉重算。这组实验先让可信身份 A 用同样 4 个 token 写入一条缓存, 再换一种身份或版本来查:
- 跨租户共用一个缓存时, B 直接命中了 A 算的 KV (合成代价 1)。
- 按租户隔离命名空间后 B 未命中, 自己重算, 缓存条目变成 2 (代价 5)。
- 换模型版本或 adapter (加在基座模型上的一小份微调权重) 版本都未命中。
- 缓存键里不放版本的那组命中了, 返回值却和当前模型应该算出的结果对不上。
- B 谎称自己是 A, 被网关直接拒绝。

所以 KV 的身份不只是 token, 还包括谁有权共享、由哪个模型和 adapter 算出来; 而且命中比不命中快, 别的租户可能借这个快慢差别探出某个前缀有人用过。

## 怎么跑

```bash
python -m llm_infer.m34_cache_identity.demo
```

## 先看这几件事

- 缓存键要把所有影响结果的身份信息都绑进去, 因为它决定什么样的请求可以复用同一份 KV。这些信息包括:
  - 授权的共享域 (哪些请求方可以共用)。
  - 不可变的模型标识。
  - adapter 标识。
  - token 前缀。
  - 多模态请求还要绑定图片等内容的摘要。

  模型和 adapter 要用内容摘要当标识, 不能用随时能被覆盖的显示名。只有 token 相同证明不了 KV 相同: 「忽略版本」那组的缓存键没放模型和 adapter, A 换了 adapter 版本后仍然命中, 拿到的却是旧 adapter 算的值, 和按当前约定重新算的指纹不一致。本例的 KV 用一个确定性的哈希指纹代替, 不真的执行模型。
- 共享域由可信的身份网关根据凭据推出来, 不由客户端自己说了算。本例网关分三步:
  1. 查凭据属于哪个租户。
  2. 用一个服务端密钥对租户名做 HMAC (一种带密钥的哈希)。
  3. 结果当成命名空间放进缓存键。

  客户端可以在请求里声明自己是哪个租户, 但声明必须和凭据查出的租户一致, 否则直接拒绝: B 拿着自己的凭据声称是 A, 被拒绝, 也就碰不到 A 的缓存。同一个域内可以复用 (A 再来一次就命中), 跨域则靠不同的命名空间隔开。
- salt (混进缓存键、按租户各不相同的一段值, 本例的 HMAC 命名空间起的就是这个作用) 只能让不同租户查不到彼此的缓存。这能减少靠命中快慢探测别人前缀的风险, 但不提供服务进程、网络或显存层面的隔离, 这些要靠别的手段。命中记代价 1、未命中记代价 5 是人为设定的合成数字, 只用来说明命中和不命中之间有可以观察到的差别, 不是测出来的延迟, 也不能当成真实攻击的成功率来报告。

## 怎样验证

固定同一串 4 个 token, 先由可信身份 A 用 v1 模型和 v1 adapter 写入缓存, 再分别改变第二次请求的租户、模型版本、adapter 版本或客户端声明的租户, 共七种情形。判定看四件事:
- 是否命中。
- 返回值是否和按当前模型约定重新计算的指纹一致。
- 冒充身份是否被拒绝。
- 是否出现跨隔离域复用 (一个租户用上了另一个租户的缓存)。

### 跨租户共用

| 指标 | 实际结果 |
| --- | --- |
| 缓存命中 | true |
| 返回值匹配模型约定 | true |
| 身份越权被拒绝 | false |
| 跨隔离域复用 | true |
| 缓存条目 | 1 |
| 合成命中代价 | 1 |

命中 1 / 未命中 5 是合成代价，不是测量时延或攻击成功率。salt 只隔离缓存键，不隔离服务进程、网络和显存；多模态还要绑定内容摘要。
