# 缓存身份: 相同 token 不一定能复用

推理服务会将已处理前缀的 KV cache 保存下来, 后续请求遇到可复用前缀时即可省去重复 prefill 计算。本实验先由可信身份 A 对固定 4 个 token 写入一条缓存记录, 再变换请求身份或模型配置发起第二次查询:
- 跨租户共用全局缓存时, 租户 B 直接命中租户 A 写入的 KV (合成代价为 1)。
- 按租户隔离命名空间后, 租户 B 未命中并独立重算, 缓存条目增至 2 条 (合成代价为 5)。
- 升级基座模型版本或切换 adapter 版本后, 查询均未命中并触发重算。
- 缓存键忽略版本信息的对照组虽然命中缓存, 但返回的 KV 与当前模型约定应算出的指纹不一致。
- 租户 B 持自身凭据伪称身份为 A 时, 请求在网关层被直接拒绝。

由此可见, KV cache 的可复用身份不仅取决于 token 序列, 还取决于授权共享域、基座模型版本与 adapter 版本; 同时由于命中与未命中存在可观测的耗时差异, 缺乏租户隔离还会引入前缀探测侧信道风险。

## 怎么跑

```bash
python -m llm_infer.m34_cache_identity.demo
```

## 先看这几件事

- 缓存键必须完整绑定所有决定计算结果与共享边界的身份要素, 以明确界定哪些请求允许复用同一份 KV cache。核心绑定要素包括:
  - 经鉴权派生的授权共享域。
  - 不可变的基座模型标识。
  - 不可变的 adapter 标识。
  - 精确的 token 前缀序列。
  - 多模态请求中图像等非文本输入的内容摘要。

  模型与 adapter 标识应采用不可变的内容摘要, 而非可被原位覆盖的显示名称。仅凭 token 序列一致无法保证 KV 等价: 在「忽略版本」对照组中, 缓存键未纳入模型与 adapter 标识, 租户 A 切换 adapter 版本后依然命中旧缓存, 取回的旧值与按当前版本重新计算的指纹不符。本实验使用确定性哈希指纹替代真实张量以验证缓存键语义, 不实际执行模型前向计算。
- 缓存共享域必须由可信身份网关依据鉴权凭据派生, 不得直接采信客户端自报的租户标识。本实验中网关按三步构造隔离域:
  1. 根据请求携带的凭据核查真实归属租户。
  2. 使用服务端密钥对已核实的租户标识计算 HMAC。
  3. 将派生的 HMAC 值作为命名空间写入缓存键。

  若客户端在请求体中显式声明租户身份, 该声明必须与凭据核查出的租户完全一致, 否则网关直接拒绝请求: 租户 B 持自身凭据伪称 A 时即在鉴权阶段被拦截, 无法触达租户 A 的缓存条目。同一共享域内的合法请求 (如租户 A 再次请求) 可正常命中复用, 不同共享域则通过独立命名空间严格隔离。
- 缓存键中的租户级 salt (本例由 HMAC 命名空间承担) 仅负责在键空间层面隔离不同租户的缓存查找。该机制可降低利用命中延迟差异探测他人前缀的侧信道风险, 但并不提供服务进程、网络或 GPU 显存层面的强隔离, 底层资源隔离仍需独立基础设施保障。实验中命中代价记为 1、未命中代价记为 5 均为人工设定的合成读数, 仅用于表征命中与未命中之间存在可观测差异, 并非真实硬件实测延迟, 也不能直接折算为真实侧信道攻击的成功率。

## 怎样验证

固定同一串长度为 4 的 token 前缀, 先由可信身份 A 使用 v1 模型与 v1 adapter 写入缓存, 随后分别变更第二次请求的租户身份、模型版本、adapter 版本或客户端自报租户声明, 对比七种测试条件。评估指标包含四项:
- 第二次查询是否命中缓存。
- 返回值是否与按当前模型及 adapter 约定重新计算的指纹一致。
- 伪造租户声明的请求是否被网关拒绝。
- 是否发生跨隔离域的缓存复用。

### 跨租户共用

| 指标 | 实际结果 |
| --- | --- |
| 缓存命中 | true |
| 返回值匹配模型约定 | true |
| 身份越权被拒绝 | false |
| 跨隔离域复用 | true |
| 缓存条目 | 1 |
| 合成命中代价 | 1 |

命中 1 / 未命中 5 是合成代价，不是测量时延或攻击成功率。salt 只隔离缓存键，不隔离服务进程、网络和显存；多模态还要绑定内容摘要。
